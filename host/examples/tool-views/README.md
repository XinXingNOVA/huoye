# 工具视图布局示例

展示新公共契约，不是业务插件：普通草稿和说明、智能工具与内容页。草稿由宿主安排独立默认组；说明用 `placement.default` 指定初始组合。首次展开才挂载；移动、组合、切换／关闭工具后草稿与实例保持。侧栏重启不保存草稿，持久状态由实际插件负责。另提供示例 A／B 内容页，用 `saved / setState` 保存页面草稿，展示 active 与 visible 的区别。

在宿主目录执行：

```sh
node scripts/plugins/pack.ts examples/tool-views artifacts/plugins/demo-tools.rmplugin
```

在应用设置安装该包，在当前仓库勾选并应用。从最左快捷栏「布局示例」打开「说明」，草稿可从命令面板的「打开草稿」、组菜单或说明中的按钮打开，新装时默认分别位于右侧普通组；已有用户布局保持；工具标签右键可以加入资源组、独立放到另一侧或恢复默认位置。「说明」中的按钮用 `host.showView` 展开当前实际位置的草稿。

不需要核心入口、数据块或业务插件。独立开发时仍将源码复制到自己的工程，使用宿主开发目录／打包工具；详细契约见[工作区布局](../../docs/plugins/工作区布局.md)。

「说明」可打开示例 A／B；点击中央分屏图标直接向右分割，按住 Alt 向下分割，区域的 `···` 提供合并等操作，拖动或右键标签移组。页面内的延迟打开按钮用于验证切组后仍在来源组打开；K 键只由获得操作焦点的页面响应。两页分别输入并重开仓库可验证页面状态恢复。

示例声明 `open-target-v1`。页面的「在另一组打开此页」调用 `host.openTab(..., { group: 'other' })`，移动已开的页面并保留输入。导入名为「布局路由示例.txt」的文件后右键「在另一组打开」，示例打开器会延迟调用 `host.openData`，用于检查回调继承目标；其余文件不匹配此示例打开器。

可以把示例标签拖到任一区域四边，观察落点预览后继续局部分割；移动和合并保持草稿，重启恢复各区域的当前页。区域尺寸不足时会提示，其他组开页使用最近访问的非来源组。

## 页面结束回调

示例包 1.3.0 声明 `page-lifecycle-v1`。中央页面可勾选“保留页面”，静态 `beforeLeave` 会拒绝关闭和重载；宿主保留页面。取消勾选后重试即可。这个示例演示失败协议，不代表完整业务编辑器；草稿仍是本机页面存档，没有共享编辑会话。详见[页面生命周期](../../docs/plugins/页面生命周期.md)。

1.4.0 增加 `page-instances-v1` 示例：说明视图可打开「多视图示例」（每份内容最多两个页面）与「单例示例」（每窗口一个）。示例计数是局部状态，可验证普通打开复用、新建／导航超限与重新加载；不是共享编辑器。标签菜单可复制允许多开的页面到另一组。

1.5.0 为 `布局路由示例.txt` 的回调打开器补充 `demo-tools.route` 与可读标题，并声明 `open-with-v1`。它会与文字阅读器同时出现在“打开方式…”中，可验证临时选择、默认偏好、当前／另一组和延迟开页。普通素材不受此示例匹配影响。

## 智能组示例（1.6.0 · context-tools-v1）

本示例同时验证普通工具与上下文工具：

- 「集合概况」需要 `collection.filter`；延迟筛选按钮故意等待后调用，用来检查来源页切换不会串页。
- 「示例页面」通过 `expose({ context })` 提供 `demo-tools.reading`。阅读工具调用页面计数动作，工具输入框是按来源隔离的临时局部状态。
- 「额外工具示例」默认隐藏，可从智能组齿轮菜单加入；同类页面恢复上次组合，切到未提供能力的单例页面显示占位。
- 普通草稿／说明工具继续使用原 `toolViews`，不会自动变为智能候选。1.7.0 的阅读工具／集合概况声明 `bound-context-tools-v1`，支持最多两份固定工具；额外工具仍未声明独立能力，用于验证旧工具不会自动多开。

启动临时完整验证：`node tests/electron/sidebar-layout-check.mjs --context`（先构建宿主）。示例不是发行附带功能，不写入业务数据块。

1.7.0 的 `--context` 流程还验证从真实鼠标起拖、固定筛选不串页、标题整组拖动与取消、菜单重复固定复用、跨侧保留局部输入、来源页离开最近缓存仍可操作、关闭目标占位和重启恢复。固定工具和智能入口的局部输入互不复制；它们可共用页面提供的数据与动作。

## 跨区域停靠（tool-placement-v1）

草稿、固定阅读工具声明 `placement: { regions: ['left', 'center', 'right'] }`；说明与集合概况只允许两侧，不因其他工具跨区而扩大范围。拖动草稿／固定工具到中央标签栏、中部或四边，也能从中央拖回侧栏；阅读工具可直接从智能组拖到中央，重复拖出复用。右键提供同样的移动入口。

`--context` 流程覆盖跨区输入 DOM 身份、草稿、滚动、原页面操作、普通工具关闭重开、固定实例重启恢复及中央工具不接收窗口级素材导入。布局预设保留当前工具，不按命名预设创建中央工具。任意插件内局部草稿仍不是重启存档。

## 常用操作入口（1.9.0 · quick-actions-v1）

声明 `ui-commands-v1` 与 `quick-actions-v1`。命令 `demo-tools.open-status` 用 `quickAction: { icon: 'tool', order: 10 }` 加入快捷栏，复用 `host.showView` 定位已有说明工具；草稿未声明，所以不会自动出现在栏中。运行命令仍经过统一会话和可用性检查。固定的新建／导入面向仓库，页面中的原输入规则保持。


## 内容独立声明（1.11.0 · tool-placement-v1）

所有工具都不再声明 `container`、`placement.container` 或 `viewContainers`。草稿默认独立成组；说明用 `placement.default: { region: 'right', group: 'demo-tools.tools' }` 保留原组合建议；智能工具仅凭 `context.requires` 成为候选。内容 ID 不变，已保存的位置和关闭状态优先。

构建后运行 `node tests/electron/sidebar-layout-check.mjs` 和 `--context`，验证自动分组、普通及智能工具移动、局部输入与来源保持和重启。旧存档接续通过布局读取回归验证，不再靠在公开示例里混入旧声明。
