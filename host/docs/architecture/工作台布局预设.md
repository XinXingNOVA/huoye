# 工作台布局预设

2026-11-13。预设由宿主应用管理，用于在同一仓库中切换整理、专注、对照等工作方式。保存区域安排、工具组合和显式支持的功能入口／呈现。插件组合、业务场景模板、跨仓库引用映射仍独立推进。

## 使用

左下「布局」菜单可以直接选择：

- **整理**：单区域，展开两侧栏。
- **专注**：单区域，收起两侧栏。
- **对照**：左右两个区域，收起两侧栏。

内置布局沿用当前侧栏宽度和工具位置。自定义布局通过「将当前布局另存为…」保存，在「管理布局预设…」中应用、重命名、更新为当前布局或删除。临时调整不会自动改写已保存预设；删除预设不改变当前工作台。侧栏工具的打开、恢复默认等操作收在「侧栏显示与位置…」内，各普通组菜单也能添加工具。

基础管理界面按「当前工作台／我的预设／应用附带／插件提供」列出内容，可搜索名称。点击条目只选择预览，点击「应用预设」才切换；菜单和命令面板仍保留直接切换的快捷入口。预览包含中央分区示意、主分区、左右开合、各组工具及关闭项、智能工具偏好、中央功能页与页面提供的显示说明。无显式内容编排的旧预设会标明沿用当前组合／保留已有页面，不把空定义画成必然清空。

保存前先在「当前工作台」确认范围；另存副本复制所选预设，覆盖更新则预览并确认当前工作台的新编排。我的预设支持改名和删除，重复名称在表单中提示。缺失插件／无效入口展开显示原因；用户仍可应用可用部分，不会自动安装依赖。附带原版只读，但也能另存副本。未提供任意编排编辑器：先在工作台安排页面，再保存。后续只调整呈现即可，管理界面不拥有布局或存储规则。

插件也可附带只读原版，或替换保存／管理界面；用户副本和当前工作区独立保留。默认界面仍随宿主提供，渲染故障原位回退，基础菜单始终可用。公共接入见[工作台预设 API](../plugins/工作台预设API.md)。

## 保存内容与归属

| 保存 | 不保存 |
|---|---|
| 中央递归分屏树、比例、主区域，以及支持的功能入口与呈现 | 具体素材、任意标签参数、页面完整状态 |
| 左右侧栏显隐、宽度 | 草稿、编辑会话、撤销记录 |
| 普通组位置、顺序、当前工具、关闭项、组高度与智能工具偏好 | 插件启停、安装包、业务配置 |

当前活动区域成为预设的主区域。自定义预设保存到应用 renderer 的本机 `localStorage`，键为 `rm:workbench-presets:<libraryId>`，目录格式仍为 1，嵌套 `sidebars` 使用 v4；同一仓库 ID 共用其预设，不同仓库隔离。它们不写入仓库数据库，也不随仓库文件自动搬到另一台机器。

正在使用的工作区仍通过原有工作区存档自动保存，包括页面、草稿和当前布局。预设目录与这份存档独立：应用预设只改变当前布局，随后由原存档机制续存；预设本身只能显式保存或更新。最多 40 个自定义预设，每个布局最多 64 个区域。坏数据、未知版本或存储失败会报错并保留原目录，不把读失败当作空目录覆盖。

旧预设中的侧栏 v1 在读取时转换：原同时展开工具分别形成纵向组，后台与折叠工具保留但关闭。首次改写旧目录前，将原 JSON 保存到 `rm:workbench-presets:<libraryId>:before-sidebars-v4`，备份或正式写入失败都会报错，原目录保留；单纯读取不改写目录。运行时不保留第二套旧侧栏。

## 切换与返回规则

1. 当前操作区域的页面放入预设主区域。其他区域先按已有区域身份对应，再按原分屏顺序分配；容不下的标签合并到主区域，保持各组内顺序。
2. 增加的空区域先补「开始」页；有 contents 声明时准备对应内容，优先复用已有实例，不复制素材。只在空组采用预设默认激活项，有真实内容时保持当前焦点。仅预设自动产生的空白占位页可在后续切换中回收，用户自己打开的页面保留。
3. 保留真实标签的 ID、参数、业务状态和当前操作页；显式呈现配置只经页面适配器合入 saved，并用 presentationRevision 通知已挂载组件，不经过页面关闭／替换流程，不触发页面结束时的提交，也不重置共享编辑会话。失焦提交型控件会先收到失焦；页面可见性和最近访问缓存仍按原规则工作，隐藏的页面不保证永远保留 DOM，插件仍须按公共接口报告恢复状态。
4. 每次应用保存一个**本次窗口会话内**的返回点，包含此前布局及标签 ID 的区域归属。点击「返回切换前布局」，只移动仍存在的标签；新打开的标签保留，已关闭的标签不复活，页面内容保持最新。返回后消费该点；再次应用会替换上一次返回点，不建立无限布局撤销栈。重启后恢复当前工作区，但不恢复这个临时返回点。
5. 中央停靠工具随真实标签保留，不因应用预设在侧栏重复创建。固定实例不改来源，命名预设不保存固定页面身份，普通中央工具可进入 contents，固定工具仍不进入；完整工作区自动存档另行保存位置与绑定。返回仅移动仍存在的工具，不恢复已关闭实例。
6. 停用／缺失的侧栏视图保留排布，当前画面按可用贡献回退，并提示不可用面板；重新启用后可以沿用位置。预设不负责安装或启用插件。新出现的贡献继续按侧栏协调规则加入。
7. 小窗口沿用现有最小区域尺寸与中央画布滚动，不丢分屏、不修改已保存比例。文件、仓库和文件空间的格式及操作语义不变。

## 实现边界

- `src/shared/workbench-layout.ts` / `sidebar-layout.ts`：公共纯布局值、白名单与尺寸约束，运行时与贡献校验共用。
- `src/renderer/src/workbench-arrangement.ts`：内容捕获、检查、实例复用、纯状态编排和呈现返回；页面业务适配集中在 `page-workbench.ts`，由类型显式接入。
- `src/renderer/src/workbench-presets.ts`：纯布局转换、返回点和原有本机目录。
- `src/renderer/src/workbench-preset-service.ts`：冻结快照、订阅、原版／用户副本及有语义的公共动作。
- `src/renderer/src/app/workspace.ts`：在唯一工作区状态上执行明确动作，协调侧栏与占位页清理。
- `src/renderer/src/components/WorkbenchPresets.tsx`：菜单、保存与管理界面。`App` 只接线。

公共 `host.workbenchPresets` 和预设／管理界面贡献用于组合使用，默认界面不再直接操作存储类或工作区控制器。没有新增 MCP 工具或数据内核“预设实体”，旧目录版本和已保存预设保持。未接入编排的页面保持现有行为；支持预设捕获／呈现的页面显式接入 `workbench-content-v1`，详见公共 API。实际布局／页面插件继续使用现有的 `active / visible / saved / setState`、侧栏容器与共享编辑协议即可。具体插件的 iframe、媒体或第三方编辑器状态仍按其真实场景验收。

验证入口见[开发与验证](../development/开发与验证.md#工作台布局预设)，区域与插件规则见[工作区布局](../plugins/工作区布局.md)。
