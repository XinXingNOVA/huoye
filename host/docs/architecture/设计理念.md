# 设计理念

资源管理器服务于素材的积累和再利用。文件夹之外，同一份素材可以出现在多个查询视图中，以不同界面完成阅读、整理、对照和加工。

## 稳定身份与可组合数据

素材具有稳定身份。名称、路径、呈现方式发生变化，不应随意产生新的身份。文件只是素材的一种内容来源；纯文字、摘录和插件定义的实体也可以直接由数据块构成。

数据块描述信息，系统执行行为，视图提供观察和操作入口。标签、笔记、来源、自定义字段等按需组合，不要求所有素材具有同一套固定字段。业务校验由拥有相应语义的模块承担。

## 仓库与文件空间

仓库保存素材身份、数据块及所接纳的文件版本；文件空间保存原件、版本、可用状态和关联权限。一个空间可以服务多个仓库，各库的标签和笔记独立。

仓库回收素材、空间回收文件、把字节送入系统废纸篓，以及清理记录，是不同操作。公共接口分别表达影响，界面再组合为便捷流程。发布空间新版本与某个仓库接纳版本同样分开。

以应用发起的受控管理为主。外部编辑通过工作副本明确目标和意图，完成后确认发布；直接修改受管原件只提供手动检查与恢复选择，不凭路径或内容相似度自动猜测身份。

## 插件与公共机制

插件提供增加、管理、使用、呈现和处理数据的能力。数据归仓库，停用或卸载插件保留原始数据；公共定义快照支持未知数据的基本读取。

宿主提供必要的事务、查询、历史、内容读取、布局、选区及生命周期协议。插件间通过明确的公共接口协作。共享选区是临时交互通道，持久数据和本机草稿另有归属，不把所有状态塞入同一存储。

公共能力从真实功能中提炼，有足够案例再统一。保持接口精简、语义完整，插件自己能维护的业务留在插件；不预先搭建没有使用场景的抽象层。

## 使用与可靠性

查询定义素材集合，浏览布局决定集合如何呈现。工作台布局、页面局部位置、插件组合分别保存，不与素材业务数据混为一体。

原始记录与可重建的派生数据分别处理。保护用户编辑、引用和撤销，结构变化考虑迁移和失败恢复。跨层流程有明确阶段和回执，不假设磁盘、多个数据库与外部程序能组成一个原子事务。

UI 和 MCP 共用业务入口。外部 AI 通过授权的查询与操作协作，写操作可追踪、可重试；操作历史与幂等回执有不同生命周期。当前为可信本地插件体系，不是任意代码的安全沙箱。
