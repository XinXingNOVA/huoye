# 容器与内容契约

日期：2026-11-09。状态：**语义与职责约定已确认；内部内容描述、现有放置解析、侧栏容器的只读快照／显式动作及内部插槽登记已收敛，工具可独立声明允许区域与初始位置，侧栏普通／智能容器已通过内部定义装配，页面与固定工具的实例判断已收敛；外部容器注册和统一内容装配 SDK 尚未实现。** 本批不新增容器类型、容器设置或布局格式，旧插件声明已退役，工具统一使用 `tool-placement-v1`。当前可调用的 API 以[工作区布局](../plugins/工作区布局.md)及源码为准；本文的契约项不是可直接使用的 SDK 字段。

## 1. 三层结构与目标

工作台保持“区域 → 容器 → 内容”。左、中、右区域及其空间规则由宿主定义；最左快捷栏是独立的操作入口，不是第四个内容区域。容器属于可扩展层，普通组和智能组是同层的两类行为；内置或外部只表示提供方。

目标是：内容声明自身信息与承载需求，容器声明承载能力和组织方式，宿主解析并装配。内容不依赖具体容器类型、容器实例 ID 或外壳 DOM；容器不解析文件、笔记、目录、播放队列等业务数据，也不根据插件名称猜测内容用途。

普通内容通常只需说明允许区域；需要上下文、特定运行能力或尺寸保障时，再声明对应需求。仅换文字标签／图标／标题栏，不增加一种承载要求。中央与侧栏可以是同一容器行为的不同表现；同时展开多个内容等变化则属于行为变化。

## 2. 身份与权威状态

| 概念 | 含义与归属 |
| --- | --- |
| 区域 | 宿主定义的 left／center／right，决定空间和布局限制 |
| 容器类型 | 一种可复用的组织与呈现实现；未来由注册表装配，当前只有宿主内置实现 |
| 容器实例 | 用户工作区中的某一个组，有稳定 ID、区域、成员及布局状态 |
| 内容类型 | 提供方注册的功能定义、公共信息与组件，不等于素材类型 |
| 内容实例 | 一次具体打开／绑定的界面，由宿主管理身份、位置和生命周期 |
| 业务对象 | 素材、文档、歌曲或会话等；可以被多个内容实例使用，不因容器改变而复制 |

容器类型、容器实例、内容实例不可共用一套含混的 ID。宿主持有唯一的成员关系与实际位置；容器只读取快照并发出操作请求，不能自己维护另一份可写成员列表。提供方拥有组件和业务，不拥有用户的摆放结果。

同一内容实例只有一个展示位置。移动保留实例；显式新开按内容的实例规则创建；智能工具拖出按固定绑定规则创建或复用，不能伪装成普通移动。

## 3. 内容侧契约

| 契约项 | 约定 |
| --- | --- |
| 基本信息 | 稳定类型 ID、可读名称、可选图标；缺图标由宿主提供通用表现。实例标题可随业务更新，身份不随标题变化 |
| 承载需求 | 允许区域、可选默认区域及确有需要的通用约束；默认是初次装配建议，用户已有位置优先 |
| 上下文 | 所需的具名能力及来源约束；由宿主解析具体来源，内容收到绑定后的运行上下文 |
| 内容呈现 | 提供业务组件，在分配的空间内响应尺寸；不查找容器 CSS 类或操作外壳节点 |
| 运行状态 | 接收有效可见性、操作焦点等必要状态；隐藏时可停止绘制，持续播放／请求由服务或会话管理 |
| 公共操作 | 提供已有命令机制能够表达的动作，宿主传入明确目标后执行；容器只呈现入口，不另造命令系统 |
| 实例与结束 | 声明复用／多开限制，并按已支持的生命周期处理关闭与保存；界面卸载不等于业务保存完成 |

名称、图标、状态和动作可以被容器用于标题、标签或菜单；业务正文仍通过内容插槽显示。动态信息须经宿主更新，不让容器重新查询业务实体才能显示一个标题。

这些项目是目标职责，不表示当前所有内容已经拥有同一组属性。现有 `tabTypes`、普通工具与固定工具的状态和关闭语义不同，见第 8 节。统一装配时必须明确适配，不能仅统一字段名称就宣称行为相同。

## 4. 容器侧契约与内容插槽

未来注册一种容器，需要描述以下内容；具体 TypeScript 签名、能力标记和状态版本格式在实际接入时确定，本批不导出空接口。

| 契约项 | 约定 |
| --- | --- |
| 类型身份 | 稳定 ID、名称及提供方；与用户创建的容器实例分开 |
| 可用区域与承载能力 | 声明支持的区域和通用承载方式；匹配由宿主完成，不列举业务插件 ID 作为准入名单 |
| 组织规则 | 选择显示一个内容，或支持多个内容同时显示等明确行为；选择、可见与键盘焦点分别表达 |
| 内容来源 | 普通组承载用户安放的实例；智能组使用宿主解析的上下文候选，不能凭空取得或重绑业务对象 |
| 呈现实现 | 读取宿主提供的内容描述和布局快照，为内容安排稳定插槽、标题和操作入口 |
| 局部布局状态 | 保存折叠偏好、展示方向等容器特有的可序列化参数；由宿主落盘，不重复保存权威成员关系、业务数据或运行时句柄 |
| 操作请求 | 选择、关闭、移动等请求提交宿主；读取成功／拒绝结果，再显示实际状态 |

内容插槽是宿主交给容器的承载边界。容器安排插槽的位置和空间、报告可见内容；宿主持有内容组件、来源和生命周期，不把业务 `Component` 的创建／销毁权直接交给外壳。

- 同一实例不能在两个插槽中各挂载一次；移动或改变外壳不能换业务实例的 key。
- 有效可见性由区域开合、容器状态和插槽展示状态共同决定。容器的“当前项”不自动等于窗口的操作焦点。
- 宿主协调焦点、原生拖动窗口区域、布局拖放和菜单等共同规则；容器提供键盘可达的选择和操作入口，并有可读名称。
- 外壳失效不应直接销毁内容或停止服务。错误、缺失与恢复由宿主协调；插件内部草稿仍遵守自己的保存机制。

契约不要求宿主解释一套通用布局脚本。容器代码负责自己的布局与交互，声明只承担装配、校验和恢复所需的有限语义。

## 5. 宿主装配与放置解析

本节约定目标解析顺序；首批只收敛现有规则，具体边界见第 8 节。当前尚未提供可配置的区域默认容器服务。

1. **已有实例优先。** 普通打开先按内容规则定位／复用已有实例，不重复创建；本步决定使用哪个实例，不覆盖后续明确的移动落点。没有新落点时，有效的用户位置优先于提供方默认建议。
2. **明确落点。** 拖放或操作指定容器时，校验区域、容器承载能力、上下文、实例限制和空间；不满足就说明原因，不偷偷改投另一个位置。
3. **只指定区域。** 在满足约束的容器中优先使用该区域当前操作的合适容器；需要新建时采用区域默认类型。多个候选的选择必须确定，不按插件加载顺序或任意优先级抢占；具体默认策略以后随设置能力落实。
4. **没有指定位置。** 有效的历史位置优先，其次内容的默认区域和宿主默认；保留失效记录，无法承载时明确反馈。
5. **提交前复核。** 操作期间来源、容器或插件可能已改变；宿主重新校验后一次更新实例归属与布局。预览、取消或拒绝不留下空组、重复位置或半次移动。

智能工具的普通打开先进入智能组候选机制，不因为有可用空间就创建固定实例。固定实例只有在显式独立打开／拖出时产生；上下文需求与区域需求是两种不同约束。启用一种新容器本身不改已有位置，也不成为所有内容的新默认。

## 6. 生命周期、上下文与保存

| 情况 | 公共语义 |
| --- | --- |
| 组内切换、折叠或区域收起 | 更新可见性，保留按现有策略托管的实例；不等同于关闭、保存或停止后台服务 |
| 同实例跨组／跨区域移动 | 只改变位置，不改变业务身份、来源绑定和实例数量；恢复有效范围内的局部状态 |
| 智能容器切换中央来源 | 按来源隔离工具实例；类型用于组合记忆，能力用于适用性，不能把旧目标草稿写到新目标 |
| 智能工具拖出 | 保留智能入口；创建／复用固定工具，绑定当时页面实例，切换焦点不改绑 |
| 来源失效 | 显示不可用状态，不跳到同名／同类型页面，也不自动创建替代页面 |
| 关闭或离开 | 经过对应内容已支持的生命周期；拒绝／失败保留原位置和可继续处理的状态，容器不能直接绕过宿主卸载 |
| 重开应用 | 恢复已保存的布局与内容快照；不承诺保存任意 React 局部变量、DOM 或未提交草稿 |

容器呈现、内容来源策略可以分别组织代码，仍同属容器职责，不新增第四层。普通容器不因当前页面改变而自动切换内容类型；其中的歌词、详情等仍可按自身明确语义更新。智能容器使用公共上下文机制，外观变化不应复制一套跟随与绑定实现。

布局和容器参数属于本机按仓库隔离的工作区；业务内容属于仓库或对应服务。命名布局预设不携带真实页面身份、固定来源或业务草稿。运行时能力、React 组件、DOM 和函数不写入布局。

## 7. 外部容器的接入与替换边界

以下是以后开放外部容器时必须满足的要求，不表示已有这些管理操作，也不排入本批实现：

- 启用使容器类型可用；设置默认仅影响后续装配，替换某个现有容器必须是明确操作。
- 替换前检查全部内容是否可承载，保留内容实例、顺序和来源；外壳局部参数按类型隔离，不把不认识的状态强行解释成新类型参数。
- 替换过程不能复制服务、丢失草稿或留下半次迁移。外壳挂载失败时保留原布局或由宿主托管，不以卸载内容当作回滚。
- 停用、卸载或缺失外部容器时，宿主优先用可承载的基础容器维持内容；无法承载则保留记录与可恢复占位。保留原类型及其局部状态，不把回退当作删除内容。
- 恢复插件不能抢走用户之后已经调整的布局。回退、恢复和格式升级必须有明确记录及校验。

现在继续使用现有普通／智能容器；不提前添加类型选择器、替换按钮或容器插件包规范。

## 8. 当前实现对照与未开放项

| 目标契约 | 当前实现与边界 |
| --- | --- |
| 内容独立声明承载需求 | `tool-placement-v1` 的工具无需指定容器；`placement.regions` 表达允许区域，`placement.default` 是普通工具的初始区域／组合建议。宿主生成稳定分组，用户存档优先；智能候选只需上下文声明。旧容器声明已退役，加载时明确拒绝 |
| 容器类型注册 | 默认分组由工具的放置建议生成，旧 `viewContainers` 已删除。侧栏已有固定的内置装配定义，记录可用区域、内容来源和呈现组件；不是外部注册 API。中央分割树保持原实现 |
| 内容描述适配 | `workbench-content.ts` 将页面声明、普通工具、固定工具及缺失工具占位转成带身份／标题／允许区域的内部描述；保留页面动态 `Title` 和工具 `Component` 的原始引用，不复制实际位置或统一生命周期 |
| 实例判断 | `content-instances.ts` 只读决定复用／创建／拒绝；页面和固定工具各自适配身份与配额，普通工具沿稳定 ID 唯一。计数不依赖区域或 React 挂载，关闭／保存不合并为同一协议 |
| 放置解析 | `workbench-placement.ts` 集中来源、区域、落点与空间检查；预览只返回结果，提交用最新快照复核后调用原布局操作。页面打开目标共用 `resolveEditorOpenTarget`；未开放外部容器匹配器 |
| 容器状态与操作 | `workbench-containers.ts` 分开投影容器呈现快照和宿主实例记录；呈现快照不含工具正文组件或页面能力对象。`container-actions.ts` 在最新工作区上执行明确动作。外壳不再接收可写布局或任意变换回调；仍是宿主内部接口 |
| 内容统一承载 | 主页面用 `tabTypes`，仍在中央；工具用 `toolViews`，明确声明后普通／固定实例可跨区。未开放任意主页面入侧栏 |
| 运行状态 | 页面 `active` 是中央操作焦点，`visible` 是本组可见；工具 `active` 表示当前呈现，多组可同时为 true。未来适配必须保持这个差异，不能直接按同名字段透传 |
| 上下文来源 | `TabApi.context`／`PageContext` 提供能力；`context.requires` 参与智能候选，`detachable` 约束固定实例。智能入口与拖出实例的停靠规则仍有区别 |
| 内容与插槽分离 | `SurfaceSlot` 显式登记位置，`RetainedSurface` 按插槽身份安放；中央页面、普通／固定工具与智能组共用登记和缺位停放，继续由原承载者持有实例。不是外部容器 SDK |
| 生命周期与存档 | 页面有 `beforeLeave`／`saved`，普通工具关闭通常保活，固定工具关闭释放；没有统一的工具关闭拦截协议，复杂编辑工具需单独接入 |
| 容器动态信息与通用约束 | 工具目前是静态 `title`／可选 `Icon`，页面有 `Title` 组件；不存在统一的动态标题／尺寸需求／容器状态版本接口 |
| 外部容器失败回退和替换 | 未实现；不把已有的内容插件缺失占位等同于容器类型失效恢复 |

源码依据：[UI 声明](../../src/plugin-api/ui/contracts.ts)、[页面上下文](../../src/plugin-api/ui/page-context.ts)、[工具装配](../../src/renderer/src/components/ToolViewSurfaces.tsx)、[智能工具装配](../../src/renderer/src/components/ContextToolSurfaces.tsx)、[侧栏存档](../../src/shared/sidebar-layout.ts)。当前使用流程及能力标记继续查[工作区布局](../plugins/工作区布局.md)。

### 首批代码接入边界

内部内容描述使用 `kind: page / tool` 区分现有生命周期，`id` 表示实例、`typeId` 表示贡献类型。`regions` 是允许区域；普通工具的 `defaultPlacement` 仅用于默认位置，不覆盖工作区中的实际归属。页面描述保留原 `TabType`，动态标题仍由原组件渲染；工具标题、图标及固定来源由同一适配出口供两侧和中央使用。描述只在内存生成，不另存一份配置。

工具菜单与拖放经过同一 `DockSource → DockTarget` 解析。来源可以是普通／固定工具、整组或智能候选；目标区分加入某组、在边缘独立放置和标签前插入。渲染层提供命中位置与实际尺寸，解析模块不读取 DOM；失败不创建固定身份或修改布局。真正的位置转移继续调用 `tool-docking.ts`、`sidebar-layout.ts` 与 `editor-layout.ts`，内容仍由原有稳定插槽承载。

本批保留原有默认策略：侧栏仅指定区域时独立成组，指定普通组时加入；中央仅指定区域时使用当前组，边缘落点沿分割树拆分。普通页面的“另一组”仍选择明确目标或相邻组，没有另一组时才向右拆分。**这还不是可按容器能力选择新类型的通用解析器。** 页面关闭保护、工具有效可见性、固定来源和工作区存档均沿用现有协议。工具的新声明入口见下节。

### 主工作台代码职责（2026-11-10）

本轮只整理已有交互，不新增容器类型、插件 API 或存档版本。修改时按下列入口定位：

| 要调整什么 | 源码职责 |
|---|---|
| 窗口装配 | `App.tsx` 接通工作区、宿主服务与画面；不直接管理设置退出和命令会话 |
| 设置窗口与退出衔接 | `app/settings-window.ts` 负责可见性、关闭检查和重载定位；`SettingsContent` 保留表单，`SettingsWindow` 提供局部弹窗，`AuxiliarySurface` 承载原生窗口；主页面导航不再关闭设置 |
| 重载后返回设置 | `settings-recovery.ts` 读写本窗口的一次性意图；保持既有 sessionStorage 键，不进入布局存档 |
| 命令面板会话 | `app/command-palette.ts` 负责打开、执行、取消和释放；上下文快照与业务校验仍归命令服务 |
| 设置分类目录 | `settings-catalog.ts`、`application-settings-catalog.ts` 提供内置和插件页面元信息；导航、搜索与定点打开共用，渲染组件仍按 ID 装配 |
| 工作区、页面注册、焦点与保活 | `app/workspace.ts` 是唯一状态所有者；页面结束协议继续由 `app/lifecycle.ts` 协调 |
| 内容实例规则 | `content-instances.ts` 统一身份匹配与数量决策；`page-instances.ts`、`context-tools.ts` 适配现有声明；集合导航的原位切换继续由 `collection-navigation.ts` 决定 |
| 工具预览与放置 | `app/workspace-docking.ts` 读取当前上下文和尺寸，调用 `workbench-placement.ts`；提交前重新校验，模块不另存布局 |
| 布局预设和返回点 | `app/workspace-presets.ts` 协调服务、存储通知与布局应用；需要释放的页面注册交回工作区处理 |
| 侧栏与中央菜单 | `components/sidebar-menus.ts`、`components/editor-menus.ts` 构造选项、分派明确动作；组件保留布局、事件与插槽呈现 |
| 外壳测量 | `components/workbench-geometry.ts` 读取区域、组、头部与项目的语义标记，输出普通坐标和尺寸；不依赖 CSS 类或固定包装层 |
| 拖放命中 | `workbench-hit-test.ts` 将坐标解释成加入、前插或边缘分割；能力、容量及来源存活检查仍在放置和布局规则中 |

语义标记是宿主内部测量约定，不是插件自行操作外壳的 API；它与 `SurfaceSlot` 的内容安放协议分开。测量不缓存为第二份布局状态，预览不创建实例。头部样式或包装层可以变化，但必须保留对应区域、组、头部和项目标记。

已删除未注册的旧设置标签页、未被运行代码使用的 `currentContainer` 和旧内容拖窗占位；设置浮层及定点打开保持。旧 settings 标签转浮层、侧栏／中央旧布局读取及备份仍在存档读取边界，不能随旧界面一起删除。旧插件侧栏声明、`showPanel` 和底部部件入口已退役；公共示例已迁移，实验插件另行适配。样式入口现已按基础、控件、工作台、设置与内容分开，职责和层叠约定见[前端界面约定](../development/前端界面约定.md#样式归属)。

### 实例判断接入边界（2026-11-10）

页面和固定工具共用只读的 `ContentInstance` 与 `ContentInstanceRule`，分别提供实例 ID、类型、内容键，以及复用范围、显式新建许可和数量范围。它们不是新增的插件 SDK，也不持久化到布局。适配器读取完整的逻辑记录，隐藏和未挂载不改变计数；普通工具由稳定 ID 保证唯一，不为结构上不可能发生的新建再造计数状态。

共享判断先选择可复用实例，再校验新增；规则收紧不阻止定位已有内容。固定工具的来源身份匹配集中到同一适配函数，拖放落点解析直接携带选出的实例 ID，提交时仍用最新快照重算；失效来源或落点失败不改绑。页面关闭／替换继续经过 `PageTransitions`，工具关闭仍区分隐藏普通工具和释放固定绑定。完整声明指引见[内容实例规则](../plugins/工作区布局.md#内容实例规则2026-11-10)。

### 工具声明与默认装配

`shared/tool-placement.ts` 收敛工具声明校验和初始装配，公共入口为 `tool-placement-v1`。新工具不必声明容器，默认允许两侧、普通工具优先右侧独立成组；只允许左侧则默认左侧。可选 `placement.default` 只建议侧栏区域与本插件组（或宿主导航／详情组），不能覆盖用户已有摆放。同组合区域不一致在加载时拒绝，不留到拖放才发现。

智能工具通过 `context` 进入候选，不再要求 `container: 'host.context'`，也不填写普通默认位置；固定实例仍按允许区域和真实拖出位置安排。普通工具本批不支持仅中央或初始中央放置，内容页面也不因此获得侧栏能力。

旧声明适配已删除；插件只描述工具与放置建议，内部目录仍用默认组 ID 与现有布局装配。保存的工具身份、实际位置、关闭状态、比例、未知 ID 和 v4 格式保持；新默认只影响新工具或明确恢复默认。仍未开放自定义容器类型。公开用法见[工作区布局](../plugins/工作区布局.md#插件声明)。

### 容器快照与宿主动作

侧栏外壳读取 `SidebarSnapshot`，包括全部保存的成员、当前可用内容、组内选择、比例与区域开合。`present` 表示是否占据布局，`visible` 再考虑区域是否展开；都不是中央页面的操作焦点。智能组的候选、顺序、来源名称和空状态由宿主投影，外壳只安排插槽。成员／偏好数组不与可写存档共用；组件和能力对象只出现在独立的宿主实例记录里，保持原引用，不作为容器外壳的输入。

关闭、排序、恢复默认、调整尺寸和修改智能组合，通过 `app/container-actions.ts` 的明确方法提交，纯动作模块读取提交时最新布局并校验目标。智能动作携带当时的来源页身份和类型，执行时核对存活与能力；菜单等待期间不能把旧偏好整体写回，也不能改投新页面。拖放仍走已有放置解析，普通内容页的关闭仍走 `beforeLeave` 等页面生命周期。

整组关闭时，普通工具隐藏并保留位置，固定工具只释放该组内的实例，智能组关闭保留组合。恢复默认侧栏是一次工作区更新，保留中央内容及其固定绑定。拒绝的动作保持原工作区。旧的 `onChange(layout => ...)` 和界面内写整个智能偏好的入口已删除，侧栏外壳不再保留这条直接改写布局的通道。

中央与侧栏仍保留各自读取模型，工具和页面仍由原承载者管理；没有因为收敛容器动作而统一其业务生命周期。

### 内部插槽登记与承载

`surface-slots.tsx` 提供按工作区隔离的 `SurfaceHost`、`SurfaceSlot` 和临时登记表。容器使用明确插槽身份登记实际 DOM；中央组、侧栏组和智能组正文各有命名范围，侧栏整组换侧不改变组身份。`RetainedSurface` 只接收目标插槽身份，移除旧 `target()`／`placement` 参数，不再由内容持有者用 CSS 选择器查找位置，也不在每个外壳维护私有节点表。

- 插槽撤下前捕获滚动并把直属内容移入宿主隐藏停放区；内容组件与 Portal 身份保持。插槽晚到或同身份替换后，登记通知自动重新安放，不要求内容再次渲染或用户调整窗口。
- 登记清理核对注册身份，旧 ref 的迟到清理不能删除接替它的新插槽。一次提交中的变化合并处理；外层安放后再复核嵌套插槽，让滚动在真实尺寸下恢复。
- 实例创建、可见性、首次显示挂载与页面后台保活规则仍由原承载者决定。登记只管理临时 DOM 位置，不自行创建页面、改写布局、重绑来源或触发业务结束。缺位停放不是数据保存；退出、释放和恢复仍走内容各自的协议。
- 本机存档不保存插槽节点或登记表；重启由现有布局生成位置并重新登记。CSS 类负责样式；拖放测量通过外壳语义标记取得几何信息，不充当内容安放协议。

这仍是宿主内部边界。外部容器注册、显式替换／失败回退及新设置未开放；内容类型和容器类型仍按实际案例逐步适配。

### 内置容器装配

左右侧栏通过 `components/SidebarContainers.tsx` 的固定定义装配普通组和智能组。每个定义包含允许区域、内容来源（用户安放的成员／主页面上下文）、`Header` 和 `Body`。装配时校验区域和来源快照是否匹配，头部与正文使用模块级稳定组件；没有新增类型或设置，也不改 `tabs / context` 存档身份。定义不是可动态注册的外部 SDK。

- `SidebarWorkspace` 保留区域尺寸、分组排列、公共标题栏操作、菜单、拖放接线和动作分发；用定义呈现组头部／正文，不再直接写两类正文装配分支。
- 外壳只接收本组只读快照、显式交互方法和宿主分配的插槽身份。普通组安排工具选择器与正文插槽；智能组安排来源指示、候选选择器和上下文正文插槽。插件正文组件、完整 `UiHost` 和运行时能力不交给外壳。
- 普通／固定工具仍由 `ToolViewSurfaces` 持有；智能工具改由稳定的 `ContextToolSurfaces` 持有。实例以“组＋来源页＋工具”识别，外壳换侧、关闭或重挂只撤下／重建插槽，工具转入宿主停放区并沿用组件。首次显示才挂载；隐藏时向工具传递 `active=false`，来源失效或组实际移除仍按原策略释放。固定实例关闭仍走原释放协议。
- 两类头部复用 `SidebarToolStrip`：当前工具展开名称，其余显示图标，空间不足进入溢出菜单；键盘仍可切换全部工具。智能来源使用头部的只读指示；普通组的固定来源进入工具提示和菜单，不随当前项改变而增减头部元素，正文也不补来源栏。固定工具移入中央后保留原来源条。旧 `ContextToolContainer` 已撤下，业务组件仍由承载层持有；菜单携带捕获的来源，宿主提交时复核。

这里固定了内置呈现组件的装配位置，并把智能实例所有权从外壳移到宿主。来源投影、布局动作和生命周期仍知道普通／智能两类规则；增加新行为不能只往定义表塞一个组件就视为完成。外壳自身的临时 UI 可以随布局重挂；需要跨重挂保存的容器局部状态以后要有明确协议，不能与业务草稿混存。

后续改现有容器样式，可从定义中的头部／正文入手，复用快照、动作和插槽；外部注册、替换／失效回退、中央容器统一和新增承载行为仍须实际案例验收。

## 9. 新增功能时的接入判断

1. 内容自身的信息和动作，走页面／工具／命令接口；详情内部的小部件继续使用对应内容的内部扩展点。
2. 需要伴随页面，声明能力需求并使用来源上下文；需要独立服务，接入已有窗口／本机服务，不依靠某个容器一直可见。
3. 需要换标题、图标或标签样式，改容器呈现；内容业务组件不依赖外壳结构。
4. 需要新的组织行为，先对照本文说明内容承载、可见性、生命周期和恢复需求，再补宿主契约；不在业务插件中绕过布局所有权。

以后实施统一装配或外部容器时，用实际场景验收：原内容无需认识新容器；显式落点得到尊重；同实例移动不重复挂载；焦点、可见性和来源不混用；取消／失败不改归属；关闭保护及重启恢复按各内容约定接续。多内容同时显示的容器必须另验可见性和资源开销，不能用“文字标签换图标”的验证代替。


### 同会话的多个显示窗口（2026-11-14）

内容小窗沿用普通中央容器能力，`EditorGroup.window` 只描述组的显示位置，主窗口的树仍只包含主窗口各组。中央内容由 `EditorSurfaces` 统一持有，工具仍由 `ToolViewSurfaces` 持有；`EditorWorkspace` / `ContentWindows` 提供插槽，不各自装载另一份页面。`RetainedSurface` 移动稳定 DOM 根并更新 `UiDocumentContext`，不复制核心连接、provider 或草稿。`workspace-windows.ts` 复用既有放置解析后提交位置，`lifecycle.changePages` 先检查一组全部页面再整体关闭。拖出智能候选仍通过原固定实例协议。

布局尺寸以当前容器为边界；外壳提供的动画终点宽度是可选提示，缺省使用容器自身宽度。尺寸观察、选区坐标和逐帧调度归当前显示文档；公共 `useUiEffect` / `useUiFrame` 统一重绑与清理，`UiPortal` 提供浮层目标，不为主窗／小窗各写一套内容布局。业务生命周期仍归原会话，避免移动导致重新保存／恢复或重复启动服务。

内容允许区域与原实例规则决定是否可移窗；不增加内容与某个容器类的互相引用。正常关窗关闭内容，异常承载丢失才回主窗；小窗内部多分屏和外部容器类型仍未开放。详见[内容小窗](../plugins/工作区布局.md#内容小窗2026-11-14)。
