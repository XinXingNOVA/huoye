# 查询与视图

视图保存名称、查询、排序、布局和布局选项。成员由素材当前数据决定，不保存成员清单；同一素材可出现在多个视图。规则属于仓库，临时查找、选中、滚动与显示调整属于本机标签页。删除视图不删除素材。

## 日常使用

- 侧栏“视图”旁的 `＋` 创建视图；也可以先在列表里筛选，再保存为视图。
- `＋筛选` 打开条件编辑器。不同条件同时满足；先“确定条件”，再“应用筛选”。未确定的条件存在时不能保存外层表单。
- 数据块存在性使用“有／没有”；字段根据定义提供等于、任一、全部、范围、未填写和文字搜索。数字格式会说明单位，日期使用本机时区输入并保存绝对毫秒时间。
- “任一”表示列表中至少一个成员命中；“所有”拆成多条相等条件。当前不提供跨字段 OR、嵌套条件组或相对日期。
- “未填写”表示没有字段索引值，包括没有这个数据块的素材。要找某模板中未填的字段，组合“有此模板”与“字段未填写”。不把所有空字符串或占位文字统一理解成缺值。
- `排序` 使用收录时间或有索引的单值字段，先支持一个主排序字段；空值末置，同值按收录时间和身份稳定排列。列表字段不能排序。
- 保存规则显示在可展开的摘要中。临时筛选和排序单独呈现，可逐项移除或重置；工具栏搜索继续限定数据块／字段并与规则取交集。
- `视图 ⋯` 提供编辑规则、将当前条件与显示更新到此视图、另存为新视图。编辑规则不会自动写入，保存后其他打开页同步；各页临时调整独立保留。
- 保存使用视图块序号校验。规则在别处变化后，旧表单不能覆盖，可载入最新规则或另存。表单不是跨重启的共享草稿，取消表单会放弃这次规则编辑。
- 原视图被删除时，已打开页面保留查询并成为未保存页面；保存应另建视图，不复活已删除身份。

## 侧栏导航

保存的视图现在也是整理入口，不必先打开它再放入内容：把库内素材或库外文件拖到侧栏的视图名称，悬停会显示写入／检查说明。放下时按该视图**保存的规则**处理，不使用当前中央页的临时筛选，也不自动切换标签。导航空白、设置按钮与分面不是导入入口；预设视图和插件自带导航仍通过打开后的页面接收内容。

视图行的 `⋯` 菜单（或右键）提供固定到常用、上移／下移、编辑规则、隐藏与删除。固定的视图放在预设入口上方；其他保存视图放在预设入口下方。拖住行首的手柄或星标可以排序，拖到另一分区会对应固定／取消固定；也可以用菜单调整，不要求拖拽。隐藏后通过“设置视图菜单”重新显示，删除仍保留素材并可撤销。

规则是仓库数据，**固定与顺序是本机、按仓库身份保存的导航偏好**（`localStorage` 的 `navigation:views:<libraryId>`），不修改视图查询或素材，不属于素材撤销历史，也不随仓库备份到其他机器。原有显隐设置继续沿用本机的 `navigation:visible:<root>`。缺失或隐藏身份的位置暂时保留，撤销删除或重新显示会接续位置；新视图追加在已有顺序之后。此批不增加任意导航分组或预设入口排序。

字段与候选值来自数据定义。模板与已停用插件的可用快照可参与查询，休眠字段不推导拖入写入。暂时缺失的定义与布局不会被自动清除；不可用条件保留，未知的 has 查不到、lacks 按无此块处理，缺失字段的 empty 按无值处理，原布局不可用时显示默认布局。

## 拖入、导入与数据修改

悬停目标视图／区域时，宿主用同一个 `splitConditions` 协议说明将写入哪些确定值、需要满足哪些只读条件。普通修改查询不会改素材。

| 条件 | 放入行为 |
| --- | --- |
| 可写列表字段等于某值 | 追加该值，保留其他值，不重复追加 |
| 可写单值字段等于某值 | 设置该值，可能替换原值 |
| 可写单值字段为空 | 清空该字段 |
| 有可附加模板 | 缺少时挂上空模板 |
| 多值任一、范围、全文、内容／派生字段、休眠字段 | 只检查，不选择值、不改原内容 |

执行前等待相关加工；在同一事务保存点中批量写确定值，再按完整查询验收最终状态。有拒绝时回滚试写，只提交通过的项；拒绝项不留下半次字段或历史，接受项形成一次可撤销操作。指定 ids 范围也必须满足。撤销这里的数据整理不等于撤销原件导入或文件空间操作。

库内拖入使用现有素材身份，不复制原件，也不额外移除来源标签；单值修改可能使素材离开其他视图。库内拒绝项保持原状，并在处理结果中显示原因。

外部输入拖到有条件的视图，先进行不写数据的保守预检。格式、输入文件名、类型、大小等可以提前判断；需要正文、派生块、引用或加工结果的条件列为“待确认”，不把未知当成匹配。输入文件名可能不同于查重后已有素材的显示名，预检只是初步判断。

- 全部初步匹配时继续导入；否则一次展示批量选择，默认只选匹配项。
- 未匹配／待确认项默认不收录，也不复制到文件空间；可以额外勾选，界面明确提示“即使未进入视图也会留在仓库”。无法读取的输入不能勾选。
- 关闭或取消确认时，本次还没有开始导入。确认后按仓库导入配置执行；若配置只保存文件，仍遵守该配置。
- 严格项在正式收录事务中按完整 Query 写入、验收。文件变化、查重后实际数据不同等导致拒绝时，整批仓库修改回滚，不复活回收站条目、不遗留附加字段。准备阶段已经保存的空间文件保留为候选，错误信息说明此状态；不通过删除原件模拟取消。
- 明确额外选择的输入可以先收录，再等待加工并执行视图准入；最终未匹配的仍在仓库，并按新增／恢复／原有素材分别反馈。

当前没有为预检另建一套插件加工环境，所以图片尺寸、正文等不能在完全不收录的情况下自动确认。需要这类条件时，选择仍然收录就是明确接受“可能不进入视图”；不宣称已经提供完整的离线加工暂存区。

异常结果按批保留到主动关闭，连续拖入不覆盖前一批。摘要区分已进入、未收录、已在库但未匹配、处理失败；详情按原因汇总、分页列出名称和首个未满足条件，并可查看对应素材。失败不是不匹配，关闭提示不是撤销。结果是本次处理的快照，窗口关闭后不保留，不是持久任务日志；后续修改规则或素材可能改变归属。

中央视图、标签页、布局提供的拖入区域和侧栏保存视图共用接纳入口及规则说明。异步读取／下载之前捕获目标规则快照，之后切换页面、编辑或删除视图不会悄悄改成本次操作的新条件；结果反馈使用当时的目标名称。导航排序使用独立的拖拽类型，不能被误识别为素材导入。不提供通用“从视图移除”的反向操作。

## 公共查询与接入

类型见 `src/shared/query.ts`，外部输入校验见 `src/shared/query-input.ts`。现有 Query 和视图块结构保持，新增长度为 1～100 的同字段 `in` 条件：

```ts
const query = {
  has: ['image'],
  where: [
    { op: 'in', kind: 'file', field: 'ext', values: ['png', 'webp'] },
    { op: 'range', kind: 'image', field: 'width', min: 1600 }
  ],
  sort: { kind: 'file', field: 'name' },
  dir: 'asc'
}
```

UI `core.query`、插件查询与 MCP `search_items` 共用核心查询实现。MCP 输入和视图保存复用 schema；空 in 候选在这些输入边界拒绝，直接核心查询的空集合返回零项，不扩大成全部。多条 eq 继续表示 AND。排序、查询与查看器的来源导航共用有效 Query。

宿主新增 `previewViewImport(inputs, query)` 与 `importToView(inputs, {requestId, query, allowUnmatched?: number[]})`。前者只读展开目录并返回输入定位、初步状态和原因；后者只接收展开后选择的输入，`allowUnmatched` 是本次输入下标的明确例外。其余项在原导入事务内验收，沿用回执和失败重试；参数／Query／例外选择均参与请求签名。普通 `importToLibrary`／MCP 导入保持原有语义，不由某个 UI 视图暗中改变。

依赖 `in` 的外部插件声明 `query-in-v1`：后端使用者放在 `coreFeatures`，仅 UI 使用者放在 `uiFeatures`；旧宿主应拒绝未知能力。已有插件无需重新声明，不使用新条件时行为保持。不要让旧代码把未知 op 当作 range；消费条件的插件应穷尽区分或直接传给宿主。

内部视图模块新增 `core.run('view', 'saveView', { id?, expectedSeq?, title, query, layout, options })`，更新时 expectedSeq 必须匹配，创建返回 `{ id }`。这没有新增 MCP 写操作；MCP 本批增强的是通用查询表达能力。

列表刷新保留已有画面，丢弃过期请求结果，错误显式显示；这里没有引入长期查询缓存、物化视图或全新存储格式。


## 侧栏分面与全库词汇（2026-11-08）

侧栏用于缩小当前页面范围，打标和编辑查询条件则需要全库词汇，两者不共用一个已被裁剪的列表。宿主分面支持按 Query 统计；集合提供按字段排除临时条件后的范围，保留基础视图规则、搜索、其他字段条件及动态身份交集。点击标签不让同一范围的兄弟标签消失；分屏时跟随当前操作页面。

标签分组仍是全库组织数据。侧栏隐藏范围外标签和空组，已选零结果条件保留清除方式；「管理全部标签分组」展示完整目录。搜索、切页和隐藏组不会写仓库。完整接口、无查询与空查询的区别见[公共 UI API](../plugins/公共UI%20API.md#按页面范围联动分面)。
