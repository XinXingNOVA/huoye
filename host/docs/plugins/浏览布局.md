# 浏览布局

2026-11-05。浏览布局负责把同一批素材排成瀑布流、表格或看板；查询视图决定成员，工作区布局决定页面放在哪里，阅读器负责打开后的单项内容。三者不混成同一个协议。

## 使用与配置范围

集合工具栏的“显示”面板用于切换布局、调整布局自己的选项和尺寸。“保存／编辑视图”使用同一套布局选项组件。

| 内容 | 归属与生效范围 |
| --- | --- |
| 布局 ID、分列字段等选项 | 本页调整；经“视图”菜单保存后成为仓库中的视图规则 |
| 每种布局的尺寸、滚动锚点、私有界面状态 | 本机工作区中的当前标签页；换布局分别接续，重启后恢复 |
| 本库新页面默认 | 本机按仓库身份保存；仅用于没有指定布局的新页面，不改已打开页面或已有保存视图 |
| 多选、搜索、临时筛选 | 集合拥有；换布局不另建一份，不随布局私有状态覆盖 |

默认偏好包含布局、选项和尺寸，存于应用本机 localStorage 的 `rm:browsing-default:<仓库 ID>`，带版本标记。不把选择、滚动位置或插件私有状态带给新页面。“清除默认偏好”让后续无指定布局的新页面回到瀑布流，不重置当前页面。

每页首次打开取得默认快照并随页面存档；显式 `CollectionParams.layout` 始终优先。旧页面中已指定的布局不会被新偏好重写。“重置本页临时调整”恢复页面基础规则，清除各布局临时选项缓存，但保留各布局尺寸与浏览位置。保存视图目前保存布局与语义选项，尺寸仍为本页偏好。

插件停用时，缺失布局临时投影为瀑布流，并显示原因；原 ID、选项和该布局状态仍保留。在回退布局调整尺寸／选项，只改变临时瀑布流。明确切换到另一布局才改变本页选择。重新启用后按原规则继续，缺失布局的仓库默认也不会被悄悄清空。

## 声明一个布局

使用新增配置、默认布局或私有状态协议的外部包声明 `uiFeatures: ["browsing-layout-v1"]`。基础 `apiVersion` 仍是 1。旧宿主拒绝不认识的能力，新宿主继续接受只用旧布局接口的包。

```tsx
import type { LayoutDef, LayoutOptionsProps, LayoutProps } from '@resource-manager/plugin-api/ui/contracts'

const layout: LayoutDef = {
  id: 'example.cards', title: '卡片',
  description: '适合查看封面和简短信息。',
  defaultOptions: { showCaption: true },
  size: { label: '卡片大小', min: 120, max: 480, step: 10, default: 220 },
  Component: Cards,
  Options: CardOptions
}
// export const plugin: UiPlugin = { id: 'example', layouts: [layout] }
function CardOptions({ options, setOptions }: LayoutOptionsProps) {
  return <label><input type="checkbox" checked={options.showCaption === true}
    onChange={e => setOptions({ ...options, showCaption: e.target.checked })} />显示标题</label>
}
```

- `size: false` 不显示宿主滑块。省略 `size` 为已有包保留 120～480 的“卡片大小”；新插件应明确声明是否需要。
- 尺寸经 `LayoutProps.zoom` 传入，以保持旧接口；名称可以是“列宽”“行高”等，宿主按声明限制范围。`step` 只规定滑块步长。
- `defaultOptions` 是初始选项，宿主浅合并已保存选项，不丢未知字段。嵌套字段校验、旧业务选项迁移仍由插件负责；这不是业务 schema 或通用表单系统。
- `Options` 可选，宿主在显示面板和保存视图中复用。收到 `options` 后不直接修改它，调用 `setOptions` 提交完整新对象。
- 标题、说明、尺寸范围和默认选项在装配时校验；配置与私有状态要求 JSON 对象，每次提交最多 64 KB，拒绝函数、无限数、DOM 等不可存档内容。不要保存查询结果、媒体字节或可重建缓存。

## 布局运行与状态

`LayoutProps` 接收有效 `query`、`ids/aspects`、`options`、`zoom`、`selection`、`host` 和公共动作。

- `active` 是唯一操作焦点；`visible` 是所在分屏当前可见。多个布局可以同时可见，可据此报告可见素材的加工优先级。
- 单一滚动轴可用 `anchor/onAnchor(id)`；按素材身份恢复比固定像素更能适应尺寸变化。等待容器有尺寸、异步结果到达再恢复，锚点不存在时回到有效位置。
- 多列或其他复杂界面用 `state/onState(object)`。状态按标签页和布局 ID 隔离。看板保存横向位置及按字段／列标识区分的素材锚点，表格保存行锚点和横向位置。
- 状态是界面快照，不能冒充业务保存、事务或共享编辑。用户滚动等操作发生后报告变化；不要等卸载才保存，也不要每次渲染回写收到的状态形成循环。
- 切换布局会卸载旧布局组件，接续它最后报告的状态；不保持所有布局的 DOM、订阅或虚拟列表同时运行。
- `onPointer(id,event,order?)` 复用集合的选择语义，可按列提供 Shift 连选顺序。`dragIds(id)` 保持多选拖出。
- `onOpen(id,order?)` 可提供当前列或视觉顺序，宿主先与当前结果相交，再作为 `NavigationList.orderedIds` 交给打开器。阅读器按公共导航协议消费；右键通用打开仍使用集合的导航来源，不擅自把某列作为整个页面的导航范围。
- 虚拟化和方向键的空间规则由布局实现，宿主不假设所有布局都是矩形网格。

`ResourceCard`、`ResourceCover`、字段编辑器及 `computeMasonry` 仍是可选公共零件，不要求所有布局都使用卡片。

## 基础实现与渐进接入

瀑布流继续内置，使用同一 `LayoutDef` 声明，保证零外部插件也能浏览素材。表格／看板保持独立外部工程；1.1.0 接入本协议，更新包后分别隐藏无效尺寸滑块／显示“列宽”，并恢复各自浏览位置。已有包仍可加载，但未主动报告的插件私有滚动状态无法由宿主凭空恢复。

本批不增加新列表或时间线业务插件，不统一任意布局的方向键导航，不改变仓库／文件空间格式，也不增加核心或 MCP 写操作。后续用真实布局需求继续检验接口。


## L2 定位与渲染回执（2026-11-17）

外部布局可声明 `uiFeatures: ["workbench-session-v1"]`，并在 `LayoutDef` 设置 `session: true`，接入公共集合的 `LayoutProps.session`。旧包不声明时继续正常浏览，但 MCP 不宣称其列表已渲染，也不尝试定位。

`session.revision` 对应本次 ids/aspects 的查询结果版本。在 DOM 提交后调用 `session.onRendered({revision, ids, revealToken?})`，ids 只列布局实际挂载的素材（可以含 overscan），不能把完整查询结果冒充已挂载项。只在 visible 时回报；虚拟布局先滚动并挂载目标，确认其进入视口后再附 revealToken。只回报 DOM，不承诺图片解码完成。

`session.highlightedIds` 是独立的临时展示提示；不能写入 selection 或调用 onPointer 来模拟用户选择。宿主 ResourceCard 新增可选 highlighted 属性。收到 `session.reveal={token,id}` 后每个 token 定位一次；查询更新和用户滚动不能不断重新抢位置。集合负责清除提示、生命周期及查询版本，布局只负责自身渲染与滚动，不创建第二份查询结果或选区。

自定义页面如使用公共 ResourceCollection / CollectionSurface，自动暴露实际有效查询和选区。完全自绘页面可通过 TabApi.collectionSession 提供同等运行时契约；缺失能力时保持 unsupported，不从 params 或页面存档猜测现场。
