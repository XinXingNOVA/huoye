# 插件组合预设

2026-11-06。组合是一次性套用的功能选择方案。布局预设负责区域安排，插件组合负责启用能力，插件内部配置继续由各插件管理。应用组合后可以继续单独勾选，不持续绑定、不反向修改原组合。

## 使用

「设置 → 当前仓库 → 插件组合」：保存当前选择、选择已有组合、预览变化、确认放入下方勾选，再统一应用；插件配置有变化时才重新加载。套件原版与配套布局见[本地插件套件](本地插件套件.md)。可以重命名、用当前选择更新和删除组合。更新、删除需要确认；删除组合不改变仓库选择或卸载插件。

- **补充到当前选择**：启用需要的插件和必需依赖，保留其他选择。
- **按这套组合切换**：列出额外的停用项；核心功能保留，开发来源及其必需依赖保持。
- 当前勾选含未应用修改时，保存捕获这份草稿；预演也以草稿为基线，并明确确认替换。预览后继续改勾选会使该预览失效。
- 组合保存的是用户的启用意图，不以运行成功为条件。缺包或加载失败的已选正式插件不会在保存时悄悄消失。

## 归属和边界

组合目录在本机应用的 `userData/plugin-presets.json`，跨仓库共用。文件有格式版本和大小限制，临时写入后替换；坏配置报错并保留，不重置为空目录。组合更新与删除核对修订号，避免另一个仓库窗口的旧表单覆盖新修改。

实际启停仍通过现有插件配置事务写入目标仓库的 `plugins/externalPlugins` 配置。组合目录不写仓库或文件空间，不改变素材、原件和已有数据块，也不进入素材撤销历史。安装由独立的套件／包流程负责；方案应用不自动安装、卸载或升级，不导出插件内部设置。套件原版与可选配套布局由静态目录提供，MCP 及文件空间授权保持独立。

正式包按稳定插件 ID 匹配，保存时版本仅作提示：优先沿用当前仓库／草稿已选版本；未选时，套件方案的精确推荐摘要可明确选择一个版本；没有摘要时，只有一个已安装版本才自动选取。多版本、缺包、依赖环和不满足的必需依赖列为问题，不静默跳过，也不依据版本提示选“最新”。可选依赖不自动启用。预演仅检查声明，插件持久数据兼容和实际代码加载仍由原装配器检查，运行失败继续在插件列表显示。

开发插件不写入组合；正式绑定即使暂被开发来源覆盖也原样保留。组合明确要求一个正处于开发模式的 ID 时拒绝应用，提示先在开发区域处理，不自行切回正式来源。替换模式保留开发来源需要的已选能力，不改源码目录或构建快照。

## 公共 UI API

插件声明 `uiFeatures: ["plugin-presets-v1"]`，类型从 `@resource-manager/plugin-api/ui/plugin-presets` 导入。由当前仓库窗口提供 `host.pluginPresets`；宿主基础面板也调用这个服务。可以用已有 `settingsSections` 或工具视图组织另一套管理 UI，无需访问 `window.bridge`、应用配置文件或宿主私有模块。首版没有专门的管理界面替换贡献或应用级无仓库入口。

| 方法 | 语义 |
| --- | --- |
| `list()` / `onChanged(listener)` | 读取应用组合目录／订阅目录变化，返回取消订阅函数；通知后重新读取 |
| `current()` | 本仓库已保存的完整选择、校验基线 `revision` 和开发插件 ID；不是实际运行成功列表 |
| `save(title, selection?, options?)` | 新建组合；省略选择时捕获仓库已保存配置，传入时保存界面草稿 |
| `copy(id, title)` | 原版或用户组合另存独立用户副本，保留说明与配套布局 |
| `rename(id, revision, title)` | 修改名称；修订号取自对应组合记录 |
| `update(id, revision, selection?, options?)` | 替换组合内容，名称与 ID 保留 |
| `remove(id, revision)` | 删除组合，不改变已应用的仓库 |
| `preview(id, 'add' \| 'replace', base?)` | 形成候选选择、启停差异、依赖来源、问题及提示；不写入、不重载 |
| `apply(selection, revision, arrangement?)` | 复核并应用；有变化才重载，返回 `{ reloaded }`；布局交由宿主持久接续 |
| `pending()` / `retryPending(id)` / `cancelPending(id)` | 查看未完成的布局接续、重试或取消；取消不回滚插件配置 |

2026-11-13：`list()` 汇总用户组合和套件原版，附 `source` 与 `editable`；套件原版不能重命名、更新或删除，应用安装区移除套件只撤下其原版。`options` 支持 `{ description?, layout? }`；更新时省略布局保留原值，显式 `null` 移除布局。`arrangement` 为 `{ title, layout }`，通常来自用户所选方案，也可以使用公共工作台快照。`pending()` 的 `problem` 表示需要先处理的运行环境问题；没有 problem 也仍须由宿主检查布局和保存结果。`apply()` 返回只代表选择处理完毕，配套布局可能仍待接续，不应立即宣称整套完成。

配套布局亦出现在工作台预设服务的 `scheme` 只读来源。这里可以单独预览／切布局，不改变插件启用。接续只由宿主工作区控制器完成，插件管理 UI 不调用私有完成回执或自行落盘 workspace。

`PluginSelection` 的 `disabled` 仅放可关闭的仓库内部功能 ID；`external` 为完整正式绑定 `{ id, hash, enabled }[]`。从 `current()` 或预演结果取得后修改，保留无关和被开发覆盖的登记；不能用省略条目表示卸载。只传 ID／摘要，不由调用者提供包声明。

```ts
// 用户点击预览时；draft 可省略，也可传入自有界面的待应用选择。
const plan = await host.pluginPresets.preview(presetId, 'add', draft)
// 展示 plan.changes / issues / warnings，允许用户确认或返回调整。
// 用户明确点击应用时才调用；不要在渲染、订阅或插件启动时自动应用。
if (!plan.issues.length) {
  await host.pluginPresets.apply(plan.selection, plan.revision)
}
```

组合记录的修订号与仓库选择的预演基线不是同一个东西。预演基线绑定目标仓库、已保存选择、安装包集合和开发覆盖，提交前及页面收尾后都会核对；变化后重新预演。组合在预演后改名不会改变已经展示的候选选择。

应用由主进程持有，复用原有批量提交和仓库重载，管理插件自己被停用也能完成。配置已满足且运行正常时跳过收尾与重载；有布局则走同一持久接续链，保持运行实例。页面保存／校验失败不提交；确认配置提交失败时保留原选择并恢复页面；响应丢失且结果不确定时保留接续意图，重开核对；已保存而重载失败明确返回 `[PLUGIN_PRESET_RELOAD]`，应续接重新加载或重新打开仓库，不能宣称已经回滚。重载会结束服务、播放和会话撤销历史，按原页面／草稿协议保存恢复，不承诺布局切换那样保留运行实例。此 API 不提供缺包自动安装、启动失败重试授权或任意包管理入口；失败插件仍使用原插件面板的重试操作。

## 维护位置

- `shared/plugin-presets.ts`：数据契约与公共服务；`plugin-api/ui/plugin-presets.ts`：SDK 类型入口。
- `shared/plugin-preset-plan.ts`：捕获选择、依赖和版本预演；使用现有 `resolvePluginPlan` 判断装配规则。
- `plugin-packages/presets.ts`：本机组合目录和提交／重载的失败阶段。
- `main/plugin-presets.ts`：当前窗口上下文、基线、IPC 和生命周期协调。
- `renderer/src/components/PluginPresets.tsx`：默认管理 UI；设置页拥有原启停草稿。

验证命令与覆盖边界见[开发与验证](../development/开发与验证.md#插件组合预设)。
