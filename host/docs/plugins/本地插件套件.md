# 本地插件套件

2026-11-15。已串起本地分发、已有仓库应用及按方案新建仓库。套件是静态安装包，不是额外运行的插件；仓库和文件空间格式不变。

## 使用

1. 在「设置 → 全局应用 → 套件与插件包 → 安装套件或插件包…」选择 `.rmsuite`，也可与 `.rmplugin` 一起多选。预览列出每个包及将登记的方案；确认后逐项安装。
2. 安装结果中的「在当前仓库中预览此方案 →」直达「当前仓库 → 功能与方案 → 方案组合」，并选中方案。在开始页安装时，可用「用此方案新建仓库 →」进入起始方案选择页。
3. 默认补充到当前选择，亦可选按方案替换。先查看启停变化、依赖、版本提示及配套布局；选择是否应用工作台安排，再放入待应用选择，点击底部统一应用。
4. 插件选择有变化时，先保存页面／草稿，再保存配置并重载。新环境可用后自动接续布局；没有配置变化且插件运行正常时直接应用布局，保留运行实例。判定依据是仓库实际保存的配置，不只是相对勾选草稿的差异。
5. 套件原版只读，可「另存副本」。副本保留插件清单、说明和布局。保存或更新用户组合时可勾选「一并保存当前工作台安排」；更新时默认保留旧布局，也可明确取消保留。

「插件包 → 已登记的套件」可再次进入方案，或移除套件目录。移除只撤下原版方案，不卸载包、不停用插件、不删除用户副本、当前布局或仓库数据。插件本身仍在原有包管理区逐个卸载。

工作台预设管理器的「方案附带」列出已登记组合的配套布局，未启用插件也能预览。这里仅切布局，不负责启用插件；需要完整应用时走插件组合预览。

## 按方案新建仓库

启动首页提供新建、打开本地仓库、应用设置三个入口；近期仓库保留在左栏。点击「创建」后填写名称、位置与文件空间，通过「更换方案…」进入独立方案页，选择默认创建、套件原版或用户组合。方案的「应用配套工作台安排」可以单独取消。选择只预演，不创建目录、不运行插件；详情中可查看所需功能、依赖提示，并在多版本时选择已安装版本。

「安装套件…」定位到原有应用插件包页，仍需预览并确认安装。安装结果只有一份方案时定位该候选，多份方案可用结果里的「用此方案新建仓库 →」进入对应候选；安装本身不提交起始选择。「确认选择此方案」才把方案、版本及布局选项带回创建表单，直接返回会放弃本次候选调整。页面往返保留名称、位置、文件空间和已确认的方案。目录变化重新预检，未完成预检或存在阻塞问题时不能创建。窄窗口中的方案页暂时隐藏近期仓库，为目录与详情让出宽度。

点击「创建并打开」会重新核对方案修订、包集合和空间身份。默认创建使用发行默认且仍安装在本机的功能；显式方案只启用其选择、必需依赖和不可关闭的核心能力，不额外叠加所有默认插件。已有仓库或含其他文件的目标目录拒绝创建；请走「打开」，再在仓库设置中应用方案。

初始选择在核心第一次装配之前写入，目标插件直接参与首次启动。工作台安排沿用持久接续，不再先打开默认仓库然后重载。选择已有文件空间仍是独立的明确操作；已被其他库占用的独享空间在创建前拒绝，不自动转共享，也不自动收录空间文件。

### 失败时如何继续

- **预演／提交前检查失败**：修复缺包、版本歧义或空间选择，再创建；不留下新库。
- **目录已认领、初始化或插件启动失败**：首页显示可展开的「未完成的创建」，点击「继续创建」处理同一份仓库。重试使用已确认的插件版本和方案快照，不因套件更新暗中换方案。
- **先打开仓库**：暂缓本次方案的外部插件加载、空间关联和布局接续，保留已有数据与插件选择；进入仓库后可在功能与插件中重试启用。已完成的空间关联不会撤销。
- **取消接续**：只移除创建意图及本次尚未应用的布局意图，保留已创建目录、仓库、空间及应用里已安装的包。不是删除仓库。
- **工作台内容缺失或冲突**：仓库可正常打开，沿用「插件组合」里的布局重试／取消入口；不误报整个安排已完成。

应用本地的 `library-creations/` 保存未完成创建的固定任务 ID、预分配的仓库 ID、精确插件配置及可选空间／布局。目录内的临时 `.creation.json` 只用于认领同一创建任务；初始化成功时核心在原有 `meta` 表保存 `creation_initialized` 回执，防止重试覆盖后续插件选择。创建完成后撤下任务和临时标记。仓库身份与初始化标记同事务写入，空 SQLite 文件或配置事务中断可以接续；遇到不同身份的数据库、其他文件或不同认领标记时拒绝接管。

### 宿主接入

宿主开始页使用 `window.bridge.creation`，契约见 [library-creation.ts](../../src/shared/library-creation.ts)：

| 入口 | 行为 |
| --- | --- |
| `preview(preset?)` | 未打开仓库也可预演；返回插件选择、修订基线、问题及版本候选 |
| `create({parent,name,spaceRoot?,spaceId?,preset?,previewRevision?})` | 复核预演，认领新目录，启动并接续；选方案时必须提交预演基线 |
| `pending()` | 列出本机未完成创建 |
| `resume(id)` | 继续同一任务，不重复建库或覆盖其他仓库 |
| `openBasic(id)` | 保留已建库，暂缓方案并打开 |
| `dismiss(id)` | 取消接续，保留目录与数据 |

`PresetCatalog` 共用套件／用户方案目录及 `planPluginPreset`，初始化使用原有插件配置事务；主进程不自行写仓库数据库。界面只提交选择和调用这些操作，不维护另一套初始化流程。以上是宿主内部应用桥，未新增外部插件跨仓库能力，也未扩大 MCP 创建授权。原有 MCP 默认建库流程不变。

## 作者打包

先用既有 `plugin:pack` 生成独立 `.rmplugin`，再提供一份 JSON。插件源码、依赖和测试仍在各自独立工程；套件目录只装配发布物。

```json
{
  "formatVersion": 1,
  "id": "study-kit",
  "title": "学习工具试验套件",
  "version": "1.0.0",
  "description": "组合插件与工作台安排，不附带个人资料或凭据。",
  "packages": ["./packages/tags.rmplugin", "./packages/table.rmplugin"],
  "presets": [{
    "id": "organize",
    "title": "资料整理",
    "plugins": ["tags", "table", "text"]
  }]
}
```

`packages` 相对清单文件解析，也接受本机绝对输入路径；发布物只包含经过校验的插件字节和静态方案，不保留这些本机路径。`plugins` 为所需插件 ID，必需依赖由现有预演补齐；核心不可关闭能力不用写入。可在每份方案中加入 `description` 和 `layout`，布局使用 [工作台预设 API](工作台预设API.md) 的 `WorkbenchLayout`，包括内容入口和呈现描述。不要把完整 workspace、具体文档 ID、草稿、API Key 或业务配置塞进布局。

```sh
npm run suite:pack -- /path/to/suite.json /path/to/study-kit.rmsuite
```

工具自动填入包 ID、版本、SHA-256 摘要和方案中的推荐版本。套件每个插件最多带一个版本；方案可有多份，包也可为零（只分发基于现有能力的方案）。可直接试用 [基础整理示例](../../examples/suites/starter.json)：

```sh
npm run suite:pack -- examples/suites/starter.json artifacts/suites/starter.rmsuite
```

示例只启用宿主文字能力并安排「全部＋文件空间」对照页面，不承诺一套成熟业务场景。完整的多包流程由临时验证包覆盖。

## 身份、版本与安装语义

- 归档格式为 `RMSUITE1` 标识＋gzip JSON，包含清单和 base64 编码的 `.rmplugin`。不接受安装脚本、解压路径或运行时入口；安装不执行插件代码，启用仍走原有信任和装配流程。
- 单批源文件最多 50 个、合计 128 MiB；展开最多 50 个插件，每包沿用 16 MiB 上限。套件解压 JSON 限 192 MiB，内部包合计限 128 MiB；每个包及套件的摘要、身份、版本、路径、重复项都会核对。
- 方案 ID 为 `suite:<套件 ID>:<方案 ID>`，名称可修改而身份稳定；修订号为套件文件摘要。同内容重复安装复用；同 ID／同版本不同内容拒绝，作者必须升版；不自动降级。同批不能选择同一套件的两份文件。
- 套件与插件身份由各自 ID 决定。方案中的版本／摘要是推荐，具体确认的仓库选择与恢复任务才固定包摘要。用户本次显式选择优先，其次沿用仓库选择，再选已安装推荐包；推荐包不在时，唯一已安装候选可预选，多候选需手动选择。不按最大版本号猜测兼容性，接口／依赖／数据结构检查仍由原装配链承担。已有库方案预览直接选择使用版本；新建库共用解析规则。
- 安装逐项返回结果，不声称整套跨文件事务回滚。附带插件可以选推荐包、复用预览中的已安装包，或暂不安装。只有一个不同的已安装候选时默认复用，最终仍需确认；普通单插件安装的同版不同内容冲突规则不变。合法套件可先登记，缺包明确显示“插件待补齐”；已安装成功的包保留，失败项或目录登记可重试。重试保持暂不安装选择；确认使用预览字节，不重新读取被替换的源文件。
- 依赖未满足、插件代码不能加载或开发覆盖冲突，仍在仓库预演／装配阶段明确报告。安装成功不等于已经启用或完整方案已经生效。

## 作用域与恢复

| 内容 | 归属 |
|---|---|
| 独立插件包 | 本机应用原有插件目录 |
| 套件原版方案 | `userData/plugin-suites.json`，应用级只读来源 |
| 用户组合副本 | `userData/plugin-presets.json`，跨仓库复用 |
| 实际启停选择 | 当前仓库原有插件配置 |
| 实际工作台及草稿 | 本机当前仓库工作区存档 |
| 待完成创建 | `userData/library-creations/`，固定任务与仓库身份；目标目录有临时认领标记 |
| 待接续布局 | `userData/preset-applications/`，按路径和仓库身份绑定 |

应用有布局的方案时先持久化接续意图，再提交插件配置。重开仓库会核对目标选择和实际运行的插件；不匹配时保留记录并说明原因，不擅自改变选择。布局缺失工具、参数无效或实例规则冲突时，整份配套布局不提交，用户可在组合页重试或取消接续。取消不会回滚已经保存的插件选择。

布局成功后和草稿一起保存工作区及完成回执，再清除接续记录；在这两个动作之间退出，下次只确认完成，不再次覆盖用户后来的工作台。RPC 响应丢失时保留不确定的意图，重开核对实际配置。插件启停重载仍遵守原有生命周期，不承诺跨重载保留播放器／进程等运行实例。

## 接入与当前范围

应用安装桥的 `PackagePreview.suites` 返回每个套件状态及 `presets: { id, title }[]`。前端可据此定点进入预览，不需要启动插件才能发现方案。`PluginPresetService` 扩展见 [插件组合预设](插件组合预设.md)。宿主负责接续和完成回执，管理 UI 不自行拼接重载与布局落盘。

当前覆盖本地套件、已有仓库应用和开始页按方案新建。不实现联网市场、自动更新、套件联动卸载插件、单插件 manifest 静态方案、插件内部配置／密钥导出或业务数据初始化。后续界面可以替换，本批的静态清单、预演和应用规则保持独立。


## 套件更新与推荐版本（2026-11-15）

已登记套件的“更新套件…”选择同 ID 更高版本 `.rmsuite`；复用安装预览显示新增／移除的插件需求、推荐版本与布局变化。提交重新核对目录修订，拒绝过期确认。套件同版本不同内容仍不覆盖，不自动降级。

更新只改变应用方案目录，不修改已有仓库选择、布局和业务数据，不卸载被新版移除的插件。之后由用户预览应用；用户副本保持独立。已有原版的 `hash` 无需删除或改写，直接按推荐解释，因此视觉素材库 0.1.1 可继续使用，无需清库或重建方案。

方案目录中的推荐旧包不阻止插件更新；但未完成建库／布局接续任务仍使用确认时的具体包与布局快照，不能因目录更新换包。部分安装失败已成功的包和登记会保留；重启后重新添加套件可继续补齐，仍需确认，不自动重试已跳过的安装。安装结果“方案已登记”不等于依赖兼容、成功启用或布局已应用。

公共接口：`PluginPresetService.preview(id, mode, base?, versions?)` 可提交本次显式版本选择；`PluginPresetPreview.versions` 提供实际选择、推荐摘要与已安装候选。`PackageBridge.pick(suiteId?)` 定向更新、`install(token, choices?)` 确认套件成员的安装／复用／跳过。应用和任务恢复继续使用原接口，未扩展 MCP 权限、数据格式或复杂版本范围语言。
