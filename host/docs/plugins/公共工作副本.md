# 公共工作副本服务

2026-11-05。用于插件呈现本机“编辑中”状态、管理外部文件编辑。仓库与文件空间格式保持 v4；任务不是素材数据块，不随仓库导出。读取器继续使用本库已接纳版本。

## 两种接入

- 只需要“编辑文件”入口：声明 `file-working-copy-v1`，调用 `host.editFile(itemId)`。宿主负责创建／复用、选择编辑器及异常反馈。
- 要做自己的编辑管理界面：声明 `file-working-copy-service-v1`，使用 `host.fileEditing`。类型入口为 `@resource-manager/plugin-api/ui/file-editing`。旧宿主拒绝不认识的能力声明；不需要修改旧插件。

`host.editing` 仍是字符串共享草稿。插件内自行产生文件内容时，可以继续使用[公共文件编辑协议](公共文件编辑.md)的 `host.core.prepareFileEdit/commitFileEdit`；这里提供的是已有原件的本机工作副本生命周期，不是任意可写文件系统。

## API 与返回语义

| 方法 | 行为 |
| --- | --- |
| `list()` | 当前仓库的未完成任务快照，含错误和恢复阶段；不散列工作文件 |
| `onChanged(listener)` | 任务动作或本机编辑器配置改变后通知重新读取；返回解除订阅函数 |
| `chooseReplacement(id)` | 声明 `file-working-copy-ui-v1`；原生选择一个替换文件后创建副本，取消返回 null；不接收或返回任意路径 |
| `start({id})` | 从本库已接纳版本创建副本；同库同素材已有活动任务时复用，不打开应用 |
| `editorOptions(taskId)` | 已登记的编辑器 ID／名称、本库该格式偏好、能否使用系统关联及实际格式 |
| `chooseEditor()` | 原生应用选择器，用户选择后登记；取消返回 null，不启动程序 |
| `open(taskId, {editorId?, remember?})` | 打开已有工作副本；省略 ID 使用偏好，再回退到受限的系统关联 |
| `reveal(taskId)` | 在系统文件管理器显示副本；不返回可写路径 |
| `check({taskId, destination})` | 检查修改，必要时准备稳定快照；返回 `{task, unchanged}` |
| `commit(taskId, token)` | 确认当前准备；保存后保留工作副本，适用于继续编辑 |
| `discardPrepared(taskId)` | 放弃未发布的准备，保留工作副本；已发布的准备不能取消 |
| `finish({taskId, destination?})` | 检查、发布、接纳、清理；null 才表示完成，否则继续呈现任务 |
| `inspectEnd(taskId)` | 读取放弃前的确认 token、是否有变化及读取问题 |
| `discard(taskId, token)` | 用户明确确认后，放弃未提交修改并清理；不删除素材和已发布版本 |

`destination` 是 `{mode:'publish'}` 或 `{mode:'copy',spaceId}`，可选目标来自 `host.core.fileEditCapabilities(itemId)`。`finish` 省略目标时接续已有准备，否则默认发布当前文件。共享空间发布前应向用户说明影响；核心仍检查基线、权限和预览，不由按钮状态代替校验。

`phase` 区分 `editing / preparing / ready / saving / pending / cleanup / unadopted`。保存失败、迟到修改、接纳跳过都保留副本；`pending` 续接原接纳请求，`cleanup` 只续接清理，不能重新发布。`unadopted` 提示本库未接纳，不应自动强制覆盖。详细恢复语义见[受控文件编辑](../development/受控文件编辑.md)。

`task.canOpen` 仅表示可否使用**系统默认关联**，不是能否选择自定义编辑器。`format` 来自文件块的真实扩展名，不从可修改的显示标题推断。无扩展名为 `''`。预览使用 `host.url(task.prepared.reference)`，只读当前准备快照；没有工作副本的通用写入 URL。

## 使用示例

```ts
// 在用户点击“编辑”后执行；插件负责呈现错误，不以失败为由删除任务。
const task = await host.fileEditing.start({ id: itemId })
const options = await host.fileEditing.editorOptions(task.id)
if (options.preferred || options.systemAllowed) {
  await host.fileEditing.open(task.id)
} else {
  const editor = await host.fileEditing.chooseEditor()
  if (editor) await host.fileEditing.open(task.id, { editorId: editor.id })
}

// 用户已在外部保存并关闭、确认发布影响之后：
const retained = await host.fileEditing.finish({ taskId: task.id })
// retained === null 才移除管理界面中的该任务；否则展示恢复入口。
```

界面先订阅再读取，卸载时解除订阅；异步刷新使用请求序号忽略旧结果。通知是状态失效提示，不保证一次动作只发一条，也不监听外部编辑器的每次保存。页面焦点恢复可主动 `list()`；只有明确检查或完成时读取并散列工作文件。关闭插件界面／停用插件不结束任务，也不丢修改。

放弃必须先 `inspectEnd`，向用户说明未提交内容将丢失，再传该 token 调用 `discard`。期间工作副本又变化会拒绝旧确认。不要在 React 卸载、程序启动失败或请求超时时自动调用放弃。

## 编辑器与边界

本机应用设置登记编辑器；公共服务只返回 ID 和名称。插件不能通过此服务传任意程序路径、shell 字符串、启动参数或替换文件路径。`chooseReplacement` 只接受素材 ID，选文件、仓库有效性复核和替换校验由宿主完成。`editorId:'system'` 表示系统关联；只允许已有文档／媒体白名单。未知格式和无扩展名必须明确指定已登记编辑器，将文件作为输入交给它，不能直接执行素材。

`remember:true` 在成功打开后保存本机、当前仓库、实际扩展名的默认偏好。没有扩展名时禁止记忆，防止把所有此类文件归为一种格式。更换编辑器继续使用相同任务和字节；编辑器缺失会报错，不静默切换。应用设置移除编辑器登记时清除相关偏好，但不删除程序和工作副本。

MCP 继续使用既有文件编辑工具，不增加启动本机应用或接管这些任务的权限。当前不做多文件工程、外部自动保存监听、自动合并，也不据外部程序退出推断编辑完成。

## 管理界面的组合

列表、输入规则与卡片状态可复用[公共集合与页面输入](公共集合与页面输入.md)。工作副本服务提供动态素材 ID，集合不理解任务阶段；窗口共享订阅把编辑状态投影成角标。“文件编辑”现为独立外部包：提供编辑中页面、任务角标、详情分区、完成／放弃对话框及编辑器选择。宿主保留工作副本服务、本机编辑器登记和通用入口。任务存储与恢复保持在服务中，不能依赖标签页是否打开。

## 编辑入口交给可卸载界面

声明 `file-working-copy-ui-v1`，通过 `UiPlugin.fileEditingUis` 提供界面处理器。每项有唯一的 `插件ID.名称`、有限数字 `priority` 和 `open(request, host)`；当前窗口选优先级数字最小的一项，同值保持装配顺序。停用／卸载即不参与装配，不是运行时修改全局回调。

```ts
fileEditingUis: [{
  id: 'example.editing', priority: 100,
  async open({ id, intent = 'edit' }, host) {
    // intent: edit / choose-editor / replace
    // 自己组织界面，通过 host.fileEditing 操作任务；不要回调 host.editFile。
  }
}]
```

`host.editFile(id, {intent?})` 将请求送到该处理器，缺少处理器时提示启用且不创建任务。旧的单参数调用继续有效；可选 `intent` 需声明新能力。`choose-editor` 表示创建／复用后选择应用，`replace` 表示用户选择一个同格式替换文件；界面处理器收到请求后仍负责执行和反馈，宿主路由不会提前改文件。处理器内部再次调用 `host.editFile` 会递归，应使用服务方法。

实际交付插件 ID 为 `file-editing`，源码与产物在独立工程，使用说明随包工程 README 保存。基础构建不自动包含它；安装后按库勾选，或者在发行时通过 `RM_PLUGIN_BUNDLE` 选择附带。发行策略为新库默认启用，已有库保持显式启用规则；不增加暗中安装／启用的迁移。停用、卸载、重装不改变任务、文件版本或编辑器偏好。
