# 工作区布局与工具视图

2026-11-09。工作台按“区域 → 容器 → 内容视图”逐步整理。当前左、右侧栏支持纵向普通标签组和智能工具组，中央继续使用递归分割树；三处顶部对齐，常驻全局命令输入框已移除。导航与集合筛选已分开；智能工具可拖出固定绑定，明确声明停靠范围的普通／固定工具也可移入中央标签组，本轮结构改造到此收束；后续按实际界面和插件需要调整呈现，范围说明见[实施计划](../development/工作台区域与智能容器改造计划.md)。

2026-11-09 补充：容器作为可扩展层的语义约定见[容器与内容契约](../architecture/容器与内容契约.md)。该文区分目标契约与当前实现；宿主内部已收敛内容描述适配、现有放置解析、侧栏容器快照／动作、内部插槽登记及普通／智能容器的固定装配入口；工具新增 `tool-placement-v1`，内容无需声明容器即可由宿主安排默认分组。未新增容器、设置或 SDK 注册入口，旧声明已于 2026-11-10 退役，存档接续保留。

## 结构基线与可替换外观

2026-11-09 用户确认：保持“区域 → 布局容器 → 内容视图”的职责、身份和操作语义，当前外观不定稿。两侧可将文字标签换成图标入口，智能组可重做标题、来源指示、候选切换和空状态；内容内的目录、列表、播放器、聊天等结构仍由各内容负责。

| 层次 | 当前承担的规则 | 可以继续调整的表现 |
| --- | --- | --- |
| 区域 | 左／中／右的可用空间、开合、尺寸和承载范围；中央维护操作焦点 | 分段顶部、边框、间距、开关图标、宽度呈现 |
| 普通容器 | 保存一组内容实例的顺序、当前项及位置，按用户选择切换 | 文字标签、紧凑图标、切换菜单；每组当前只呈现一个内容 |
| 智能容器 | 跟随中央主页面，按能力确定候选、按页面类型记忆组合；无适用目标保持占位 | 工具选择器、来源标识、配置入口和占位画面 |
| 内容实例 | 页面或工具的稳定身份、状态、数据来源及生命周期；固定工具保留来源页绑定 | 业务界面和内部布局；适配区域大小，不依赖外壳 DOM |
| 常用操作栏 | 有限固定入口和插件显式贡献的窗口命令 | 图标、提示、间距；不承担容器当前项或工具位置索引 |

存档中的普通组 `type: 'tabs'`表示“组内选择一个内容”的行为，**不要求绘制文字标签**。换成图标时保留稳定 ID、可访问名称、键盘选择、当前位置和拖动语义即可，不必改插件声明或本机布局格式。智能组 `type: 'context'` 描述跟随规则，不规定它必须长成当前样子。

2026-11-10：单项和多项容器保持同一种切换项样式，不因数量自动变成另一种标题外观。侧栏普通组和智能组采用统一紧凑头部：当前工具显示图标与名称，其他工具只显示图标；完整名称保留在提示和菜单中，无图标的工具用名称首字兜底。窄栏通过“更多工具”切换隐藏项，左右方向键及 Home／End 仍可到达全部工具。抓手拖动整组，工具图标拖动单项；关闭、排序和配置在右键或组菜单中。智能组保留头部跟随指示并可点击定位；普通组不额外显示固定工具的来源按钮，来源保留在工具提示中，右键或组菜单的当前工具操作可定位来源页；无适用工具保留“页面工具”和原空状态。正文不再叠加容器标题、来源栏和切换栏。中央标签外观和固定来源条保持，插件无需为此改代码。

如果要从“一组显示一个内容”改为“多个内容同时展开”，或让普通组自动跟随焦点，则涉及可见性、实例与容器行为，需要单独推演；不能仅换 CSS 后继续按旧规则管理状态。当前没有开放任意第三方容器渲染器，也没有把所有页面和工具统一成可放任意区域的一种类型。

## 工作台 API 索引

外部插件从 `@resource-manager/plugin-api/ui/contracts` 导入下面的主体类型；上下文、命令与预设另有 `ui/page-context`、`ui/commands`、`ui/workbench-presets` 专题入口。`uiFeatures` 声明仅按实际使用加入，不要求为换图标升级所有插件。

| 接入目的 | 声明／调用 | 能力标记和当前边界 |
| --- | --- | --- |
| 新增中央内容页面 | `UiPlugin.tabTypes`、`TabType`、`TabProps`；`host.openTab` | 页面仍在中央；`key` 是身份键，`instances` 需 `page-instances-v1`，`beforeLeave` 需 `page-lifecycle-v1`；不由标签外观决定 |
| 新增普通工具与初始放置建议 | `UiPlugin.toolViews`、`ToolViewContribution.placement.default?` | `tool-placement-v1`。无需声明容器；宿主生成默认分组，用户已有位置优先 |
| 声明工具可放哪些区域 | `ToolViewContribution.placement.regions` | 使用 `tool-placement-v1`。普通／固定工具可明确加入 `center`；省略仍只允许两侧 |
| 页面提供伴随工具所需能力 | `TabProps.expose({ context })`、`PageContextSource` | `context-tools-v1`。只报告标题和具名运行时能力，宿主不猜 PDF／歌词等业务数据 |
| 工具按上下文成为候选 | `toolViews.context.requires`、`defaultVisible`；`ToolViewProps.context` | `context-tools-v1`。按能力匹配，页面类型仅用于组合记忆；`PageContext.isAvailable()` 检查来源，异步动作不改投当前页 |
| 允许从智能组拖出固定工具 | `context.detachable.maxInstances` | `bound-context-tools-v1`。新增独立实例，智能入口保留；同工具／来源页复用，关闭目标不改绑。实际拖出由宿主交互执行 |
| 打开或定位工具 | `host.showView(toolId)` | 普通工具定位实际位置；上下文工具定位智能组候选，`host.context` 打开智能组。不是任意重排或创建固定实例的 API |
| 打开内容及指定中央位置 | `host.open / openData / openTab` 的 `OpenOptions` | `group` 需 `open-target-v1`，`instance` 需 `page-instances-v1`，打开器选择需 `open-with-v1`；打开方式与位置分开 |
| 管理页面的显示、操作和存档 | `TabProps.active / visible / saved / setState / setFocus / expose` | 页面 `visible` 需 `editor-groups-v1`，活动页与可见页不同；`ToolViewProps.active` 表示该工具当前呈现，多个组可同时为 true，不能当作唯一键盘焦点 |
| 管理结束与长期运行 | `TabType.beforeLeave`、`host.editing`、`windowProviders`、本机服务 | 分别见 `page-lifecycle-v1 / shared-editing-v1 / window-surfaces-v1` 及本机服务契约；隐藏不等于关闭，移动不结束业务，任意 React 局部状态不自动保存 |
| 设置与常用动作入口 | `settingsSections`、`host.openSettings`；`commands`、`quickAction`、`host.commands` | `settings-navigation-v1 / ui-commands-v1 / quick-actions-v1`。界面外壳可改，保存与命令语义继续走原服务 |
| 布局预设 | `workbenchPresets / workbenchPresetUis`、`host.workbenchPresets` | `workbench-presets-v1`。本机结构预设，不复制业务数据、运行时能力或固定来源页；切换保留当前真实实例 |

具体签名与例子见后续章节，以及[页面生命周期](页面生命周期.md)、[设置与命令](设置与命令接入.md)、[工作台预设 API](工作台预设API.md)、[共享编辑](共享编辑会话.md)。可打包的结构验证在 [tool-views](../../examples/tool-views/README.md)，业务插件根据实际需要逐步接入。

### 宿主内部与插件公开接口的分界

插件声明“提供什么、需要什么、可放哪里”，宿主掌握实际位置与实例管理。当前**没有公开**创建任意区域、修改分割树、直接拖出固定实例、注册新容器渲染器或写整个工作区 JSON 的通用 SDK。用户通过宿主拖放／菜单调整；程序化套用已支持的结构使用预设服务。插件不能导入以下私有模块。

| 宿主维护入口 | 所有权与用途 |
| --- | --- |
| `app/workspace.ts`、`workspace.ts` | 唯一工作区状态与打开／关闭／移动动作、恢复；画面调用这些动作，不复制一份可写布局 |
| `shared/tool-placement.ts` | 校验并归一新旧工具声明、生成默认分组；默认位置不是实际位置，不写用户布局 |
| `workbench-content.ts` | 将既有页面／工具声明适配为内部内容描述：实例与类型 ID、标题、允许区域、默认位置及固定来源；保留原组件引用，不存实际位置 |
| `workbench-placement.ts` | 工具来源与目标解析；菜单、拖放预览与提交共用区域／分组／空间检查。失败不创建绑定；DOM 命中和尺寸测量仍在画面／控制器 |
| `workbench-containers.ts` | 分开投影外壳只读快照与宿主实例记录；外壳拿到名称、图标、成员／候选和来源摘要，正文组件与运行时能力只交承载层 |
| `container-actions.ts`、`app/container-actions.ts` | 关闭、排序、尺寸、恢复和智能组合的宿主动作；提交时校验最新状态，外壳不能再传任意布局变换函数 |
| `editor-layout.ts`、`sidebar-layout.ts`、`tool-docking.ts` | 中央分割树、两侧容器与跨区位置转移；页面打开共用目标解析。通过一次工作区更新转移位置，预览不提前落盘 |
| `sidebar-catalog.ts`、`page-context.ts`、`context-tools.ts` | 声明目录、来源页能力与候选／固定关系；能力对象只在内存，不写入布局 |
| `SidebarWorkspace`、`EditorWorkspace` | 区域布局与交互接线；侧栏通过内部定义装配头部／正文，中央分割树保持原实现 |
| `components/SidebarContainers.tsx`、`SidebarToolStrip` | 内置普通／智能容器的区域、来源与呈现定义；外壳只读快照、发出动作并安排插槽，不拥有工具正文实例 |
| `surface-slots.tsx` | 按工作区隔离的显式插槽登记；按中央组／侧栏组／智能组正文身份定位，节点撤下或替换时通知承载者，缺位使用隐藏停放区 |
| `ToolViewSurfaces`、`ContextToolSurfaces`、`RetainedSurface` | 宿主持有普通／固定与智能工具实例，通过插槽身份安放；外壳重挂不改变实例身份，智能组关闭可停放已访问工具；固定实例关闭仍按原协议释放。中央页面保留自己的生命周期 |
| `shared/sidebar-layout.ts`、`shared/workbench-layout.ts` | 本机布局的校验、读取接续与预设结构；属于存档约定，不是插件自由写入的接口 |

上述 renderer 文件均在 `src/renderer/src/`（组件在其 `components/`）；持久布局只存 ID、顺序、比例、选择和绑定等可恢复信息。仓库身份与数据块、文件空间版本、共享编辑草稿和插件持久业务数据各走自己的接口。

后续替换外壳时复核：同实例仍只有一份组件；切换／隐藏／移动／关闭保持原含义；工具显示状态与中央焦点分开；固定来源不漂移；存档可接续；图标入口保留可读名称、键盘路径和足够大的拖动落点。后续新容器行为由具体场景推动，不为整理 API 增加空抽象层。

## 用户操作

- 最左是常用操作快捷栏：全部视图、新建文字、导入文件和命令面板；新建与导入面向当前仓库，不继承中央视图条件。插件可通过显式 UI 命令补充少量入口，普通工具不再自动出现在栏中，见[设置与命令接入](设置与命令接入.md#常用操作快捷栏quick-actions-v1)。
- 每个普通标签组只显示一个工具；两侧都能上下放多组，同时展示不同工具。点击标签切换本组内容，其他组保持。标签左右键、Home／End 可以切换。
- 拖动工具标签到组的正文上部／下部：在目标组上方／下方独立放置；中部或标签栏：加入该组；标签栏内按鼠标位置排序。正文上下各约 30% 为分组命中区，显示半组预览，不再要求瞄准边缘细线；空侧栏整体接纳。两侧只上下排列，不在侧栏里左右嵌套分割。
- 拖动组标题的 `···` 按钮可以整组移动或合并；顶部其余可拖动空白留给窗口。拖放预览不提前重排，Esc 或松到无效位置保持原布局；空间不足和对自身的无意义拆分在预览中说明。工具右键提供独立放置、加入其他组、标签前后移、默认位置与关闭；组右上菜单提供整组移动、上下排序、关闭及添加工具。
- 标签关闭保留工具位置和本窗口已有实例，可从组菜单、命令面板或 `host.showView` 重新打开；普通侧栏工具原位重开，中央普通工具关闭后回默认侧栏待重开，不复制实例。关闭最后一个可见工具后该组暂不显示；真正移空的组移除。首次加载的插件默认组在该侧已有内容时不会自动挤进画面。
- 组间分隔线调整高度，支持方向键、双击／Home 均分；侧栏外缘调整总宽。新增独立组受最小高度约束，窗口缩小时保留已有组并允许滚动。
- 左右展开时各自顶部放收起按钮；收起后展开按钮出现在中央顶部对应外缘，多分屏只出现一份。侧栏开关不改变中央操作页。中央与侧栏顶部的空标签栏、固定留白和最上缘可用于拖窗，真实标签和按钮排除在外；布局拖动期间临时关闭对应原生拖窗区，避免两种拖动争用。
- 命令面板用 `Cmd+P / Ctrl+P`、左侧快捷栏顶部或「显示 → 命令面板…」打开。左下还保留仓库切换、布局、设置和运行状态。布局菜单内可管理预设，或通过「侧栏显示与位置…」打开工具、恢复默认侧栏；恢复默认不重置中央内容与素材数据。

侧栏布局按仓库 ID 保存到应用本机工作区，不是仓库数据块。未知／停用工具的位置保留，画面仅显示可用内容；重新启用后沿用位置、比例与关闭状态。恢复全部默认布局是明确重置，会丢弃包含未知工具在内的自定义排布。布局预设的切换与返回规则见[工作台布局预设](../architecture/工作台布局预设.md)。

## 插件声明

新插件在 `plugin.json` 声明 `uiFeatures: ["tool-placement-v1"]`。无需 `viewContainers` 或 `container`。旧宿主拒绝未知能力标记，避免把新声明按旧规则误读；当前宿主在装配时校验贡献和默认建议，失败按插件错误流程报告。仓库与本机布局格式不变。

```tsx
import type { UiPlugin } from '@resource-manager/plugin-api/ui/contracts'

export const plugin: UiPlugin = {
  id: 'reader-tools',
  toolViews: [{
    id: 'reader-tools.outline', title: '目录', order: 10,
    placement: { regions: ['left', 'right'], default: { region: 'left' } },
    Component: Outline
  }]
}
```

- 基本内容声明为 `id / title / order / Icon? / Component / needs?`，ID 以本插件 ID 加点为前缀。
- `placement.regions` 是允许放置的范围；省略整个 `placement` 时为左右侧栏。默认侧栏优先右侧，仅允许左侧时选左侧。普通工具本批仍须允许至少一个侧栏区域，初始放置不支持中央。
- `placement.default` 是普通工具的初始建议，`region` 必须在允许范围内。不填写 `group`，宿主按工具身份生成稳定独立组；内部生成 ID 不属于插件要引用的公共约定。
- 要让几个工具初次放到一组，使用同一个 `default: { region: 'right', group: 'reader-tools.reading' }`。组 ID 使用本插件命名空间，宿主从首个声明补齐标题与顺序，不要求另写 `viewContainers`。同组默认区域必须一致；工具自身提供标题／图标，默认组不另行注册。
- 也可建议加入 `host.navigation`（左）或 `host.inspector`（右），必须声明对应 `region`；这只是初始组合，不是依赖某个容器类型。不能默认加入其他插件私有组或智能组。
- 智能工具凭 `context` 进入候选，不填写 `placement.default`；其独立实例由拖出动作安排，允许范围仍由 `regions` 定义。
- 用户已有位置、关闭状态、比例与未知工具记录优先。改变默认声明不会移动现有工具；明确恢复默认才使用新建议。首次接入时该侧已有内容，新独立工具默认关闭，从菜单／命令或 `host.showView(id)` 打开，不挤开当前界面。
- 可选协作的 `needs` 放在工具上；不可用时不显示入口，不丢失已保存位置。`host.showView(id)` 定位实际位置，不强制搬回默认侧栏。

可打包示例见 [examples/tool-views](../../examples/tool-views/README.md)：普通草稿不指定分组，阅读工具只声明上下文和允许区域；示例全部使用当前契约，旧存档接续另有回归。

### 退役接口与升级（2026-11-10）

当前宿主只接收 `toolViews`＋`tool-placement-v1`。已移除 `sidePanels`、`viewContainers`、`toolViews.container`、`placement.container`、`windowWidgets` 和 `host.showPanel`，不再自动转换旧声明。

- 原 `sidePanels` 转成 `toolViews`，保留工具 ID；用 `placement.default.region` 建议初始区域。原来以面板 ID 作为组 ID 的，可把它填入 `default.group`。
- 原 `viewContainers` 不再单独注册；同组工具填写相同的 `placement.default: { region, group }`。内容标题和图标仍在工具声明中。
- 智能工具移除旧容器字段，仅声明 `context`、允许区域及独立实例上限；不填写 `default`。
- `host.showPanel(side, id)` 改为 `host.showView(id)`，服从用户保存的位置。底部部件移到工具正文；`windowProviders` 继续负责跨页面常驻服务。
- 删除 `view-containers-v1`／`tool-docking-v1` 能力标记，加入 `tool-placement-v1`。上下文和固定工具仍分别声明 `context-tools-v1`／`bound-context-tools-v1`。

旧包加载时明确提示接口退役并按既有插件失败流程恢复仓库，不能静默丢弃侧栏。退役能力字符串仅保留在安装／仓库元信息解析中，方便查看、替换和卸载旧包；打包器与加载器都拒绝继续使用。公共示例已迁移。当前重点保障标签、字段、表格；音乐、番茄钟、EPUB、AI 对话、操作历史侧栏保留独立源码，暂不适配或随当前源码套件交付。

保留工具 ID 就能接续原位置、关闭状态、比例和未知成员；新默认只影响首次出现或显式恢复默认。布局读取、备份、素材数据及未完成任务恢复不随接口退役删除。

## 工具跨区域停靠

新写法在 `plugin.json` 声明 `tool-placement-v1`，工具的 `regions` 加入 `center` 即可。下例为可拖出的智能工具，还需 `context-tools-v1`、`bound-context-tools-v1`：

```tsx
{
  id: 'reader-tools.outline', title: '目录', order: 10,
  placement: { regions: ['left', 'center', 'right'] },
  context: { requires: ['reader-tools.document'], detachable: { maxInstances: 2 } },
  Component: Outline
}
```

普通工具省略 `context` 即可。未声明范围仍仅左右两侧。各区域沿用宿主的最小尺寸；智能入口的所在组不受该位置声明控制，拖出后的固定实例才按 `placement` 停靠。

- 将工具标签拖到中央正文中部／标签栏，加入现有标签组；拖到四边，沿用分割树新建区域。中央工具标签也能拖回侧栏的普通组或上下独立组。右键提供相同的移入／移出入口；不支持的区域在拖放预览中说明原因。
- 从智能组直接拖到中央，创建或复用固定实例，原智能入口仍在。同一工具＋来源页面不会因区域不同而另开一份。整个普通组／智能组仍只在两侧移动，本批跨中央以具体工具为单位。
- 工具实例由一个稳定的 `ToolViewSurfaces` 持有；区域通过宿主内部 `SurfaceSlot` 显式登记 DOM 插槽。移到中央不变成插件的 `tabType`，不触发页面结束回调，不创建第二份组件／服务。草稿、组件身份及有效范围内的滚动在同窗口移动时保持。
- 点击中央工具会获得中央操作焦点，但不提供 `PageContext`；智能组显示无适用工具，不回找旧页面或跟随自身。固定工具的 `context` 和 `host` 仍指向原页面；普通工具继续使用自身原有的上下文机制。
- 中央工具不接收以当前页为目标的宿主素材导入、粘贴或新建；组件内输入照常处理。最左快捷栏及命令面板明确标为「当前仓库」的新建／导入仍可执行，不将中央工具作为收录目标。
- 中央普通工具关闭后保持本窗口实例，回默认侧栏待重开；固定工具关闭则释放该实例和绑定。移走中央组的最后一个工具会清理空组，整个中央为空时保留「开始」页。
- 重启恢复区域位置、固定身份与原页面已经保存的状态，不承诺恢复任意 React 临时输入。插件缺失或撤回中央适配时保留中央占位，可移回侧栏或关闭。
- 应用／返回布局预设时，中央工具随当前真实标签保留，避免侧栏又补出同工具。命名预设本批只保存分区布局，不携带中央工具清单或固定页面身份，也不会按预设新建工具；重启使用的完整工作区会保存它们。

内置导航、固定集合筛选已声明三个区域。普通详情继续保留侧栏范围，避免把“选中项伴随”贸然当作独立内容页。公共示例 1.10.0 的草稿和固定阅读工具可用于跨区验证；其他插件逐个声明和验收。

## 生命周期与边界

视图 `Component({ host, active })` 在首次显示后挂载，之后切换标签、关闭工具和跨组／跨侧移动保留 React 实例。`active=false` 包括整个侧栏收起、工具已关闭或本组正在显示另一标签；停止不必要的滚动、高频绘制，但不据此停止后台工作。普通组不会随中央焦点自动切换工具，多个组可以同时有活动内容。

宿主使用稳定 Portal 容器，在 DOM 搬动前读取滚动位置，重新安放后恢复到当前可滚动范围。每个普通工具只有一个实例，不在多个位置复制。普通侧栏按键不会冒泡为中央页面快捷键；应用级快捷键仍保持现有规则。

- 草稿、控件状态和滚动：同一窗口内移动保留。应用重载后的恢复由插件自己的状态存档负责，宿主不会序列化任意 React 状态。
- 播放、流式请求等持续运行：继续使用 `windowProviders` 或已有服务能力，不能绑定在首次展开才挂载的视图上。
- 详情内部 `sections / blockSections` 仍由详情面板组织，不自动升级为可停靠视图。
- 普通工具的上下文由插件负责：详情跟随选中素材，歌词跟随播放歌曲。智能工具由主页面能力驱动，见下节；位置变化不改变上下文来源。
- 窄侧栏和同组高度可调，插件不能假定固定宽高。隐藏或移动有 iframe、原生媒体、第三方编辑器等特殊状态的业务视图，仍须按实际插件验收。

## 智能工具与主页面上下文

首批默认左侧「导航」＋「当前页面工具」，右侧详情保持。导航只负责打开预设／保存视图；格式、标签等分面在智能组的「筛选」里，只操作上方显示的来源页面。侧栏、命令面板和设置浮层不改变中央来源。无适用工具时保留原分区并显示占位，不自动寻找别的集合或打开新页。

智能组的齿轮菜单按页面类型选择显示工具；工具标签右键可调整顺序／隐藏，类型间切换记住组合和选择。关闭整组后可用命令面板的「打开当前页面工具」或底部布局与工具菜单重开。普通组菜单可新增智能组，智能组也可整组上下／跨侧移动；它的中部不接纳普通工具拖入。智能组最低 190px，新增或拖入分组时检查可用高度；窗口缩小仍可滚动。直接拖动「当前页面工具」标题即可移动整组，也保留菜单操作。整组拖动时目标面板的整个上／下半区均是放置区域；不再用中部无效区要求用户精确瞄准。顶部其余留白继续用于拖窗口。

插件声明 `uiFeatures: ["tool-placement-v1", "context-tools-v1"]`：

```tsx
import type { UiPlugin, ToolViewProps } from '@resource-manager/plugin-api/ui/contracts'

function Outline({ context, active }: ToolViewProps) {
  // reader.outline 的数据及方法由页面提供者与工具约定。
  // 异步操作捕获 context，完成前检查 context.isAvailable()，不能改用全局当前页。
  if (!active || !context) return null
  return <div>{context.title}</div>
}
export const plugin: UiPlugin = {
  id: 'reader',
  toolViews: [{
    id: 'reader.outline', title: '目录', order: 10,
    context: { requires: ['reader.outline'], defaultVisible: true },
    Component: Outline
  }]
}
```

主页面通过既有 `expose` 报告：

```ts
expose({ context: { title: '当前文档', capabilities: { 'reader.outline': outlineApi } } })
```

- `requires` 中全部能力有效才进入候选；页面类型仅用于组合记忆，不能用名称猜能力。能力 ID 使用命名空间，结构／方法由协作双方约定；宿主不代插件实现业务。
- `context` 包含 `pageId / type / title / selection / capabilities / isAvailable()`。选择带来源，页面宿主也绑定来源；两份同名集合不会混用临时筛选。能力对象仅驻留内存，绝不写入布局。
- 已有集合的 `facetQuery + toggleFilter` 自动适配为 `collection.filter`，类型 `CollectionFilterCapability`。调用时按来源 ID 读取最新 API，目标关闭后不操作；分面查询继续保留基础规则和兄弟标签。右侧打标仍使用全库词汇。
- 声明 `context` 的工具只作为智能候选，不自动加入其旧普通容器。`host.showView(toolId)` 在当前页面适用时定位智能组并选中它；不适用只提示。`host.showView('host.context')` 打开智能组。
- 工具按「容器＋页面实例＋工具 ID」隔离 React 局部状态，第一次真正显示才挂载。`active=false` 必须停止不必要绘制／查询；长期服务仍放窗口 provider。当前首批面向读取和直接动作，复杂编辑必须继续使用业务草稿及离开协调，不能把保活当作保存。
- 来源页面关闭／被工作区缓存冻结、能力撤下、插件重载时可释放该工具实例；任意 React 局部状态不保证重启恢复。界面组合与位置会保存，业务持久数据由插件负责。
- 侧栏首版不复制旧普通工具；注册上下文工具表示支持上述按来源隔离的实例。多个智能组也互不共用输入草稿；共享数据／服务仍由原业务接口负责。

可打包示例 [tool-views](../../examples/tool-views/README.md) 提供集合概况、延迟筛选验证、阅读能力及两个候选工具，不伪造 PDF 目录业务。

### 固定工具实例（bound-context-tools-v1）

支持独立放置的工具标签可以拖到普通组中部／标签栏加入该组，或拖到上／下区域独立成组。右键也有「固定到左／右侧栏」。这是额外创建实例，智能组原入口、组合和局部状态保持。固定后显示来源名称，可以点击定位原页面；中央切换不会改变其目标。固定实例和普通工具一样可排序、拆组和跨侧移动。

插件在原 `context` 声明中增加 `detachable: { maxInstances: 2 }`，同时声明 `bound-context-tools-v1`。未声明的旧工具不能拖出；内置集合筛选已接入。该上限是每窗口、每工具的固定实例数（1～16），不含智能组实例。同工具＋同来源页面重复拖出或菜单固定会复用并移动已有实例，不重复创建。拖动取消、能力失效、超限和落点失效均不创建半成品。

固定的是**页面实例**，不按素材标题或页面类型匹配。原页面内部导航／筛选仍以该页面当前状态为准；换到不同页面类型则不可用。关闭目标后保留「目标页面已关闭」占位，后续打开同名／同类型页面不会改绑。插件缺失、撤下能力、撤回独立声明也各自显示原因；记录保留。关闭固定工具会释放该实例和临时输入，业务数据仍由插件保存，不把临时输入当作持久草稿。

固定工具沿用 `ToolViewProps.context` 和按来源绑定的 host，无需另写一个渲染器。数据和操作可以由原页面服务共享，临时控件状态按实例独立；拖出不复制智能工具的 React 草稿；长期播放等工作应复用窗口服务，不能随固定视图另开服务。复杂编辑仍需接入已有业务草稿及离开策略。

有固定工具引用的来源页在本窗口保活，以便后台也能提供能力；固定工具隐藏时仍须遵守 `active=false` 的查询／绘制暂停规则。固定数量有上限，但多开复杂阅读器仍有资源成本。重启后只恢复布局、绑定和页面自身已保存状态，任意工具局部状态不保证恢复。

### 布局 v4 接续

v2 读取时保留普通组、隐藏项、未知工具和选择，在原导航之后按原侧加入智能组；导航原来隐藏时智能组也保持关闭。原导航权重按 60%／40% 分配，其他组不重排。没有导航的自定义旧预设不凭空加组。v3／v4 重载不再次添加，也不覆盖用户后来关闭的组。

升级前的 v3 原侧栏保存在 `sidebarBackupV3`，v2 的 `sidebarBackupV2` 和更早的 `sidebarBackup` 保持。预设首次改写前保留 `:before-sidebars-v4` 目录备份，写备份失败不覆盖原目录。智能组存 `type: context / closed / contexts`；`contexts` 只含按页面类型保存的工具 ID 顺序与当前工具，未知／暂缺插件配置保留。未配置时采用当时适用工具的默认建议；用户配置后按明确组合显示，新插件不擅自加入该组合。

v4 的 `bindings` 保存独立实例 ID、工具 ID、来源页面 ID／类型及显示标题。只在本机工作区保存，不涉及仓库／文件空间格式。布局预设过滤这些具体绑定和仅含固定工具的组；应用／返回预设时保留当前真实固定实例，不用预设重建来源或恢复已关闭工具。用户明确重置整个侧栏会移除侧栏中的固定实例；中央实例不受侧栏重置影响。绑定身份独立于位置，中央位置通过工作区的 `workspace.tool` 标签引用，不在两处重复保存位置。

## 现有插件接续

业务插件按实际使用逐步迁移；未适配旧接口的包暂不加载，已有数据和布局记录保留。升级规则见上面的“退役接口与升级”。

工作区 `sidebars` 当前为 v4。普通组延续 v2：每组含 `type: tabs`、工具成员和当前标签；`hidden` 保存关闭的工具，`weights` 按组记录高度，`selected` 仅表示最近操作组，不再控制其余组显隐。中央分割树、宽度偏好、页面与草稿不变。

v1 只在读取边界转换：原选中容器内同时展开的工具各成为一个纵向组；折叠工具留在首组且关闭，原后台容器保留归属但不展开。未启用／未知 ID 也保留。原侧栏存档保存在工作区 `sidebarBackup`，与转换后状态同次落盘；旧预设目录在首次改写前另存一份备份，失败不覆盖原目录。未知侧栏版本阻止载入并提示，不用默认值覆盖。

更早的 `docks` 只在没有侧栏布局时用于默认选择。新工具使用 `tool-placement-v1`；旧插件声明转换已移除，不保留第二套渲染器。智能工具及固定实例仍有独立能力声明，用户移动结果优先。

## 中央标签组与分屏

- 每个区域头部只保留 `···` 管理入口；精确分屏以拖动标签到四边为主。菜单提供向右／向下分屏，空间不足时省略对应选项。
- 单区域只列分屏；双区域再提供「均分大小」「合并为一个区域」；三个及以上提供「均分大小」「合并当前区域…」「合并全部区域」。合并当前区域先选动作、再选目标，不在第一层平铺所有区域。合并保留标签、实例和局部状态。
- 标签右键只有一个移动入口：只有另一个区域时直接移动，多个目标时通过「移动到其他区域…」选择。显式新建独立视图继续是另一个动作，不把移动改成复制。
- 标签图标、加号、区域菜单和中央顶部的侧栏开关使用相同图标尺寸与视觉中心；点击范围独立保留。窗口顶部留白仍可拖窗，样式不改变分割树与实例规则。
- 每个新区域都能继续分割，可形成左大右上下、四格等混合布局。最小区域为 260×180 CSS 像素；空间不足会提示，不新建区域。不硬限两组；窗口缩小时保持最小尺寸并滚动中央画布，不丢弃已有布局。
- 点击分屏产生轻量「开始」页，可打开素材列表或接收标签；不自动复制插件实例。拖标签到目标区域四边显示半区预览，松开后局部分割并移入；拖到中间加入已有组，拖到标签前调整顺序。只有同一仓库会话的标签拖动进入布局流程，文件拖入仍走原导入流程。
- 自己区域只有一页时向自身边缘拖动没有分割意义，预览会说明；按 Escape 取消；拖到应用窗口外松手则移入新窗口。拖放不是唯一入口，标签右键可按区域编号移动，区域菜单可按方向分割和合并。
- 合并将源区域的全部标签移入目标，不关闭内容。最后一页关闭／移走时收起空区域，邻接的分割树分支随之折叠。合并全部仍保留所有标签。
- 每组独立选择当前页；点击页面或标签转移唯一操作焦点，详情、选区菜单与快捷键随之变化，其他组仍可见。
- 分隔线调节所在分支比例，支持方向键、Home／双击均分；范围根据两侧子树的最小尺寸计算，不能把下层区域挤扁。显式均分全部作用于每个分割节点，不强制所有末端区域面积一致。
- `CmdOrCtrl+数字` 和切换前后标签作用于操作焦点所在组。每组加号在本组新建「全部」。
- `Workspace.editors` v2 保存分割树、各组标签与当前页、分隔比例及组访问顺序。原 v1 两组配置在读取时转换并保持方向、比例和页面状态；运行时没有第二套旧模型。坏配置去重并补回遗漏页面；深度／节点读取保护只针对损坏存档。仓库／文件空间数据格式不变。


### 页面插件接入

`TabProps.active` 仍表示唯一操作页，继续用于键盘、选区与操作注册；新增 `visible` 表示该组当前显示的页。可见页面的滚动定位、尺寸测量和绘制应使用 `visible`，不能因另一组获得焦点而停止。依赖此字段的插件声明 `uiFeatures: ["editor-groups-v1"]`，避免被旧宿主误加载。

页面收到的 `host.open / openTab / openData / toggleFilter` 绑定页面来源，异步处理期间换组不把打开结果或筛选送到另一组；原页面被关闭后新页回退到当前组。侧栏／窗口贡献仍面向当前操作页。`TabType.key` 表示内容身份；普通打开继续复用已有页，显式指定位置时移动已有页面。声明 `instances` 的类型另可显式新建独立视图，见下节。

跨组移动复用同一 React 实例并恢复滚动；所有区域的可见页都保活，后台页仍受近期访问缓存限制。重载后的恢复仍使用 `saved / setState`，不是序列化任意组件状态。持续播放或流式会话继续放在窗口 provider／服务中。

内置集合与 PDF 已按可见性调整；其他插件不要求一次全部迁入。使用 `active` 同时控制绘制和快捷键的旧页面需要拆开这两个用途，窄分屏、iframe 和第三方编辑器仍按实际接入检查。示例包含两个可移动的草稿页面，演示焦点、可见性与重启存档。

### 页面结束与恢复

公共 `TabType.beforeLeave` 已接通关闭、内容切换、重载和正常退出；暂时卸载不结束使用。PDF 首先接入，优先本机页面位置，结束时写回阅读进度。完整契约及未接入插件的边界见[页面生命周期](页面生命周期.md)。

### 指定打开位置

依赖此能力的插件声明 `uiFeatures: ["open-target-v1"]`。`OpenOptions` 从 `@resource-manager/plugin-api/ui/contracts` 导入；三个打开入口都接受可选 `{ group: 'current' | 'other' }`：

```ts
host.open(assetId, from, { group: 'other' }) // 保留列表来源，用素材的打开器
host.openData(assetId, { group: 'other' }) // 通用数据详情
host.openTab('my-plugin.reader', { id: assetId }, { group: 'current' })
```

- 省略选项：保持原行为，新页进入来源组，相同身份页在原位置获得焦点。
- `current`：明确放在来源组，命中其他组的同身份页时移过来。
- `other`：选择最近使用的非来源组。菜单或异步打开开始时捕获目标，等待期间焦点变化不改目标；目标已关闭时再按现有组回退。没有其他组时在来源右侧建立区域并直接放入内容，空间不足提示而不改布局。唯一旧页移走时来源保留「开始」页，不复制实例。
- 一般移组后空组自动收起。来源组在异步等待期间消失时，以当前组为来源回退；不重建已关闭的来源页面。
- 页面 host 在调用时捕获来源组；素材右键菜单在展示前捕获来源组和列表上下文，菜单等待／异步读取期间切换焦点不会反转“另一组”。完成后目标页获得操作焦点。
- `opens.open(view, host)` 回调获得继承这次位置的 host；后续调用 `open / openTab / openData` 默认延续目标，可显式覆盖选项。实际开页前不创建空组。仅播放、外部应用等不经宿主开页的打开器仍按插件自身语义工作，宿主不能强制它成为标签页。

位置只表达使用意图，不暴露组 ID，也不要求插件修改布局结构。示例页提供「在另一组打开此页」；专用示例文件名「布局路由示例.txt」演示回调打开器延迟调用 `openData` 时保留位置。

## 内容小窗（2026-11-14）

标签右键选择「移到新窗口」，或拖到当前会话各窗口之外松手。普通侧栏工具也有该入口；智能组中允许固定且允许 `center` 的工具可「在新窗口固定此工具」，仍保留智能组入口和原页面绑定。能力判断沿用允许区域：`TabType` 页面和声明 `placement.regions` 包含 `center` 的工具可承载，不新增窗口专用插件类型或业务 API。详情等只允许侧栏的工具不会因小窗能力而自动放开。

- 内容小窗复用主窗口的平台标题栏策略：macOS 的红绿灯与容器标签头部在同一行，不再叠加系统标题条；标签和按钮保持可点击／拖动，头部留白可移动窗口。Windows 继续沿用主窗口的原生标题栏。
- 一个小窗承载一个普通中央标签组，可放多个标签。标签能拖回主窗口、拖到同会话其他小窗，或用小窗 `··· → 全部移回主窗口`。第一批不在小窗内再分屏。
- 移动保留原内容 ID、React 实例、已挂载控件及局部状态；它不是复制，也不调用 `beforeLeave`。页面宿主、实例配额、共享编辑、服务、查询和选区仍来自同一会话。原固定绑定不变，普通跟随工具继续依照已有规则工作。
- 关闭小窗就是关闭其中所有页面：失焦提交 → 本机检查点 → 逐页 `beforeLeave('close')` → 全部成功后才移除标签并关窗。任一页面失败或取消，所有标签和小窗保留；已成功的保存不会回滚。普通／固定工具仍使用各自原有关闭规则。
- 关闭最后一个标签会关闭空小窗；主窗口仍保留一个入口。正常关窗不自动移回；仅承载窗口异常消失／创建失败时，将尚未关闭的内容留回主窗口，不冒充正常关闭成功。
- 窗口大小、位置及成员写入本机工作区的 `EditorGroup.window`，仍是 `Workspace.editors` v2 的可选位置描述，主窗口分割树不包含这些组。重开／重载按已有页面 `saved / setState` 恢复，离屏坐标限制到可见屏幕；不承诺恢复任意未存档的组件变量。主窗口关闭／仓库重载统一检查全部内容后结束附属窗口。
- 工作台预设只调整主窗口；小窗里的内容仍参与实例约束，但不会被预设夺回或复制，也不进入便携布局预设。现有小窗不具备独立于所属仓库会话存活的能力。

### 插件的显示文档

插件代码仍运行于所属会话的 JS 环境，**全局 `document/window` 不保证是画面所在的位置**。业务对象和服务保持原实例，DOM 环境由宿主统一提供；插件不需要判断“主窗还是小窗”。

优先使用以下公共入口（打包工具与运行时已同步）：

- `ui/widgets` 的 `UiPortal`：把浮层放到所属内容所在文档；`Overlay` 已使用它。
- `ui/hooks` 的 `useUiEffect(setup, dependencies)`：与 layout effect 一样在 DOM 提交后运行，除显式依赖外，还自动跟随显示文档；移窗、依赖变化和卸载时，自动取消该次登记的监听、观察器和未执行的动画帧，再在新文档重新登记。
- `ui/hooks` 的 `useUiFrame()`：给按钮等事件处理器安排下一帧，返回取消函数；移窗／卸载自动取消旧文档中未执行的任务。
- `ui/widgets` 的 `useUiDocument()`：原始 DOM／第三方控件的低层入口；有元素时也可用 `ownerDocument/defaultView`。

```tsx
import { useRef, useState } from 'react'
import { useUiEffect } from '@resource-manager/plugin-api/ui/hooks'
import { UiPortal } from '@resource-manager/plugin-api/ui/widgets'

function ReaderTools() {
  const root = useRef<HTMLDivElement>(null)
  const [width, setWidth] = useState(0)
  const [help, setHelp] = useState(false)
  useUiEffect(display => {
    display.observeResize(root.current!, () => setWidth(root.current!.clientWidth))
    display.onWindow('keydown', e => { if (e.key === 'Escape') setHelp(false) })
  }, [])
  return <div ref={root}>
    <button onClick={() => setHelp(true)}>帮助（可用宽度 {width}）</button>
    {help && <UiPortal><div role="status">阅读操作提示</div></UiPortal>}
  </div>
}
```

`setup` 收到 `document/window`，以及 `onWindow`、`onDocument`、`on(element, ...)`、`observeResize`、`observeIntersection`、`observeMutations`、`frame`。这些方法返回提前取消函数，通常无需手动清理；`setup` 也可返回自定义清理函数。业务依赖照常写入依赖数组；观察目标须在本次提交时已存在，条件挂载的目标需将对应条件加入依赖。动画帧会在移窗时取消，不用于必须完成的业务提交。已经发出的异步请求仍由调用方用原来的取消／过期结果规则处理。

容器默认按自身可用宽度排版；主窗口可额外提供侧栏动画的终点宽度，内容不依赖 `.app`。普通 React 状态、共享编辑、播放记录、核心连接和后台服务不应放进 `useUiEffect`，否则移窗可能重复创建业务会话。公共显示机制也不代替插件的可见性／暂停规则。

公共选区、尺寸测量、PDF 可见页检测、内置弹层与播放条已采用上述机制。宿主工作台级快捷键仍由全部显示窗口的统一路由处理，插件自己的局部监听用 `useUiEffect`。系统弹窗与菜单跟随操作窗口，IPC 和业务执行仍由原会话负责。

第三方编辑器、iframe、原生绑定或直接使用全局 DOM 的外部插件仍需按此规则接入并验收；宿主不能自动改写第三方内部的窗口依赖。主窗口的主题源、插件样式注入、核心通信、存档和会话退出监听保留原归属，不机械替换为小窗上下文。

## 内容实例规则（2026-11-10）

内容身份、实例身份与位置分开。页面内容身份是类型＋`key(params)`；同一素材的阅读器与数据详情不是同一内容。实例 ID 对应一次具体打开，移动不换 ID；所在区域／组不参与窗口配额。集合的 `viewId / presetId` 只是导航来源，同来源集合仍可拥有不同的临时筛选和局部状态。

| 场景 | 当前声明与复用依据 | 数量与关闭 |
| --- | --- | --- |
| 普通工具 | `toolViews`，稳定工具 ID 就是唯一实例 ID；`placement` 只管位置 | 每仓库窗口一份；关闭隐藏，重开沿用原实例；移到中央不复制 |
| 中央阅读／编辑页面 | `tabTypes.key` 判断内容，`instances` 声明按内容／类型计数；普通打开复用，显式新建另申请 | 包括隐藏、缓存卸载但未关闭的页面；关闭走页面结束协议，失败保留 |
| 集合浏览页 | 导航按本组内来源 ID 定位，未命中再决定原位切换或新开 | 显式新开保留独立页面；不按同一保存视图强制合并 |
| 智能组伴随工具 | `context.requires`，宿主按组＋来源页面＋工具持有呈现 | 不占固定工具配额；焦点变化、隐藏与缓存释放不等于关闭独立固定实例 |
| 独立固定工具 | `context.detachable.maxInstances`；工具类型＋来源页面 ID／类型决定复用 | 按窗口、工具类型计数；隐藏、来源失效及插件暂不可用的绑定仍占名额，明确关闭才释放 |

给插件选择声明时：页面用 `key / instances`；普通工具不需要伪造页面单例；伴随工具用 `context`，允许拖出时再声明 `detachable`。`placement` 不控制多开，不能通过换区域绕过数量限制。需要自己的复杂保存流程时，优先使用页面及 `beforeLeave`；本批没有为工具新增关闭拦截协议。设置和命令面板仍是窗口浮层，不加入标签实例计数。

内部 `content-instances.ts` 统一只读判断“复用已有实例／允许创建／拒绝”，`page-instances.ts` 和 `context-tools.ts` 将各自声明与权威记录适配给它。实例清单由当前工作区即时生成，不新增注册表或持久配置；普通工具的唯一性直接由稳定 ID 和原装配流程保证。集合导航继续使用独立的打开意图解析，不把来源 ID 当作强制单例身份。

复用先于数量限制；移动和合并容器不重新申请名额。拖放预览不预留名额，提交用最新工作区再次选择实例并检查落点，失败不产生半份绑定。中央的 `workspace.tool` 只是位置引用，固定工具从 `bindings` 计数一次；智能候选及运行缓存不混进固定配额。128 份固定记录的工作区结构保护上限也仅拦截新增，不阻止复用。

数量规则收紧后，恢复仍保留有效存档中的已有页面／绑定和状态，后续新增受限；不静默删掉超额实例。保留现有布局版本、公共 API 和关闭差异，不引入临时预览标签、LRU 自动关页或单项容器样式变化。

## 集合导航的打开与复用（2026-11-10）

导航中的预设／保存视图、命令面板和“全部”快捷入口共用窗口内部的 `openCollection` 动作。它是导航意图，和公共 `host.openTab` 的通用开页契约分开：

- 普通打开只在请求来源分屏组查找相同 `viewId` 或 `presetId` 的集合页，优先当前页、近期访问页，再按组内顺序。命中只定位，不重置临时筛选、搜索、排序、选择和布局状态；不按标题或查询 JSON 判断同一视图。
- 未命中时，只替换仍然是当前组活动页的来源集合；当前是阅读页、工具或开始页时新开集合。不会替换后台其他集合，也不跨组搬走已有目标。
- 导航 Cmd/Ctrl 点击明确新开，同一保存视图可在同组或不同组保留不同临时条件。新建视图后的打开同样明确新开。存量副本不合并、不删除。
- 命令和设置退出前捕获来源页及分屏组。异步等待期间换页时，不替换后来激活的页面；来源组已不存在则按现行组定位规则回退。
- 插件导航贡献的 `open(params, newTab)` 使用这套动作；插件直接调用 `host.openTab('collection', ...)` 仍按原契约开页，公共 API 未新增方法。自定义 `preset.tab` 页面仍交其类型规则处理。

实现由 `collection-navigation.ts` 只读决策、工作区控制器提交，替换继续走页面结束协调与设置离开检查。不新增临时预览标签、数量上限或自动淘汰；同一内容的阅读页实例规则继续见下节。

## 页面实例数量与显式多视图（2026-11-01）

外部插件声明 `uiFeatures: ["page-instances-v1"]`。新能力不改变仓库／文件空间数据格式，页面实例 ID、各自参数和状态仍保存到本机工作区。

```ts
// 每份内容最多两份视图。省略 max 则不设上限。
{ id: 'reader.page', key: params => params.id,
  instances: { scope: 'content', max: 2 }, Title, Component }
// 整个窗口只允许一个该类型页面；不需要伪造内容身份。
{ id: 'tool.settings', instances: { scope: 'type', max: 1 }, Title, Component }

host.openTab('reader.page', { id }, { group: 'other', instance: 'new' })
// host.open / openData 同样接受 instance；最终页面类型决定是否允许。
```

规则分两部分：`key` 识别同一内容；`instances.scope` 确定计数范围。`content` 必须声明 key，按同类型＋同 key 计数；`type` 统计窗口中该类型所有页面。max 若提供必须是正整数，包含可见、隐藏和已卸载但未关闭的页面；每个仓库会话独立计数，主窗口和其内容小窗共用名额。不是按标签组设限，也不是全应用全局单例。

- 未声明 instances：沿用已有规则，有 key 时每份内容一页，无 key 时普通打开新页；不提供新的复制入口。
- 普通打开仍优先复用：先找请求目标／来源组当前页，再按来源、当前页与近期访问记录选择匹配页，最后取已有匹配页。多个视图存在时不任意复制，显式定位参数只交给获选视图。
- `instance: 'new'` 请求独立实例。需要类型明确声明且 max 不是 1；超限或未开放时提示，保留所有原页，不暗中搬走／关闭／替换它们。新视图可在同组或另一组；另一组尚不存在时沿用区域尺寸校验。
- 标签右键的「在另一组新建此内容的视图」只对允许多开的类型出现，复制所点页面的参数和最新已报告存档；两份对象独立，之后不互相同步局部状态。菜单等待期间保留来源与目标组。公共 open 调用新建时使用传入参数，从插件默认恢复逻辑开始，不自动复制其他页面的存档。
- 原「在另一组打开」以及移动／拖放仍移动原实例。没有把移动改为复制；菜单分屏继续只创建「开始」页。
- `setParams` 同 key 更新不新建、不触发结束；内容 key 改变时先检查目标容量，再结束原内容并清空旧状态。已允许多视图时可在本视图切到另一处已打开的内容；未声明的旧类型仍定位已有页并保留来源。超限则保留来源内容并提示。
- 数量规则作用于新建／替换／导航。升级后若规则收紧，恢复存档保留原页和状态，不静默删除超额草稿；新增仍受限，用户关闭后数量自然收敛。移动、合并不改变实例数。
- 插件应仅在页面局部状态和业务写入已能正确处理多视图时声明。它不自动提供共享编辑草稿、保存冲突或撤销协同。

### PDF 与图片首批接入

两种查看器声明按内容多开，暂不设固定数量上限。PDF 页码、页内位置、缩放独立；图片缩放和平移独立，并新增本机存档以支持冻结／重启恢复。普通打开保持复用；显式多开才增加渲染和内存开销，不保证多页与单页资源成本相同。

PDF 结束回调读取同内容其他页面的快照，选择最近实际翻阅／定位的记录。隐藏、布局复位、存档恢复和关闭引起的自动焦点转移不刷新阅读时间。核心 `pdf.saveReading` 命令在同一事务中检查素材未回收、原件 hash 仍匹配、阅读时间更新后才写入，迟到和重复回调不会覆盖新进度；继续不占仓库撤销历史。只影响正式进度，不拉动其他视图的滚动位置。

这是 PDF 自己的仲裁规则，宿主只提供同内容快照。文字数据块的条件保存与[共享编辑会话](共享编辑会话.md)已作为下一批接通，其他插件需主动适配。纯看图／阅读的多视图不表示所有批注、第三方编辑器或旧插件均已验收。
