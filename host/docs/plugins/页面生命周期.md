2026-11-05 宿主内部将工作区控制、结束协调和 UI 接口装配分开，职责见[窗口运行与界面装配](../architecture/设计文档.md#窗口运行与界面装配)。以下插件契约和执行顺序保持，不需要插件跟随宿主目录调整代码。

## 归属与事件

内容身份、页面实例和使用会话是不同概念。当前页面实例由标签 ID 标识，`TabType.key` 用于识别同内容，普通打开优先复用；`saved / setState` 是每个页面的本机恢复状态。布局或组件挂载情况不能决定业务会话是否结束。

| 操作 | 宿主行为 |
| --- | --- |
| 获得焦点／失去焦点、显示／隐藏、移组、分割／合并 | 更新布局和 `active / visible`，不触发结束回调 |
| 后台页面超出保活缓存 | 卸载组件，保留参数和 `saved`，不触发结束回调 |
| `setParams` 改变内容身份键 | `navigate`，提供 `nextParams`；无 key 的类型由插件判断是否离开旧内容 |
| 打开时复用同身份页面／同 key 的参数调整 | 更新打开意图并定位，不调用结束回调、不阻塞焦点切换 |
| 原位置换成另一标签类型／页面 | `replace`，先结束旧页面 |
| 关闭标签 | `close`，保存成功才移除页面 |
| 正常关闭仓库窗口／应用退出 | `shutdown`，逐页准备成功后允许关闭 |
| 应用菜单重载／插件应用并重载 | `reload`，准备成功后卸载旧页面；仓库重载随后才停止旧服务／核心 |

未声明多视图的类型同标签切换内容时，若新 `key` 已在另一页打开，定位已有页并保留来源页；已声明的类型则按数量规则检查后在本页切换。键发生变化时旧页面恢复状态不传给新内容。普通打开优先沿用已有页面；显式阅读定位仍由插件解释。

## 静态结束回调

回调声明在 `TabType` 上，不能只由挂载中的组件临时注册：后台组件可能已经被回收。

```tsx
import type { TabType } from '@resource-manager/plugin-api/ui/contracts'

const reader: TabType<{ id: string }, ReadingState> = {
  id: 'reader.page',
  key: params => params.id,
  Title,
  Component: Reader,
  async beforeLeave({ params, saved, reason, nextParams, host, signal }) {
    if (reason === 'navigate' && nextParams?.id === params.id) return
    if (!saved || saved.id !== params.id) return
    signal.throwIfAborted()
    await saveReadingPosition(host, saved) // 功能自己定义写入及校验；返回真正的保存 Promise
  }
}
```

- 声明 `page-instances-v1` 后，可使用 `otherViews` 读取其他同类型、同 key 的页面 `{id, params, saved}` 快照（含未挂载页）。无 key 时为空；快照是独立副本，不是跨视图可写状态。
- `id` 是标签实例 ID，`params / saved` 属于即将结束使用的旧内容。`nextParams` 仅在 `navigate` 提供。
- 页面应在状态变化时用 `setState` 报告必要的可序列化数据。不能直到 React 卸载清理时才报告，也不能把 DOM、组件引用或密码放进去。
- 保存成功正常返回；拒绝或失败抛错。宿主保留页面、参数和本机状态，并提示重试。新接口不使用“先关掉，后台再尝试保存”的顺序。
- 回调可能因关闭重试、退出被其他页面拒绝而再次执行，应可重试、不重复产生业务副作用。已经成功的业务保存不会因另一页拒绝退出而回滚；这不是跨插件事务。
- `signal` 在取消或超时后中止。回调应传递信号给可取消工作，并在等待后检查。宿主忽略旧准备的完成结果；已发出的数据库写入不能因此撤销，也不会自动重试。
- 整个页面准备有 30 秒上限，超时保留窗口／页面。准备期间暂停常规界面操作；插件通过 `host.showDialog` 展示的结束交互仍可使用。
- 首版 `setParams` 保持原调用签名，但有回调时变更在保存成功后才生效。应以实际收到的新 `params` 判断完成，不能在调用后假定已切换。

## 恢复与退出

复用按仓库 ID 保存的本机工作区，不另建业务数据库。日常状态变化按 400ms 时间片合并保存，连续滚动也定期落盘；进入受管理的结束回调前先保存恢复快照，整窗准备完成后再保存一次。保存失败不继续丢弃页面。异常中断只能恢复最近一次成功落盘的状态，不能保证最后一瞬间的操作。

主进程与页面通过请求 ID 协调，成功后才关闭或重载；失败和超时允许重试。应用退出时，任一窗口拒绝会解除其余窗口的准备状态，不提前停掉仍在使用的应用服务。原生重载的兜底不能依赖卸载时异步请求能完成；Electron 的卸载取消语义参见 [BrowserWindow close](https://www.electronjs.org/docs/latest/api/browser-window#event-close) 和 [will-prevent-unload](https://www.electronjs.org/docs/latest/api/web-contents#event-will-prevent-unload)。

后台核心已经退出时，仓库重载先保存本机快照，跳过无法完成的业务写回再启动后台，避免恢复入口被旧回调卡住。绕过宿主的程序化导航受 Chromium 用户手势限制，不能保证执行结束回调；插件应使用宿主重载入口。强制结束进程／系统关机不能保证执行回调；本机恢复快照是补救，不是事务日志。工作区属于本机，不应把它当成跨设备的最终阅读记录。

## PDF 首个接入

- 已有页面优先定位；恢复顺序为同内容版本的页面状态，再回退 `pdfreading` 数据块。旧页面没有 hash 的存档可沿用，但新报告带上原件 hash。
- 阅读中保存页面页码、页内位置、缩放和阅读时间；不再按 600ms 防抖不断写 `pdfreading`。
- 关闭标签、换另一篇文档、重载及正常退出时写回。失焦、移动、暂时卸载不写回；冻结的标签仍可以结束并保存。
- 结束回调从本页和其他同内容快照选择最近翻阅位置；核心命令事务内检查素材仍存在、未回收、原件版本匹配且阅读时间更新。只报告完成初始定位的位置，打不开文件不写入默认第 1 页。
- `pdfreading` 原结构和既有数据不变；进度仍不占撤销历史，缩放不进仓库块。检查器显示“上次保存进度”，避免被理解成当前页面的实时位置。
- 进度校验与写入现由 PDF 自己的同步命令原子完成；没有新增通用条件写入或共享编辑框架。
