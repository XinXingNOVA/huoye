# 操作历史与 MCP

操作历史归仓库核心。宿主「编辑 → 操作历史」和应用 MCP 读取同一个 `History` 服务；界面可以另行包装，不能自行遍历数据库拼出另一套撤销规则。外部 UI 插件使用这些接口时声明 `uiFeatures: ["operation-history-v1"]`；类型从 `@resource-manager/plugin-api/core` 导入。

## 范围与保存

- 展示当前核心会话内实际产生修改的仓库操作。关闭后重开、重新加载仓库或重启应用开始新会话；仅重载页面不重建核心时仍是同一会话。
- `operation` 保存时间、名称、状态及可选来源信息；影响身份和数据块种类来自已有 `block_history / op_entity / record_history`。结构准备时增量补上 `operation.context / bytes` 与会话索引，不改变文件空间 v4 格式。
- 来源为 `application`（应用入口）、`external`（对外操作或应用 MCP 入口）、`system`（自动收录）。这是调用入口说明，不是权限、AI 身份认证或防篡改审计。插件命令可包含插件 ID 与命令名。
- 空操作、命令预演和失败事务不产生记录、不会发出历史变化通知。一个批量命令对应一笔历史；多次 MCP 调用分别记录，不自动拼成一次 AI 任务。
- 彻底删除素材会清除它的历史；混合操作的影响项随之减少，空记录移除。管理记录的可撤销删除可能暂时显示「当前不存在」。这是当前可恢复记录，不是永久审计日志。
- 不包含尚未保存的共享编辑草稿、应用配置或文件空间的物理操作。原件发布、接纳、回收、系统废纸篓等依照文件协议恢复，不能借仓库历史宣称整体可撤销。

## 公共查询

```ts
const page = await host.core.listHistory({ limit: 30 })
// 最新在前；page.nextBefore 非 null 时继续。requestId 可精确定位本次会话的请求。
const older = page.nextBefore === null ? null
  : await host.core.listHistory({ before: page.nextBefore, limit: 30 })
const matches = await host.core.listHistory({ requestId: 'my-request-id' })
const detail = await host.core.readHistory({ id: page.entries[0].id, offset: 0, limit: 50 })
const stop = host.core.on('historyChanged', () => { /* 丢弃旧翻页位置，重读列表与详情 */ })
```

`listHistory` 返回 `session / revision / entries / total / nextBefore / undo / redo`，以及可选 `retention: { limit, byteLimit, bytes, trimmed }`。`bytes` 为当前保留历史的 UTF-8 载荷估算，不含 SQLite 页和索引开销；`trimmed` 为本会话因预算裁剪的操作数。旧宿主可不返回该字段。每条记录包含 `id / at / label / state / source / affected / kinds`，以及可选 `plugin / operation / requestId`。当前 `state` 为 `done / undone`；撤销后发生真实新修改，会物理清除放弃的重做分支。类型仍接受旧宿主返回的 `discarded`。

`readHistory` 返回当前记录与分页影响身份。每项含 `id / exists / trashed / kinds`，不返回请求参数或历史正文。`exists / trashed` 为查询时的身份状态；标题和现有内容另通过 `get / readItem / readContent` 取得。两种查询每页最多 100 项，每处块种类最多 30 个，超出用 `kindsTruncated` 标记。未知、非当前会话或已裁剪／放弃重做的 ID 报 `HISTORY_UNAVAILABLE`。

分页是实时读取，不是冻结快照；`historyChanged` 后重新从首页加载。通知只在所属事务成功提交后发送，后台派生加工不刷新历史。结果不依赖插件是否仍能提供专用界面。

## 撤销保护

保留无参数 `undo() / redo()`，继续用于即时快捷键。展示了待撤销操作的面板应带上快照保护：

```ts
if (page.undo) {
  await host.core.undo({ session: page.session, revision: page.revision, id: page.undo.id })
}
```

若期间有新操作、撤销／重做或历史清理，返回 `HISTORY_CHANGED`，未改动数据；刷新后让用户重试。`id` 只是校验当前栈顶，不允许选择任意旧记录回滚。重做使用 `page.redo`。不能把 `done` 的每一行都显示成可单独撤销。

## MCP 与回执

应用 MCP 增加只读工具 `list_history`、`read_history`，都必须传 `libraryId`。该仓库 `read / organize` 权限均可使用；未授权或未打开仍拒绝。没有开放 MCP 撤销／重做工具。

```json
{ "libraryId": "目标仓库", "requestId": "之前写操作的请求ID", "limit": 30 }
```

以上参数用于 `list_history`；获得记录 ID 后以 `{ "libraryId": "目标仓库", "id": 记录ID }` 调用 `read_history`。

`execute_operation` 自动记录操作名、所属插件、请求 ID 与外部来源。`import_to_library`、`adopt_space_files`、`apply_item_lifecycle` 的可撤销部分也关联请求；这些 UI/MCP 共用入口的可选 `source` 参数仅供入口标注，默认 `application`，应用接入层覆盖为 `external`，不改变校验、权限或请求签名。插件不用为已有 operations 新增声明。

请求回执与修改在同一事务提交；重试重放原回执，不产生第二条历史，撤销后重试也不重新执行。历史查询可能为空：无实际修改、只保存原件而未收录、不可撤销的永久清除、记录已清理或核心会话已重开。空结果不代表请求失败；应按原请求重查回执，再读取当前素材状态。


## 自动保留与手动整理（2026-11-06）

核心会话成功开始时，一次事务清理旧的 `operation / block_history / op_entity / record_history`，包括早期没有所属操作的快照。只做 `openLibrary` 结构准备或装配失败不会触发清理。重载核心也算新会话；页面刷新不算。

当前会话固定保留最近 **1000 笔**，并按约 **64 MiB 历史载荷**裁剪，从最早操作开始，始终留下连续的最新后缀。批量操作不可拆分；最新一笔即使自身超预算也完整保留，因此不是数据库文件的硬上限。字节计量包含数据块前后 JSON、身份记录和操作说明的估算；仅在完成操作及永久清除影响项时更新，不在每次写入扫描全部历史正文。

裁剪与新写入共用事务，失败／预演一起回滚；提交后才更新 `retention.trimmed`、修订号和通知。撤销／重做不裁剪，也不再追加无主快照。无变化写入不清空重做分支。`Store` 只为明确所属 `History.run` 的原始块记录快照，底层非操作写入不是另一套永久版本日志。

历史清理不涉及当前素材与数据块、类型定义、原件、`operation_receipt`、未完成导入或文件编辑任务。请求回执仍用于跨会话幂等，不随历史预算过期。文件空间的内容版本不是本策略的清理对象。

SQLite 删除后通常把空闲页留给后续写入复用，磁盘文件不会立即缩小。宿主 **设置 → 当前仓库 → 数据库维护 → 整理数据库** 提供手动压缩；不在每笔操作或开库时自动执行。公共调用归仓库核心：

```ts
const info = await host.core.databaseStorageInfo()
// allocatedBytes: library.db 逻辑页占用（包含 WAL 中已提交的页）
// reusableBytes: 可复用的完整空闲页；不是历史大小或承诺可释放字节
const { before, after, checkpointPending } = await host.core.compactDatabase()
```

外部 UI 使用维护接口声明 `uiFeatures: ["database-maintenance-v1"]`；类型 `DatabaseStorageInfo / DatabaseCompaction` 从 `@resource-manager/plugin-api/core` 导入。该入口没有开放给 MCP。整理仅对 `library.db` 执行检查点、`VACUUM main` 和后续检查点，不删任何业务表记录，不修改文件空间或派生库，不产生撤销记录，也不重置当前历史守卫。

整理期间核心数据库调用串行等待，大库可能需要较长时间和额外临时磁盘空间。活动事务或其他连接占用读取快照时返回 `DATABASE_BUSY`，稍后可重试；SQLite 写入错误直接反馈。`checkpointPending` 表示整理成功但后续检查点受占用，实际磁盘回收需等待连接释放；不要把逻辑页占用当作整个仓库文件夹或即时磁盘总占用。
