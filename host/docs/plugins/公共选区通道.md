# 公共选区通道

核对日期：2026-10-19。适用于更新后的宿主、EPUB 1.1.0、摘录批注 1.1.0。这是可信插件共用的 UI API，类型位于 [selection-types.ts](../../src/plugin-api/ui/selection-types.ts)，运行入口为 `@resource-manager/plugin-api/ui/selection`，纯数据入口为 `@resource-manager/plugin-api/content-selection`。

## 职责与使用场景

在 EPUB、文字或 PDF 中选一段正文，宿主显示一个菜单，按已启用插件组合“标记摘录”“添加批注”“复制”等操作。读者只选一次，多个插件可同时读取同一份快照；操作不会因为另一个插件读取过而消失。前三项直接显示，其余进入“更多”。

| 参与方 | 提供的能力 | 不承担的职责 |
| --- | --- | --- |
| 阅读器 | 将本地选区解释成文字和来源位置，定位、高亮坐标、原文跳转 | 不依赖某个摘录、翻译或笔记实现 |
| 宿主 | 窗口内选区快照、有效期、统一菜单与贡献装配、定位路由 | 不保存摘录业务数据，不解释章节或页码 |
| 消费插件 | 声明选区操作，决定保存哪些业务数据及如何呈现 | 不读取别的插件 DOM，不猜来源坐标 |
| 摘录批注插件 | 保存 `anchor` 身份及关联笔记、标签，展示标记和原文入口 | 不依赖 EPUB 私有代码或硬编码所有媒体格式 |

图片圈选和视频时间段仍走原有 overlay；本轮公共通道面向文字内容，没有把所有交互状态合并成全局事件总线。MCP 不读取窗口中“当前选区”；持久化后的摘录继续走通用读取。新增业务查询或写操作仍由拥有业务的插件声明。

## 数据契约与有效期

```ts
interface ContentLocator {
  provider: string             // 插件 ID 开头的稳定名称，如 epub.quote
  version: number              // 位置格式版本，从 1 开始
  data: Record<string, unknown> // JSON 数据，由来源阅读器解释
}
interface ContentReference {
  sourceId: string             // 仓库原素材身份
  text: string                 // 当时选择的原文
  locator: ContentLocator
}
```

发布后宿主添加 `id / tabId / surfaceId / revision / rect`，形成不可变 `ContentSelection`。`rect` 是当前窗口 CSS 像素坐标，只用于菜单；不要保存 DOM、Range、屏幕矩形、组件引用或本机绝对路径。持久数据只保存 `ContentReference` 的三部分，具体字段名由业务插件决定。

- 每个仓库窗口独立；只允许活动标签页发布，标签页之间不共享选区。
- `surfaceId` 区分阅读区域；`revision` 必须随实际内容／章节改变。切标签、关闭来源、卸载区域、进入编辑态或换版会使此前的快照失效，切回来也不会复活。
- 点击操作时捕获快照。打开批注对话框导致原生选区消失，快照仍可使用；保存前调用 `context.valid()`，不能再次读取 `window.getSelection()`。
- 滚动、布局变化、Escape 和关闭菜单会清掉当前菜单；不废弃已经点击操作持有的快照。异步操作完成只清理它自己的快照 ID，不会擦掉更新的选择。
- 通道是交互有效期检查，并非数据库事务锁。业务操作仍需遵守核心的数据验证、引用及撤销规则。
- 单次文字限制为 100,000 个 UTF-16 单位，位置 JSON 长度限制为 500,000；异常或过大的选区给出提示。

## 阅读器接入

外部包在 `plugin.json` 中声明：

```json
{ "uiFeatures": ["content-selection-v1"] }
```

如果已有其他 feature，应追加而非替换。旧宿主会在安装检查时拒绝未知 feature。UI 贡献使用了选区扩展但没有声明 feature，运行装配也会拒绝。包 API 版本仍为 1，feature 明确这次新增能力。

在**已排好版、活动**的正文旁挂载 `ContentSurface`：

```tsx
import { ContentSurface } from '@resource-manager/plugin-api/ui/selection'

// 示例片段：source、read、locate、reveal 等由本阅读器实现。
<ContentSurface
  host={host} tabId={tabId} surfaceId="reader.chapter"
  source={source} revision={`${sourceHash}:${chapterId}`}
  active={active} root={scrollViewport}
  read={read} locate={locate} reveal={reveal}
  selected={selected} select={setSelected}
  revealId={params.focus} revealKey={String(params.request)}
/>
```

- `root` 是正文可见的滚动视口，标记按其矩形裁剪。`read()` 验证两个端点都在来源正文，返回 `{text, locator, rect}`，否则返回 `undefined`。工具栏、其他页签、侧栏不可混入。
- `locate(reference)` 返回 `{status, rects}`。`found` 表示当前可定位；`elsewhere` 表示另一章或尚未呈现的页；`missing` 表示原文失配；`unsupported` 表示不识别位置格式。矩形采用视口 CSS 像素，随字体、窗口和缩放重新计算。
- `reveal(reference)` 滚到相应文字，需要时切换章节。`revealId / revealKey` 区分主动回跳与普通续读；重复打开同一摘录也应跳回。
- `version` 可传布局／搜索／渲染版本，促使贡献层重新计算。它不同于使快照失效的 `revision`。
- 正文明确设置 `user-select: text`；选择状态不能遮住原生拖选。动态字体、搜索标记和章节 DOM 改变后使用新的文本索引。
- 用 `contentLocations` 声明持久位置的打开方式：

```ts
contentLocations: [{
  id: 'reader.quote', version: 1,
  match: source => !!source.blocks.reader,
  open: (reference, focus) => ({
    tab: 'reader.book',
    params: { id: reference.sourceId, location: reference.locator,
              focus, request: Date.now() }
  })
}]
```

`match` 供检查器判断来源是否支持内容定位；`open` 只路由到阅读器，由阅读器验证位置。消费方调用 `host.revealContent(reference, excerptId)`，不用知道阅读器的标签页名称。来源插件停用或格式版本不支持时，宿主提示并打开摘录的通用数据详情。每个定位名称当前只注册一个格式版本；改变格式时应规划旧位置兼容，不假定版本号递增即可自动迁移。

无 DOM 的画面也可直接使用 `host.selection.register(owner)` 返回的 lease，主动 `publish / clear / dispose`。React 消费方用 `useContentSelection(host)`；非 React 消费方用 `subscribe/getSnapshot`。自行登记时必须在来源切换、失活和卸载时 dispose；通常优先用 `ContentSurface`。

完整实现可参考 [EPUB](../README.md)、[文字](../../src/plugins/text/selection.tsx)、[PDF](../../src/plugins/pdf/selection.tsx)。

## 消费插件接入

通过 `UiPlugin.selectionActions` 贡献操作，支持现有 `needs` 可选协作约束：

```ts
import type { SelectionAction } from '@resource-manager/plugin-api/ui/selection'

const explain: SelectionAction = {
  id: 'example.explain', title: '解释选中文字', order: 30,
  when: selection => selection.text.length <= 2000,
  disabled: selection => selection.text.length < 2 ? '请多选几个字' : undefined,
  async run(ctx) {
    const reference = {
      sourceId: ctx.selection.sourceId,
      text: ctx.selection.text,
      locator: ctx.selection.locator
    }
    // 可打开自己的对话框，保留 ctx 和 reference。
    // 实际保存之前检查 ctx.valid()，写入仍走本插件的核心命令。
    if (!ctx.valid()) throw new Error('来源已变化，请重新选择')
    ctx.host.notify(reference.text)
  }
}
```

动作 ID 全局唯一，不使用保留的 `host.` 前缀；`order` 越小越靠前。`when / disabled` 应为轻量纯判断。动作抛错由宿主提示，不清掉当前选择；重复点击执行中动作会被拦截。写入后可调用 `ctx.select(createdId)` 让阅读器和详情栏选中结果。

通过 `selectionLayers: [{id,order,Component}]` 贡献持续的标记显示。组件接收 `SelectionSurfaceProps`，查询自己的记录，调用来源的 `locate / reveal`，不要遍历别的阅读器 DOM。宿主只在活动来源渲染这些层；组件必须清理自己的监听和订阅。参考 独立摘录批注插件的 selection.tsx。这是可信插件协作契约，不是恶意代码沙箱。

## 现有三种位置与数据兼容

| provider@version | 保存位置 | 失配判断 |
| --- | --- | --- |
| `text.quote@1` | 正文偏移、前后文；原文另存 | 通过原文与上下文重新寻找，位置仅用作重复句子的辅助 |
| `pdf.quote@1` | 原文件指纹、每页原文与比例矩形 | 文件指纹和页数；缩放时按当前页面重算坐标 |
| `epub.quote@1` | 指纹、章节 href、章节文字偏移与前后文 | 原文件指纹、章节与正文；按当前阅读排版定位 |

EPUB 当前一次选区限一个已显示章节；PDF 支持已加载文字层之间的连续跨页。EPUB 不宣称 CFI 互通；PDF 无文字层时仍不能直接选字，不新增 OCR。来源失配保留摘录原文、笔记与标签，不把旧位置套到新文件。

摘录批注 1.1.0 将 `anchor` 扩展为 v3，新增 `内容摘录` 和 `locator`，新文字、PDF、EPUB 摘录共用这一形状。旧 `文本区间 / PDF摘录 / 图片区域 / 时间段` 及其字段原样保留；冻结 v1、v2 通过 `compatibleSchemas` 接续，只更新结构版本，不重写原文、身份、写入序号或历史。旧文字／PDF 标记继续由兼容 overlay 显示，新记录由 `selectionLayers` 显示；导出、标签、引用、删除与撤销沿用原有路径。

旧批注包没有 `overlay.selection: 'shared'`，新宿主的文字／PDF 阅读器会保留其旧选区菜单，避免出现两套操作。新版批注包显式声明 shared，阅读器接管选区发布，旧 overlay 只负责旧记录显示。已绑定旧版本的仓库不会自动升级：更新宿主后，安装并选择 EPUB 和摘录批注 1.1.0，再统一应用重载。数据已经接续到新结构后不保证降级旧包。

后端 `place` 是可重建定位结果，仍由理解来源格式的 text/pdf/epub 加工器产出；纯 JSON 定位结构不把几何解释塞给核心。其他来源若要支持关闭阅读器时的失配状态，也应自行提供对应加工规则。


验证命令与当前覆盖范围统一见[开发与验证](../development/开发与验证.md)。
