# 公共集合与页面输入

2026-11-05。用于把已有素材呈现为一个可搜索、筛选、排序和选择的页面。插件提供范围与业务动作，宿主提供标准集合界面。“编辑中”由独立的 `file-editing` 外部插件使用同一入口实现，任务服务仍由宿主托管。

## 能力与归属

| 能力 | 清单声明 | 公共入口 |
| --- | --- | --- |
| 标准集合 | `collection-surface-v1` | `@resource-manager/plugin-api/ui/collection` |
| 页面输入规则 | `page-inputs-v1` | `TabType.inputs`，类型在 `ui/contracts` |
| 可订阅卡片角标 | `reactive-badges-v1` | `UiPlugin.badges[].Component`，`ui/media` 的 `ResourceBadge` |

以上均为可选能力。已有页面未声明输入规则时保持原行为；已有 `badges[].get(view)` 仍有效。旧宿主会拒绝不认识的能力声明，插件应声明实际用到的能力。

## 一个页面使用一个集合

```tsx
import type { TabProps } from '@resource-manager/plugin-api/ui/contracts'
import {
  ResourceCollection, collectionQuery,
  type CollectionParams, type CollectionState
} from '@resource-manager/plugin-api/ui/collection'

function Page(props: TabProps<CollectionParams, CollectionState>) {
  return <ResourceCollection {...props} />
}
// 作为 UiPlugin.tabTypes 的一项：
const tab = {
  id: 'example.items', Title: () => <>素材</>, Component: Page,
  dropQuery: collectionQuery
}
// host.openTab('example.items', {
//   title: '图片', query: { has: ['image'] }, layout: 'masonry'
// })
```

`ResourceCollection` 透传完整 `TabProps`，使用原有工作区的存档、焦点、键盘和页面生命周期。每页只放一个集合，不另建一份标签页状态。集合复用已启用的布局和公共卡片，提供搜索、临时条件、排序、选择、多选、上下文菜单、拖出及导航来源。默认双击调用 `host.open(id, 当前查询)`；`onOpen(id, from)` 可改成继续编辑等业务动作。右键操作和预览仍为宿主通用入口，不因双击回调而改写。

`CollectionParams` 定义标题、基础查询、布局和选项；使用 `browsing-layout-v1` 时可省略 `layout`，首次打开取得本机本库默认快照。`CollectionState` 保存临时搜索、筛选、排序、布局调整、选择、缩放和滚动锚点。窗口管理这些值，插件不要自行写工作区文件。集合按素材角色查询，不用于列出空间文件记录或插件管理记录。

公共组件不提供“保存为仓库视图”按钮。保存视图的创建、版本校验和所有打开页的规则同步仍由宿主标准集合负责；插件的业务范围不自动转成 `view` 数据块。传 `viewId` 不会给自定义页面增加保存规则同步。自定义页面要跟随业务定义更新，应自行订阅并更新 `params`。

## 动态范围、工具条和提示

```tsx
function Page(props: TabProps<CollectionParams, CollectionState>) {
  const state = useMyWindowState() // 插件自己提供订阅与恢复
  return <ResourceCollection {...props}
    scopeIds={state.ids}
    Toolbar={MyToolbar}
    beforeItems={state.error && <p role="alert">{state.error}</p>}
    onOpen={id => continueMyTask(id)}
  />
}
```

- `scopeIds` 与基础查询的 `ids` 相交，再由查询筛选、排序。它只限定成员，不代表显示顺序。范围更新传新数组；加载中用 `[]`，`undefined` 表示不限范围。空数组必须得到空结果。范围缩小时立即隐藏不再属于范围的旧结果，不等新查询返回；查询失败显示错误并保留范围内的上次结果。
- 动态范围不写进 `CollectionState`，不自动保存到业务数据中；调用方负责从任务、业务查询或其他状态恢复它。重启不能把一个旧 ID 快照冒充最新范围。
- `Toolbar` 是稳定的组件，收到 `{host, ids, selected, query}`；ID 和查询都是只读快照。用当前 `selected` 决定批量动作，异步确认保留目标快照，业务写入仍做权限／版本校验。不要在父组件每次 render 中重新定义 Toolbar，避免丢失内部状态。
- `beforeItems` 放置提示或失败恢复入口，不参与工作区存档。

动态范围只是呈现约束，**不会推导拖入后该做什么**。类似“编辑中”的派生列表应显式禁止收录／新建；可写集合则声明 `dropQuery`，复用视图的自动填写和准入检查。`collectionQuery` 合并基础与临时规则、搜索及布局拖入区域的条件；不要把动态任务 ID 塞进它冒充可写业务条件。

## 页面输入规则

```ts
inputs: {
  receive: false,
  create: false,
  reason: '此页按处理状态汇集素材，请到普通视图收录或新建'
}
```

`receive:false` 拒绝窗口路由的文件选择导入、拖入和粘贴；在打开选择器或解析剪贴板／下载内容前检查。拖动显示拒绝原因，不显示可收录高亮。`create:false` 关闭标准集合空白处新建入口，并拦截窗口新建菜单／快捷键和 `host.showCreateMenu`。宿主通过 `TabProps.inputs` 转交声明，组件可据此组织自己的入口。原因可省略，届时使用通用提示；最大 500 字。

未声明或 `true` 保持既有行为：有 `dropQuery` 时按该查询处理，没有查询则普通收录。声明为页面类型的静态规则，不是每个实例的动态权限。向侧栏保存视图拖入时，目标是该视图，不沿用当前页面的限制。

这是界面输入路由，不是数据权限，也不是只读页面开关。不会禁止已有素材的改名、回收或插件直接调用业务 API，不拦截文本编辑器自己处理的原生粘贴。外部可信插件仍须正确使用核心 API；仓库和空间授权由后端校验。

## 可订阅角标

```tsx
import { ResourceBadge } from '@resource-manager/plugin-api/ui/media'

function TaskBadge({ view }) {
  const tasks = useMyWindowState()
  return tasks.has(view.id) ? <ResourceBadge title="本机处理状态">处理中</ResourceBadge> : null
}
// UiPlugin.badges：
[{ id: 'example.processing', order: 100, Component: TaskBadge }]
```

`Component` 接收 `{view, host}`，可用 React hook 订阅状态，返回 null 表示无角标。`ResourceBadge` 复用标准样式，支持 `color`、`title` 和子内容；角标按 `order` 排列，不改变素材身份、标题或数据块。`get` 与 `Component` 二选一，组件贡献须有唯一的 `插件ID.名称`。已有匿名静态 `get` 贡献可继续使用。

外部包的角标组件由插件错误边界保护。跨卡片的任务状态宜在一个 `windowProvider` 中订阅，再投影到每张卡片；不要为每张卡片发 IPC、重复扫描文件或把临时进度写进素材数据块。卡片卸载不等于任务结束，任务恢复仍归实际服务。自定义布局需要使用标准 `ResourceCard` 才能自动呈现这些角标。

## 示例与验证

[动态集合示例](../../examples/collection-surface/README.md)仅使用公共 SDK，可拷贝到宿主外独立开发。它通过一个窗口 Provider 提供前两项素材、临时范围及角标，不创建业务数据。独立文件编辑工程的对应实现位于 `view.tsx`：工作副本服务给出动态 ID，集合只负责呈现，输入规则和角标分别声明。

验证入口见[开发与验证](../development/开发与验证.md#公共集合页面输入与角标)。本批不新增核心或 MCP 写接口，不更改仓库／空间格式，不把编辑任务变成业务数据。

布局声明、每种布局独立恢复、本库新页面默认与缺失插件回退见[浏览布局](浏览布局.md)。业务页面若有明确的呈现需求，应继续显式给出 `layout`，不让仓库默认改变该业务意图。
