# 设置导航与 UI 命令：前端及插件接入

设置由独立双栏浮层呈现，仓库窗口提供左侧快捷条、原生「显示」菜单与 ⌘P／Ctrl+P 命令面板。界面调用下面的公共服务，未改变仓库／文件空间格式、配置存储或 MCP。没有插件快捷键编辑器；后续更换外壳仍沿用相同契约。

## 文件与职责

| 文件 | 职责 |
| --- | --- |
| `src/plugin-api/ui/settings.ts` | 设置元信息、目录、导航、退出检查契约 |
| `src/plugin-api/ui/commands.ts` | UI 命令声明、来源上下文、命令会话契约 |
| `src/renderer/src/settings-controller.ts` | 每窗口导航协调器；无 React／标签页依赖 |
| `src/renderer/src/settings-catalog.ts`、`application-settings-catalog.ts` | 内置分类和插件分区的目录；应用入口不加载仓库插件 |
| `src/renderer/src/ui-command-service.ts` | 固定上下文、搜索、执行检查、防重复、释放会话 |
| `src/renderer/src/app/workbench-commands.ts` | 把既有工作台入口适配成命令，不重写业务 |
| `src/renderer/src/app/ui-host.ts` | 装配服务、固定来源页面的 host、设置呈现适配器 |

外部插件只导入 `@resource-manager/plugin-api/ui/settings`、`ui/commands`、`ui/contracts` 等公开入口，不能引用上表中的宿主实现。这些模块不引入另一份 React 或运行时注册表；命令模块另导出宿主标准图标名列表 `QUICK_ACTION_ICONS`。

## 设置贡献与目录

```ts
const plugin: UiPlugin = {
  id: 'demo',
  settingsSections: [{
    id: 'demo.connection', order: 100, scope: 'local',
    title: '模型连接', description: '地址和模型名称',
    keywords: ['API', 'model', '连接'],
    Component: ConnectionSettings
  }]
}
```

`title / description / keywords` 可选。旧包不填标题时回退到插件名称；`ui-registry.settingsSections()` 保留组件、原存储范围，并自动附加 `pluginId / pluginTitle`。按插件归组导航，不要求一个插件只能有一页，也不让插件重复声明自己的来源。

`host.settings.pages()` 返回不含组件的目录。`SettingsPage.scope` 是页面所在的 `application / library` 范围，`storage` 才是贡献声明的 `local / library` 保存归属。不要混用这两个字段：本机模型配置可以在当前仓库插件设置里显示；`library` 应标为“保存在仓库”，不承诺自动同步。凭据继续由 secrets 接口保存，设置服务不存任何字段值。

搜索首版使用标题、插件名称、说明和关键词过滤目录，不自动索引任意 React 表单字段。目录只包含实际启用、协作依赖满足的贡献；停用不清配置，也不为读取其设置自动运行停用插件。

应用贡献共用元信息，但仍使用 `ApplicationUiHost`，只有设置导航、服务调用及目录选择，不拥有 `core`。本批没有开放第三方应用级插件装配；外部插件仍按仓库运行。

## 定点打开

使用新服务的包声明 `uiFeatures: ["settings-navigation-v1"]`：

```ts
await host.openSettings({ section: 'demo.connection' })
await host.openSettings({ scope: 'application', section: 'appearance' })
```

`host.openSettings` 是带窗口提示的便捷入口；`host.settings.open` 返回同样的 `Promise<boolean>`，呈现者可自行显示拒绝原因。目标不存在、范围不适用或不明确时抛错，不悄悄跳到另一页。`false` 表示导航被拒绝／已有导航在处理；从 `getSnapshot().blockedReason` 取原因。

旧 `host.openTab('settings', { section, scope })` 已转发到同一服务，主菜单与开发提示入口也复用它。每个仓库会话／开始窗口只显示一份独立设置窗口，通过稳定 section ID 定位分类；再次打开会激活已有窗口。旧工作区中的 settings 标签转为一次打开请求，不再作为中央标签恢复；原素材页面与选择保留。

当前内置目录：

| 范围 | section |
| --- | --- |
| 当前仓库 | `import`、`plugins`、`plugin-presets`、`development`、`maintenance` |
| 应用 | `packages`、`appearance`、`editors`、应用插件贡献 ID（MCP 等） |
| 启动器应用设置 | 同上，另有 `spaces`；无仓库目录 |

## 表单退出与保存

`settings` 不规定自动保存还是显式保存。表单提供状态与离开检查，保存仍走插件自己的公共业务／服务入口：

```ts
const current = useRef({ dirty, saving })
current.current = { dirty, saving }
useEffect(() => host.settings.registerGuard('demo.connection', {
  state: () => ({
    dirty: current.current.dirty,
    busy: current.current.saving,
    message: '请先保存模型设置'
  }),
  beforeLeave: async (intent, signal) => {
    // 可以先询问保存／放弃／继续编辑；取消返回 false。
    // 只在确认后保存，处理失败抛错。
    await savePendingChanges(signal)
    signal.throwIfAborted()
    return true
  }
}), [host.settings])
```

`state()` 同步、无副作用；`busy` 阻止离开；`dirty` 且无 `beforeLeave` 默认阻止。回调返回 `true` 必须表示已保存、已明确放弃，或呈现者保证保留草稿后允许切换。组件注销 guard 不代表保存，不得通过卸载自动提交或丢弃。

现有插件选择页在分类间保留表单；有未应用选择时阻止关闭，显式应用发起的重载继续原流程。设置现由非模态原生窗口承载，仓库分类及已访问的应用分类隐藏时继续保留表单；不再依赖工作区标签缓存。导入配置、插件选择、插件组合编辑和安装确认分别登记退出检查。其他插件的手动保存表单仍需自行登记 guard，容器无法推断业务草稿。

当前设置窗口接线约定：

1. 替换 `useUiHost` 创建 `SettingsController` 时的 `present(target)`，由它打开／定位设置窗口；启动器沿用同一控制器，目录只含应用项。
2. 左侧分类调用 `settings.open(target)`。用 `useSyncExternalStore(settings.subscribe, settings.getSnapshot)` 读取稳定快照；`target` 是最近成功的目标，**不是显隐状态**，设置窗口显隐由呈现者拥有。不要反过来监听 target 再调用 open。
3. 关闭按钮、Esc、系统关闭和 Cmd/Ctrl+W 都先 `await settings.beforeLeave({ reason: 'close' })`，仅 true 才关闭；错误或 false 保留页面。导航本身已检查，不重复检查。
4. 设置外壳只挂载当前分类时，务必在检查完成后卸载旧表单；选择“保留草稿”就必须继续持有其状态。插件启停的草稿与业务表单保存分开。
5. 把现有设置标签 `beforeLeave` 对应的检查迁到窗口退出／重载准备流程，沿用 AbortSignal；移除标签呈现后，不能连这条检查一起删掉。处理旧工作区中的 settings 标签为一次打开请求，保留原素材焦点。
6. 打开设置不清选择、不替换工作区；主窗口仍可操作，其导航不再关闭设置。设置窗口内的 Esc、输入法和菜单由外壳独立处理。不要把宿主模型的 busy 当作全局业务保存按钮。

## 原生设置窗口与插件适配（2026-11-14）

- `settingsSections`、`host.settings`、`host.openSettings` 的契约和配置保存位置不变。仓库插件仍只装配一份；设置画面由同一个 React 运行环境通过 Portal 放入同源空白窗口，不重新创建 `UiHost`、核心连接、草稿或后台服务。
- `SettingsContent` 拥有设置表单；`SettingsWindow` 为它提供局部弹窗／通知；`AuxiliarySurface` 只处理显示文档、样式和主题同步、窗口生命周期。插件应使用传入的 `host.showDialog`、公共 `Overlay` 和设置退出守卫，不能假设全局 `document` 就是组件所在的文档。直接操作 DOM 时从元素的 `ownerDocument` / `defaultView` 获取目标。
- 每次新建设置窗口时，以所属主界面的中心定位，并限制在该屏幕可见工作区；随后独立移动，不随主窗口移动。再次调用打开只激活现有设置，不改变用户摆放。会话归属仍由宿主管理，不使用原生父子窗口关系。
- 系统关闭与窗口内关闭进入同一设置守卫。主窗口退出／仓库重载也先检查设置，失败保留原环境；成功后才关闭附属画面。仓库重载记住设置分类并重新打开；表单草稿仍需先保存或明确应用，不把草稿私自写进恢复记录。
- 菜单撤销／全选等作用于获焦小窗，素材删除、新建、分屏等工作台命令不会透传。打开主窗口的其他页面不丢弃设置表单。原生文件选择器和上下文菜单跟随当前附属窗口，业务 IPC 仍由所属窗口发起。
- 开始界面也使用独立设置窗口，仅展示应用设置。其关闭和应用退出经过表单守卫；套件安装后返回起始方案仍保留建库表单。
- 受控窗口当前包括 `settings` 与普通内容组，后者的移动、存档和关闭见[内容小窗](工作区布局.md#内容小窗2026-11-14)。不接受任意 URL、插件脚本或外部容器注册；不把显示窗口当作第二份业务运行环境。设置保持自身关闭／输入规则，主工作台的关闭标签命令不会因为设置窗口开着而误关设置。

## 插件 UI 命令

包声明 `uiFeatures: ["ui-commands-v1"]`，在 `UiPlugin.commands` 贡献命令：

```ts
commands: [{
  id: 'demo.playPause', title: '播放／暂停', category: '播放器',
  keywords: ['play', 'pause'], context: 'window',
  run: async (_context, host) => { await host.service('demo', 'toggle') }
}]
```

ID 使用插件命名空间，重复声明拒绝装配；`needs` 沿用现有可选协作过滤。`category` 缺省用插件名。`when(context)` 决定命令面板中的显示，`enabled(context)` 返回 true／false／禁用原因字符串；两者只能读同步状态，不做查询或网络调用。

`context` 默认为 `window`。`page` 要求来源页面仍存在且没有更换内容身份；`selection` 进一步要求原选择非空且完整存在。执行前再次检查，素材已进回收站等业务适用条件仍由命令或既有 action 校验。`CommandContext` 固定页面 ID／类型／查询和选中素材 ID，运行时深冻结；不会随着命令搜索框获得焦点或用户切换页面而改变。传给命令的 host 也绑定原页面及打开位置。

`accelerator` **仅展示已经实际绑定的键位**，不会注册快捷键。首版没有插件自定义快捷键编辑器、冲突仲裁或终端执行接口。UI 命令也不自动暴露给 MCP；后端 commands／operations／queries 保持原有职责和权限。

## 常用操作快捷栏（quick-actions-v1）

最左窄栏固定提供「全部视图、新建文字、导入文件、命令面板」，底部保留仓库切换、布局与工具、设置和运行状态。这里执行动作，不显示工具位置或当前选中工具，也不按启用插件数自动增加入口。

- 新建文字、导入面向**当前仓库**，不继承中央页面的查询条件，不给新内容自动附加视图分面；中央正在显示工具或回收站时仍可使用。新建打开文字编辑页；导入保留当前页，沿用仓库导入策略和结果反馈，取消文件选择不写入。
- 中央页面原有的创建、拖入和导入入口仍按该页面的输入声明和准入规则处理。命令面板中分别用「常用操作」与「创建与导入」区分两种范围。
- 全部视图优先定位已打开的「全部」页并保留其临时状态；没有时才新开，重复点击不制造同名标签。
- 固定命令 ID：`host.view.all`、`host.library.create-text`、`host.library.import`。命令面板仍由鼠标或 Cmd/Ctrl+P 打开，不为弹出面板再造递归命令。
- 工具通过组菜单「添加或打开工具…」、命令面板、底部布局与工具菜单打开。`host.showView(id)` 沿用已有实例和实际位置，不因快捷栏点击重排或复制工具。

插件需明确加入快捷栏，只在已有命令上补充一小段声明，同时声明 `uiFeatures: ["ui-commands-v1", "quick-actions-v1"]`：

```ts
commands: [{
  id: 'demo.open', title: '打开示例工具', context: 'window',
  quickAction: { icon: 'tool', order: 100 },
  run: (_context, host) => host.showView('demo.panel')
}]
```

`quickAction: {}` 也合法，默认 `tool` 图标、顺序 100；同序按命令 ID 排序。标准图标可选 `grid / text / import / command / tool / search / book / tag / music / chat / clock / layout / history`。用户无需配置图标；不开放自定义渲染、用户固定命令或任意分组编辑器。只接受 `window` 命令（省略 context 也视为 window），依赖某个页面／选中项的动作放在上下文菜单或命令面板，避免把快捷栏变成随焦点闪动的工具目录。

仅实际启用且 `needs` 满足的贡献会出现；声明与图标由宿主校验。快捷栏入口位置稳定，点击时通过命令会话复核 `when / enabled`；拒绝或失败显示原因，不执行其他动作。停用插件撤下入口，不清其数据与布局存档。完整示例见 `examples/tool-views` 的「布局示例」命令，未声明的草稿工具依然可以从命令面板打开。

定点执行可使用 `host.commands.createSession({ ids: ['demo.open'] })`（需要 `quick-actions-v1`），会话只允许执行这些 ID。静态命令不为执行一次快捷动作读取全库保存视图或当前选择；`host.saved-view.*` 和 `host.action.*` 仍需查询。省略参数保持完整聚合，错误处理及 dispose 规则与下节一致。

## 前端命令面板接入

```ts
// 在打开面板、转移焦点之前捕获；每次打开创建新的会话。
const session = host.commands.createSession()
const items = await session.list()
const matches = await session.list('模型')
// 需要主动刷新目录时：await session.refresh()
try {
  await session.execute(chosen.id)
} catch (error) {
  host.notify(String(error))
} finally {
  session.dispose()
}
```

名称／分类／关键词按忽略大小写的多词包含匹配；排序、模糊匹配和拼音库可由前端另做。第一次聚合会查询一次保存视图和选择项；输入搜索词不重复查库。失败可重试，刷新不改变原上下文；要采用新选择应新建会话。

取消面板时 dispose。选中命令后可以先隐藏面板，但不要在隐藏清理中提前 dispose 正在执行的会话；执行回调结束后再释放。会话取消和窗口销毁会拒绝迟到的读取／执行前检查；已经进入的业务动作不因关闭面板被回滚。窗口内共享执行锁防重复触发；异步命令必须返回其 Promise 才能覆盖整个回调。旧的 void UI 动作仍沿用自己的结果提示，execute 完成不表示后台加工全部完成。

公共目录已聚合：预设／保存视图、已打开页面、创建与导入、当前选择动作、侧栏工具、工作台布局、插件组合入口、设置分类和插件命令。创建与导入复用原准入流程；素材动作执行前重新读取并匹配原选择。布局可直接应用，插件组合只进入“预演→确认→应用重载”，不做暗中切换。原生输入框撤销、页面按键与菜单路由仍保留，不把键盘事件全交给命令面板。

命令服务限当前仓库窗口；启动器本批只提供应用设置导航。没有自动聚合内容选区 actions，也没有把 DOM 选区或聊天草稿复制进命令上下文；需要选区协作仍使用已有公共选区通道，后续由具体场景扩展。

## 验证与交接边界

运行 `npm test -- tests/integration/workbench-services.test.ts tests/integration/ui-api.test.ts`；构建后运行 `node tests/electron/workbench-services-check.mjs`。Electron 流程建立临时外部 UI 包、独立用户目录和临时仓库，验证真实装配、设置导航与拒绝关闭、焦点变化后的原选择命令、撤销及过期来源拒绝。同一场景还验证分类显隐、导入草稿关闭／重载拒绝、Tab／Esc 与焦点恢复、原生菜单不操作背景素材，以及命令分组后高亮与回车一致。`package-install-check.mjs` 覆盖嵌套安装确认与统一应用重启。仓库窗口提供快捷条、原生菜单与 ⌘P／Ctrl+P；模态操作进行中不再打开另一份命令面板。

快捷栏验证沿用同一 Electron 流程：筛选页内仓库级新建／导入、取消不写入、全新 SVG 的原生加工、插件入口失败反馈及重复定位全部页。普通工具重开与中央工具焦点场景另由 `sidebar-layout-check.mjs` 和 `--context` 覆盖。完整验证范围见[开发与验证](../development/开发与验证.md#常用操作快捷栏)。
