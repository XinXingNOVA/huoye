# 层级查询与独立标签插件

宿主提供通用 `subtree` 字段条件，不认识 Math、标签分组或标签树的业务。业务插件登记索引关系、维护不变量；查询在执行时沿当前关系展开，读取、计数、分面、保存视图与 MCP 共用同一条路径。

```ts
const condition = {
  op: 'subtree', kind: 'tags', field: 'values', value: 'Math',
  tree: { kind: 'tag-tree.node', key: 'tag', parent: 'parent' }
}
```

目标字段为文字索引，可为列表；关系 key/parent 必须为单值文字索引。关系节点只取活跃记录，递归使用 UNION 去重，畸形循环也能终止。根值总包含在分支中；多个条件仍取交集。关系定义缺失或停用明确报错，不能静默匹配全库／只匹配根。所有字段名和值都通过参数绑定，插件不能注入 SQL。

`query-subtree-v1` 是新的 core/UI 能力标记，旧宿主拒绝新包。现有 eq/in/range/empty 含义不变。通用条件编辑器显示并保留层级条件、允许移除，调整具体关系交给贡献插件。准入只推导根值写入，并保留动态条件做正式检查；导入预检保守列为待确认。

同字段的多个界面用 `FacetDef.id` 区分 React 实例，使用插件命名空间；新包声明 `facet-identity-v1`。不新增第二套筛选状态，仍用 TabApi 的 filters/facetQuery/toggleFilter。toggleFilter 按完整条件（包含 tree）比较，重复切换必须移除；普通点击替换同字段临时条件，⌘/Ctrl 点击叠加或取消。恢复页面时合并完全重复的临时条件，保留不同关系与基础视图规则。

## 当前交付

- tags 2.0.1：保留共享 tags.values、详情、导入和打标操作，旧 tagGroups 定义只为接续保留。
- tag-groups 1.0.1：独立管理 tag-groups.groups，原地整理和轻量胶囊；旧分组需点击“导入旧分组”显式接续，不自动回退旧备份。
- tag-tree 1.0.1：独立管理 tag-tree.node，层级整理与动态分支查询。第一版最多 500 节点，标签键仍是原字符串，不提供全局改名；不把父标签写到素材上。

两个业务包可同时安装／启用，也可只启用一个，都依赖 tags。先更新宿主，再把三个包批量安装，统一选择 tags 2.0.1 与需要的业务包后应用重载。不要把新分组包与 tags 1.x 混用。插件源码、文档与产物各归独立工程；公共契约由 tags/CONTRACT.md 发布，使用方携带版本快照。

旧 tagGroups 备份仍是 COMPAT，由基础 tags 拥有。自动读取回退已移除；import_legacy_groups 显式复制最早备份且禁止覆盖现有目录，撤销导入回到空目录。停用／卸载保留数据；显式清理分别按各插件归属进行，见[插件数据生命周期](插件数据生命周期.md)。
