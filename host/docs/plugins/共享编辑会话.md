# 共享编辑会话

2026-11-02。首个接入对象是内置文字的数据块正文。公共入口 `host.editing`，类型来自 `@resource-manager/plugin-api/ui/editing`；外部包声明 `uiFeatures: ["shared-editing-v1"]`。若开放多视图，还应声明 `page-instances-v1`。

## 归属与范围

同一仓库窗口中，`插件:字段:素材身份` 对应一份文字草稿、底稿版本、保存状态、冲突与编辑撤销栈。页面 ID 不参与身份。文字页、详情栏等可观察同一会话；光标、滚动、阅读／编辑模式仍按页面保存。普通打开复用已有页，标签右键“在另一组新建此内容的视图”明确新增投影。

本接口处理字符串草稿，适合正文、Markdown、代码等；不替代任意对象的编辑事务。它不是跨应用、跨电脑协作系统，也不替插件提供数据库写权限。文件发布仍走公共文件编辑协议。

会话不随 React 卸载保存或销毁。脏草稿持续保留；干净且没有观察者的历史会话缓存保留约 64 份，淘汰后编辑撤销栈不再保留。单会话撤销栈最多 100 次、约 200 万字符（至少保留一个历史值），接入输入意图后按连续输入／删除与明确操作边界合并；普通 `change(text)` 仍是一次独立编辑。重启不恢复撤销栈。

## 插件接入

```ts
const key = `my-plugin:body:${id}`
const session = host.editing.open(key, {
  text: block.data.content,
  revision: block.seq
}, async (base, text) => {
  return await host.core.run('my-plugin', 'saveBody', {
    id, expectedRevision: base.revision, text
  }) as { accepted: boolean; current: { text: string; revision: number } }
})
```

`revision` 是非负、单调递增的权威版本号。插件必须保证同 key 使用同一文档和同一保存语义；首次绑定的保存适配器不应捕获组件局部草稿、目标页或变化中的权限。会话在一个窗口内共享，适配器使用稳定的 `host.core` 与内容身份即可。

- React 用 `useSyncExternalStore(session.subscribe, session.snapshot)` 观察；快照只读，不直接修改。
- 数据订阅得到新版后，在 effect 中调用 `observe({text, revision})`。干净草稿跟随新版；脏草稿遇到不同新版则进入冲突。
- 输入调用 `change(text)`；800 ms 后自动尝试保存。`save()` 可主动提交并等待，串行合并并发保存；保存期间继续输入仍保留，并在前次完成后提交。
- 输入框挂载后调用 `host.editing.bindInput(element, session)`，卸载调用返回的解绑函数，应用原生菜单的撤销／重做进入同一历史。组件自己的键盘事件也需拦截并交给会话。
- 原生 textarea／文本 input 可使用 `bindInput(element, session, {syncChanges:true})`：宿主监听原生输入、光标移动和输入法事件，直接更新会话并提供合并所需的意图；组件的重复同值 `change` 不再记历史。该选项默认关闭，不改变旧插件的输入处理。接入时同时声明 `shared-editing-v1` 与 `edit-history-v1`，并让该适配器负责原生输入写入，不再在组件内另做一次不同内容的变换。
- 编辑撤销／重做调用 `undo()`、`redo()`，多个输入框共用；不要依赖各 textarea 的原生撤销栈。仓库撤销属于已提交数据，作为新的权威内容进入 `observe`。
- `save()` 失败拒绝 Promise，状态保留错误和草稿。自动保存不无限重试；提供显式重试入口。
- 冲突时展示双方内容，再由用户选择 `resolve('remote')` 或 `resolve('draft')`。后者以用户看到的版本为新基线，再次条件保存；不是强制覆盖。
- `discard()` 明确丢弃本机未保存草稿，不修改仓库；正在保存时不可丢弃。适用于素材已删除、无法写回等情况，界面应允许先复制草稿。

**后端条件保存不可省略。** 必须在同一个命令事务中：检查素材有效、核对当前块版本、写入并返回新版本。版本不同返回 `{accepted:false,current}`；其他错误抛出。仅在前端先读后写会留下竞争窗口。参考 [文字实现](../../src/plugins/text/lib/save.ts) 与 [前端适配](../../src/plugins/text/session.tsx)。命令是否暴露成 MCP operation 由插件另行声明，本次未新增外部写工具。

## 撤销分组策略（2026-11-02）

- 同一输入框、同一位置连续插入字符合为一段，空白或常用中英文标点结束当前词句；换行另算一步。
- 连续退格、连续向前删除分别合并，改变删除方向或切回输入开始新的一段。
- 两次输入间隔超过 1 秒，或一段连续输入超过 5 秒，开启新段，避免整篇文章只剩一次撤销。
- 移动光标、点击定位、失焦、换到另一个页面或详情栏编辑，都打断合并。即使之后移回原位置，也不会粘到上次操作上。
- 粘贴、剪切、选区替换、按词删除、程序化插入链接等各自独立，不按字符串相似性猜测合并。
- 一次输入法组合的候选变化直到确认合为一步，不受上述停顿限制；取消组合回到原文不留空步骤。组合期间暂停自动保存候选字串，结束后恢复保存；未确认时的撤销交互不改动共享草稿。
- 撤销／重做打断当前合并，撤销后继续输入清除旧重做分支；保存成功本身不拆分编辑段。它与仓库的持久操作撤销仍是两个层次。

自定义编辑器也可传 `session.change(text, {source,inputType,before:{start,end},after:{start,end},composition?})`。`source` 是稳定的输入实例身份，`inputType` 沿用浏览器意图（如 `insertText`、`deleteContentBackward`），`before`／`after` 是这次编辑前后的 UTF-16 选区位置。宿主核对相邻插入／删除及位置连续性后才合并；选区替换或无法判断的事件独立记录。`composition` 是一次组合过程的唯一标识，确认、取消后调用 `breakHistory()`。移动光标、失焦也应调用此方法。未提供输入意图的 `change(text)` 保持旧行为，便于批量替换与其他插件渐进接入。

不引入额外撤销工具栏，也不更换编辑器或加入多人协同算法。当前恢复内容与各视图局部光标分开管理，撤销内容不会把其他视图的光标拉到操作来源页。

## 生命周期与恢复

宿主把未保存的 `{base,text}` 放在本机工作区 `drafts` 中，按仓库 ID 保存；布局与草稿使用同一快照节奏（约 400 ms 合并），不是仓库业务块。强杀只保证最近一次成功快照。正常关闭／重载先落快照，等待页面回调及已绑定会话保存，失败保持窗口，不宣称已保存。

插件页面应在静态 `beforeLeave` 中通过 key 找到会话并等待 `save()`，不能用组件 cleanup 冒充页面结束。恢复后尚未挂载的页面可先读取权威数据并重新绑定适配器，再保存；见文字 reader 的实现。隐藏、移动、冻结不触发额外保存；自动保存计时仍会继续。

恢复草稿时先与仓库比较；底稿已变化则显示冲突。停用插件遗留、尚未重新绑定的草稿保留在本机，不由宿主猜测写入方式或自动清除。它们在重新启用插件并打开对应内容后继续处理。底稿与正文含用户内容，因此应用配置备份也应按个人数据保管。

## 文字界面反馈

正常输入、等待自动保存、保存中、已保存都不显示草稿工具条；撤销／重做使用编辑快捷键和应用菜单。保存失败或冲突才在当前区域角落显示“查看处理”，点击展开重试、查看双方内容或丢弃草稿。提示与处理层不占正文布局，重试期间保持提示，成功后收起。素材已删除／无法写回时仍可查看和复制草稿。

## 文字首批边界

- 仓库文字块：阅读投影实时显示草稿，文字页和详情栏共享编辑、自动保存、撤销与冲突处理。局部光标／滚动随各页存档；字数、阅读正文按草稿显示，搜索索引与仓库列表仍依据已提交数据。
- 未保存正文暂停摘录／批注选区入口，避免持久锚点引用尚未提交的文字。
- `.md`／`.txt` 原文件：可多处阅读，同一窗口同一文件一次只挂载一个编辑器；结束该编辑后其他视图可接手。草稿与发布回执沿用既有流程，显式发布版本，不加入正文数据块的自动保存。后台发布的冲突防护仍由文件编辑协议负责。
- 本批不是富文本编辑器、CRDT、自动三方合并或系统级文件锁。其他插件需主动接入，不能把“已提交数据订阅”当作共享草稿。
