# 外部本机服务：持续调用与本机存储

核对日期：2026-10-21。已开放给可信 `.rmplugin` 的仓库级服务，SDK 为 `@resource-manager/plugin-api/local-service`。与内置应用服务／MCP 的区别见[服务插件 API](服务插件%20API.md)。完整可打包源码见[服务示例](../../examples/local-service/README.md)。

## 范围与职责

这是服务生命周期、通信和存储机制，不是 AI 接口、后台任务队列或持久工作流。服务与界面显示分离，持续调用不跨应用退出恢复；宿主不知道增量数据代表模型文字、同步进度还是其他业务。

| 部分 | 职责与归属 |
| --- | --- |
| core | 持久数据定义、同步短事务、查询与命令；不在事务中等待模型或网络 |
| UI | 交互、临时业务状态、消费结果；通过现有核心接口保存有价值的结果 |
| service | 本机异步请求、协议解析、取消与清理；不得直接打开仓库数据库 |
| 宿主 | 装配正确版本、按库启停、持续通道、本机配置与凭据保护 |

首版复用现有主进程 ServiceRuntime。外部服务仍是可信 Node 代码：导入边界和命名空间用于维护，不是不可信代码沙箱，也没有进程隔离、强制终止同步死循环或保护资源免受恶意插件访问的保证。网络请求由服务自行实现；没有放开界面 CSP，也没有新增通用网络代理或跨插件事件总线。安装前仍需信任包来源。

## 声明与装配

```json
{
  "id": "example-service",
  "title": "服务示例",
  "description": "演示持续调用",
  "author": "作者",
  "version": "1.0.0",
  "apiVersion": 1,
  "entries": { "service": "./service.ts", "ui": "./ui.tsx" }
}
```

只声明 service 也合法；core／UI 均可选。构建生成 `service.mjs`，允许 Node 标准库，纯 JS 依赖随包打入；不接收 Electron、SQLite、React、MCP SDK、宿主私有实现、原生模块或安装脚本。仍不开放外部应用级入口、`executables`、`required` 和任意迁移。旧宿主会因未知 service 入口拒绝安装，使用前先更新并重启宿主。

安装只检查并存储包，不执行服务代码。按本仓库实际启用集合和确切包摘要加载，每库调用一次 `start`；停用、关库、重载时取消信号并清理。开发目录应用和正式包选择沿用原有统一重载流程。模块可能按摘要缓存并被多个仓库复用，实例状态必须放在 `start` 内；模块顶层不得发请求、创建计时器或保存库状态。

加载或启动抛错记录为服务失败，调用返回明确错误，设置中显示失败原因；其他服务和仓库数据仍可用。已装配的 core／UI 不因 service 启动失败而被撤下，UI 应处理不可用状态。服务不自动重试，修复后重载。

## 服务实现

```ts
import type { LocalServicePlugin } from '@resource-manager/plugin-api/local-service'

export const plugin: LocalServicePlugin = {
  id: 'example-service',
  start(ctx) {
    // ctx.library 为这次仓库身份；没有数据库、MCP 凭据、窗口或任意 CoreApi。
    return {
      invoke(method, input) {
        // 插件校验方法和参数；适合读取或保存少量配置。
        if (method !== 'settings') throw new Error('未知方法')
        return { endpoint: ctx.settings.get('application', 'endpoint'),
                 hasKey: ctx.secrets.has('application', 'apiKey') }
      },
      async stream(method, input, { signal, emit }) {
        // 插件自行校验输入并发起请求，网络请求务必传 signal。
        // response = await fetch(插件已校验的地址, { signal, ... })
        // 每次只能有一段未确认数据；务必逐段 await。
        await emit({ progress: 0 })
        signal.throwIfAborted()
        await emit({ progress: 1 })
      }
    }
  }
}
```

`ctx.signal` 表示整个服务生命周期；持续调用参数中的 `signal` 还包含该请求的主动取消。`ctx.onDispose(fn)` 登记清理函数，启动失败或停止时逆序执行；运行期间新资源也必须立即登记。请求中的 reader、计时器等用 `try/finally` 释放。普通 invoke 没有单次取消协议，长时间工作应使用 stream。

## 界面消费与有效期

```ts
const controller = new AbortController()
try {
  await host.streamService('example-service', 'generate', input, {
    signal: controller.signal,
    onData(value) { /* 校验、更新插件自己的运行状态 */ }
  })
  // 正常完成；此时按业务需要调用 host.core.run 保存结果。
} catch (error) {
  // 主动取消、服务停止与异常均拒绝 Promise；不要自动重试付费请求。
}
// 停止按钮：controller.abort()
```

`host.service(plugin, method, input?)` 保持普通的一次返回；`host.streamService(plugin, method, input, options)` 只做一次持续调用。它没有持久 taskId、结果查询、自动重试或恢复机制。

- 先建立端口、消费者发送 ready 后才开始执行，不丢首段；每段带递增序号。
- `emit` 直到 UI 的 `onData`（可返回 Promise）消费完成才返回。宿主同时仅保留一段待确认数据，不保存完整答案；插件不得并发调用 emit。
- 输入仅接受 JSON，最多 1 MB；每段最多 64 KB，JSON 嵌套最多 30 层。同仓库最多 16 条连接；连接就绪和单段消费等待最多 30 秒，超时关闭并取消。网络请求自己的超时仍由插件设定。
- `onData` 抛错会关闭通道并取消服务请求。abort、页面断开、关库和重载均传递取消；旧实例的迟到输出不再送到新界面。
- 隐藏面板或切标签本身不取消；任务应由持续挂载的面板或 `windowProviders` 持有，拥有者卸载时 abort。不要仅因 `active=false` 就取消需要继续的会话。
- 网络请求必须配合 AbortSignal。对不响应取消的可信插件，宿主停止接收结果，不等待该持续调用；没有强制杀死其代码的保证。同步阻塞、永不返回的 start／普通 invoke／清理仍可能影响主进程或关库。
- 普通设置调用和持续调用都绑定真实顶层仓库窗口，不接受调用方指定另一仓库路径。服务方法须自行验证参数和整理错误，不把密钥或包含密钥的 URL 写进异常、日志和返回值。

应用退出或重载后不自动续接任务。对话历史、检查点和中断标记由插件保存为仓库数据；不应每个字符都创建一次核心写入或撤销记录。选区引用应在点击时验证并复制，不能把临时 Selection 当作任务的长期上下文。

## 本机配置与凭据

服务获得的存储已按插件 ID 划分，不能通过参数选择另一个插件的存储。API 的 `scope` 必填：`application` 在该本机用户配置内跨库共享，`library` 按库路径隔离；两者都不在仓库文件夹，不随仓库导出或进入撤销历史。

```ts
ctx.settings.get('application', 'profile') // LocalValue | undefined
ctx.settings.set('application', 'profile', { endpoint: 'https://example.invalid', model: 'example' })
ctx.settings.remove('library', 'lastProfile')

ctx.secrets.available()                    // 系统保护是否可用
ctx.secrets.has('application', 'apiKey')    // UI 可展示“已配置”
ctx.secrets.set('application', 'apiKey', key)
ctx.secrets.get('application', 'apiKey')    // 只在服务里用于请求，不返回 UI
ctx.secrets.remove('application', 'apiKey')
```

配置格式、校验和版本接续属于插件。不同包版本共用同一插件命名空间，应保持配置兼容或使用明确版本键。每次读取当前文件，不缓存旧副本；写入是本机主进程中的同步读改写与原子替换。多库调用按执行顺序生效，当前没有配置订阅或跨进程锁。

每个作用域的配置／凭据文件分别最多 256 KB、100 个键，键为最多 80 字符的字母数字及 `_.-`，禁止路径和原型保留键；单个密钥最多 16384 字符。设置只接受有限深度的 JSON 数据，不是存放对话或大缓存的容器。旧服务停止后持有的存储接口失效。

凭据使用 Electron 的系统保护能力加密，Linux 的 basic_text 后端视为不可用；不能保护时明确拒绝保存，不自动降为明文。配置文件损坏或解密失败保留原记录并报错，不静默重置。UI 设置页由插件自己提供，只回传是否配置等状态。该接口不构成对可信 Node 插件的安全隔离。

停用或卸载保留本机配置和凭据，便于重装接续。插件仍可提供删除单个凭据的入口；2026-11-14 起，宿主设置也支持停用后按插件、作用域显式预览清理，不需加载服务或解密密钥。见[本机数据清理](插件数据生命周期.md#本机数据的范围与清理)。纯 UI 偏好请使用[公共界面状态](插件本机界面状态.md)，无需额外声明服务。
