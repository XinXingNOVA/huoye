# 打开方式与系统查看

当前范围：2026-11-05。打开方式决定如何使用素材，打开位置决定在哪个标签组使用，两者独立。仓库／文件空间格式不变；[受控文件编辑](../development/受控文件编辑.md)另设明确入口，不改变系统查看的语义。

## 使用

素材右键 → **打开方式…**，列出已启用插件中所有匹配的打开器，以及宿主的数据详情。常见文档、图片、音视频和电子书还提供**系统默认应用（查看副本）**。选择后可在当前组或另一组打开；播放等回调型打开器不一定创建页面，系统查看也不创建空分屏。

文件素材可勾选“记住为此仓库 .扩展名 文件的默认方式（仅本机）”。规则按仓库身份和小写扩展名保存在本机 localStorage，不写素材块、不修改系统文件关联，也不随仓库目录搬到其他机器。纯文字等没有文件类型的素材先只支持本次选择。

双击或普通 `host.open` 的顺序为：有效的默认选择 → 插件 priority 从小到大匹配 → 数据详情。插件停用、打开器移除、该素材不满足 match、目标标签页类型不可用时，自动回退，但保留原偏好；重新启用可恢复。选择“自动选择”并勾选记住会清除此类型的偏好。明确指定已不可用的打开器会报错，不悄悄改成另一种。

“数据详情”入口和 `host.openData` 始终直接打开数据详情，不受默认选择影响。已有页面仍按其页面类型的身份、数量和生命周期规则复用；切换打开器并不把所有页面合成一个实例。

## 插件声明

需要新能力的外部插件在 `plugin.json` 声明 `uiFeatures: ["open-with-v1"]`（与已有能力合并），旧宿主会拒绝未知能力。新增打开器提供稳定 ID 与可读标题：

```ts
opens: [{
  id: 'reader.read',
  title: '阅读器',
  priority: 20,
  match: view => !!view.blocks.body,
  tab: 'reader.page',
  params: (view, from) => ({ id: view.id, list: from })
}]
```

`id` 必须以本插件 ID 加 `.` 开头，全局不重复，跨插件版本保持含义；`id/title` 成对提供。`match` 仍按素材数据块判断，不改成仅按后缀判断。文件类型偏好不会绕过 match。多个打开器可同时匹配，priority 只决定自动选择顺序。

回调形式仍可用：`{ id, title, priority, match, open(view, host) }`。它适合播放、调起工具视图等入口；后续开页应调用 `host.openTab`／`openData`，位置会继承。转换、批量整理等加工动作仍使用 actions，不作为打开器堆进此列表。

旧外部包没有 id/title 时仍可自动匹配与本次选择，名称由插件名和标签类型补出；临时 ID 不持久化，不能设为默认。无需一次更新全部插件。宿主随附图片、PDF、文字、音频和视频打开器已命名；[工具视图示例](../../examples/tool-views/ui.tsx) 演示命名回调式打开器。

## 公共调用

```ts
host.open(id, source) // 默认方式
host.open(id, source, { opener: 'host.choose' }) // 用户选择
host.open(id, source, { opener: 'reader.read', group: 'other' })
host.open(id, source, { opener: 'host.auto' }) // 本次绕过默认偏好
host.open(id, source, { opener: 'host.data' }) // 同 openData
host.open(id, source, { opener: 'host.system' }) // 系统查看副本
```

`OpenOptions.opener` 只对 `host.open` 生效；`openTab` 已明确页面类型，不再选打开器。调用 API 不会修改默认偏好；由用户在选择窗口中明确保存。来源列表、发起组与另一组目标在请求时捕获，异步读取、选择和回调不会挪用后来获得焦点的页面。回调后续 `host.open` 继承位置，但不自动继承本次 opener。

## 系统查看的边界

主进程只接收素材 ID，重新从当前窗口的仓库核心取得文件块，通过文件存储层核验空间关联、固定内容版本与可用状态。打开本库**已接纳版本**，不越过本库接纳规则读取空间新版。仓库关闭／重载期间不再启动外部应用。

文件异步复制到应用用户数据目录的 `viewing-copies/view-…/`，保持正确扩展名；不使用硬链接。每次打开新建副本，外部程序修改旧副本不会污染下一次查看或空间版本。复制／系统启动失败会显示原因并清理本次副本。程序、脚本、快捷方式和暂未支持的格式不提供系统查看入口；这不是任意文件执行接口。

副本可能被外部软件编辑，**修改不会回写，也不会成为受保护的编辑草稿**；需要保留时应在外部应用另存。退出应用不立即删除副本，以免影响外部程序。每次应用运行首次使用系统查看时，清理超过七天的旧查看副本；被系统占用而无法清理的留待下次。大文件首次复制需要时间和额外磁盘空间。

此查看入口不选择指定外部程序，不监视保存、发布新版或回收修改；需要修改时使用素材菜单中的“编辑文件…”。`host.openExternal` 仍只打开 http/https 链接；本次不增加 MCP 启动本机应用的工具。
