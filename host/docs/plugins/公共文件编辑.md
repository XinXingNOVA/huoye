# 公共文件编辑与 MCP

2026-10-27，C2。仓库持有素材及业务数据，文件空间发布不可变版本；应用用例负责准备、发布和本库接纳。此接口不要求插件理解原件目录，也不把异步复制塞进同步数据块事务。

## 插件接入

外部 UI 插件声明 `uiFeatures: ["file-edits-v1"]`，从 `@resource-manager/plugin-api/files` 导入类型，通过 `host.core` 调用。旧宿主拒绝未知能力。可打包示例：[file-editor](../../examples/file-editor/README.md)。文字文件编辑与原内容副本入口也使用此协议；2026-10-28 已退出旧同步 `CommandContext.writeFile / renameFile / ensureLocalFile / isSharedFile`、`file.replace` 及 `file-copy-on-write-v1` 声明。同步 commands / operations 不允许 await 这条文件流程，后台插件若需调用须先讨论实际场景。

| API | 对象／作用 |
| --- | --- |
| `fileEditCapabilities(id)` | 仓库素材 ID；返回发布条件、不可用原因及已关联的新版独享副本目标 |
| `prepareFileEdit({id,destination,content,requestId})` | 异步复制／校验，仅准备草稿，返回 `editId/previewToken`、目标空间、名称、大小、哈希 |
| `commitFileEdit({editId,previewToken,requestId})` | 空间条件发布，再由当前仓库接纳；必须复用准备返回的凭据 |
| `discardFileEdit({editId,requestId})` | 放弃未发布编辑，不删除遗留字节；已发布不能放弃 |
| `discardFileEdit({prepareRequestId,requestId})` | 准备响应丢失时，按原准备请求放弃；与 editId 二选一，作用域保护相同 |
| `makeFileIndependent(id,spaceId,requestId)` | 异步复制当前原内容到明确选择的新版独享空间并接纳，需检查返回的 library 状态 |
| `cancelFileEdit(key)` | 准备期间传准备 requestId，提交期间传 editId；请求取消，不能撤销已提交结果 |
| `previewFileUpdate(id)` / `acceptFileUpdate(input)` | 已有空间新版的预览与本仓库接纳，沿用[版本契约](../architecture/文件空间.md) |
| `spaceFileHistory(input)` / `restoreSpaceVersion(input)` | 按空间文件身份读取历史，将历史内容发布为新版 |

`destination` 显式区分：

- `{mode:'publish'}`：原件必须已经是新版空间引用、本素材已采用空间当前版、仓库有 revise 权限。发布不改变文件身份，其他仓库按各自策略接纳。
- `{mode:'copy',spaceId}`：在已关联的新版**独享**空间生成新文件，让本素材改用副本。素材 ID、名称、笔记标签等业务数据保留；原件及其他仓库引用不变。旧格式来源已停止读取，也不能通过另存绕过；需使用归档工具处理数据副本。没有目标时先创建／关联独享空间，接口不会擅自选位置或创建空间。

`content` 为 `{type:'text',text}`（UTF-8，最多 4M 字符，只允许常见文字扩展名）、`{type:'file',path}`（本机绝对路径、同扩展名），或仅供 copy 的 `{type:'current'}`（宿主读取当前素材原内容）。不接受任意远程 URL 或原件内部路径写入。可带 `expectedPath/expectedSeq` 绑定编辑器最初读取的快照，准备前拒绝过期草稿。格式转换请另作新素材导入；内存二进制输出和后台服务编辑待具体案例。复制／哈希异步，短事务负责最终状态。

`makeFileIndependent` 现在返回 Promise，不能再把调用返回当作完成；同阶段重试保持原参数与 requestId。返回值统一为 `FileEditResult`，没有返回 void 的旧副本分支。省略 spaceId 时使用默认写入空间；默认空间不可用、是共享或旧格式时明确拒绝，不回退另选位置。界面和插件应显式选择能力列表中的新版独享目标。

```ts
import type { CommitFileEdit } from '@resource-manager/plugin-api/files'
const caps = await host.core.fileEditCapabilities(itemId)
if (!caps.publish.allowed) throw new Error(caps.publish.reason)
const prepared = await host.core.prepareFileEdit({
  id: itemId, destination: { mode: 'publish' },
  content: { type: 'text', text: editedMarkdown }, requestId: crypto.randomUUID()
})
// 显示名称、大小、修改范围；用户确认后提交。失败保留这份参数用于重试。
const commit: CommitFileEdit = {
  editId: prepared.editId, previewToken: prepared.previewToken, requestId: crypto.randomUUID()
}
const result = await host.core.commitFileEdit(commit)
// result.space 是已发布事实；result.library 是本仓库接纳结果，不能只看 Promise 成功。
```

宿主的[受控文件编辑](../development/受控文件编辑.md)提供工作副本、外部编辑与恢复，仍调用本协议。UI 插件声明 `file-working-copy-v1` 后调用 `host.editFile(itemId)`，直接创建／复用副本并打开；宿主负责反馈，用户从“编辑中”视图完成保存和清理。已有自定义编辑器无需改造。需要自定义任务界面时声明 `file-working-copy-service-v1` 并使用 `host.fileEditing`，见[公共工作副本服务](公共工作副本.md)。

原内容由公共 `host.url(file.path)` 读取，或已有读取 API 获取；不要把 `host.abs()` 的结果当作可写路径。

## 幂等、取消与恢复

每个新阶段使用新 requestId，同阶段失败重试保持参数和 ID；`file_edit_requests` 在文件编辑接口内拒绝跨阶段或跨目标复用。准备的请求签名包含内容／目标；已准备成功后重放返回历史预览，不表示草稿仍可提交。提交在发布前校验素材文件块 `seq` 和原引用，防止同路径回改、改名或换引用被覆盖；笔记等其他块的修改不阻止提交。空间执行时再次核对修订、模式与权限。

仓库 `file_edits` 保存准备快照、调用入口、关联凭据、空间草稿、提交意图与结果，不保存整段编辑正文；正文归空间草稿。空间仍使用 `version_drafts/version_receipts`。空间发布成功以后：

- `library.state=accepted`：文件快照与用例完成结果在同一仓库事务提交；清除并重建派生内容，保留原始业务数据。
- `pending`：本库接纳失败。保留空间字节；同参重试、刷新或重开只根据已存在的空间回执接续。
- `skipped`：素材已换引用、文件信息已变或被回收／删除。保留用户最新选择，不强行接纳。空间发布事实仍存在。

未发现空间成功回执时，重开绝不自动发布未确认意图。独立副本预先登记为已发现，接纳失败也不会被自动收录成第二条素材。发布／副本切换暂不进入普通仓库撤销；可恢复原件历史为新版。批注等定位保留，需要业务插件核对，不自动重定位。

取消只是请求终止复制／校验，最终提交后不会回滚。空间草稿和版本均保留完整字节，当前仍无通用空间草稿清理页；本机编辑状态仅管理自己创建的工作副本与提交快照。示例把确认参数保存在组件状态；重载后不恢复编辑器工作区，不代表框架自动清理了草稿。

本地 UI 的编辑与 MCP 的编辑使用不同作用域；各仓库再按关联凭据隔离。MCP 不能提交或取消 UI 的编辑。当前本地插件是可信代码，这不是抵御恶意插件直接写盘的沙箱，也没有承诺逐插件的存储隔离。

## MCP 调用

使用应用级配置；升级桥接代码后重连客户端。MCP 通过应用入口指定 `libraryId`，每个动作明确自己的目标；固定工具列表不随插件启停变化。旧单库协议已退役。

| 工具 | 目标及权限 |
| --- | --- |
| `get_file_edit_capabilities`、`preview_file_update` | 仓库素材 ID，只读 |
| `accept_file_update` | 仓库素材 ID，需要 organize；只更新本库引用 |
| `prepare_file_edit`、`commit_file_edit` | 准备面向素材、提交面向 editId；copy 需要 organize，publish 还需要两层 revise |
| `discard_file_edit`、`cancel_file_task` | 只管理本 MCP 入口的编辑／任务，需要 organize |
| `list_file_versions` | spaceId + fileId，只读，带分页与 revision 校验 |
| `restore_file_version` | spaceId + fileId + 历史 contentVersion，需要两层 revise；只发布，不强制本库接纳 |
| `preview_space_lifecycle` | 空间原件 ID／revision，只读，返回 blocked 及本库引用影响 |
| `apply_space_lifecycle` | spaceId + fileId，需要两层 recycle；不等于仓库素材回收 |

MCP 文本输入另限 **32000 字符**，适应本机协议包大小；大内容用本地同格式文件。工具分别报告准备／接纳／发布语义；导入工具、通用读取与插件 operations/queries 的语义不变。新文件任务允许较长等待，超时不等于未提交，必须同参重试。

两层原件权限是：

1. **空间设置**允许某仓库 revise 或 recycle（两者独立）。
2. **应用设置 → MCP → 仓库的“管理原件操作授权”**，逐空间允许 AI 使用对应能力；默认都关，仓库还须为可读写。

`list_file_spaces` 同时返回空间对仓库的 `canRevise/canRecycle` 与 MCP 有效权限 `mcp.revise/mcp.recycle`。`get_file_edit_capabilities`、历史页和生命周期预览把 MCP 限制合并进可用性。本批所有空间工具仍通过一个真实已关联仓库限定访问范围，`libraryId` 是授权上下文，`spaceId/fileId` 才是原件操作目标；尚不开放无关联的独立空间 MCP 管理。客户端不能通过工具提升权限、创建关联或提供其他路径冒充空间。撤销设置停止后续调用；已发出的操作不自动撤销，空间权限在最终提交时仍会复核。

空间回收立即限制所有历史版本的后续读取，恢复校验历史字节但不复活仓库素材。只给 organize 不授予空间原件处置。原件操作仅支持 v4；旧格式的 UI 管理、读写和迁移运行链已退出，见[兼容清单](../README.md)。
