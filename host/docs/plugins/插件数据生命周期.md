# 插件数据生命周期

2026-11-14：已提供可持久化责任声明、仓库清理服务，以及设置中的预览与清理界面。标签基础、分组、层级、自定义字段已接入；本机设置／密钥与界面偏好也有独立作用域的预览清理入口。运行中清缓存尚未开放。

## 责任与默认行为

数据属于仓库，插件需要说明自己带来的独立记录及共享影响。宿主在成功装配时持久登记声明、加工系统和定义快照；停用、卸载、包缺失后仍能预览与清理，不执行待清理插件的代码。

停用和卸载继续保留数据。安装包管理属于应用，数据清理属于某一个仓库：清理不会更改安装包、启停选择、别的仓库，也不会处置文件空间原件。两档维护均要求插件已停止运行（修改勾选后还须重载），避免正在加工的任务写回。仍有启用中的系统输出这些类型、或存在待完成收录任务时拒绝执行。

`BlockKind.plugin` 表示定义归属，不是数据最后的写入者。比如某插件加工其他插件的预览块，不能以加工者身份删除全部共享预览。标签分组／层级插件拥有自己的关系块，不能把基础标签一起清掉。

## 插件声明

外部包在 `plugin.json` 中加入核心能力：

```json
{ "coreFeatures": ["data-lifecycle-v1"] }
```

在现有 `CorePlugin` 中增加：

```ts
import type { CorePlugin, DataLifecycle } from '@resource-manager/plugin-api/core/contracts'

const dataLifecycle: DataLifecycle = {
  version: 1,
  disposableRecords: ['my-plugin-record'],
  retainedEffects: ['用户通过本插件写入的基础标签仍属于标签数据，本次保留']
}

export const plugin: CorePlugin = {
  id: 'my-plugin', version: 1, blocks,
  dataLifecycle
}
```

- 自己的静态及动态块依据宿主的 `kind_def` 归属登记，不重复列一个 kinds 清单。
- `disposableRecords` 是允许清除独立身份的类型白名单，只接受本插件定义的持久 `content`／`standalone`／`management` 类型。不能认领别的插件、普通附加属性、派生块或含原件引用的类型。
- 这里是删除授权上限，不是无条件级联删除。身份上有其他插件或未知块、仍被保留数据或动态定义引用时，宿主会保留并报告。
- `retainedEffects` 是当前不能由通用服务清除的共享数据／外部影响说明，不是可执行策略，也不能授权越过归属边界。
- 声明必须可序列化。不支持 SQL、任意文件路径、卸载脚本或启动失效插件来清理。
- 更新插件时宿主保留此前登记的独立记录类型及影响说明；删掉源码中的一条声明不会让旧数据失去责任记录。执行时仍核验当前快照归属。
- 旧插件可不声明，保持加载兼容。宿主能清理可核验的附加块及派生缓存；不猜测独立身份是否可销毁，并明确报告声明缺失。没有声明不等于没有副作用。

本机公共存储自动按插件 ID 归属，独立于仓库数据清理，详见下节。插件自己写到其他插件数据块中的内容、任意目录和旧 localStorage 仍不能按插件猜测删除；需声明保留说明，不声称清除一切外部影响。禁止把重要用户记录放进未登记的任意目录。

## 本机数据的范围与清理

本机设置、加密凭据和界面偏好由应用宿主管理；停用／卸载均默认保留，不随仓库数据清理连带删除。

| 范围 | 设置入口 | 影响 |
| --- | --- | --- |
| `application` | 应用 → 插件包 → 插件的全局本机数据 | 当前设备所有仓库共用的该插件设置、密钥、界面偏好 |
| `library` | 当前仓库 → 数据维护 → 插件的本库本机数据 | 只影响当前库在这台设备上的偏好，按仓库路径隔离，不写入仓库数据库 |

列表包含已停用／卸载但留有受管数据的插件。先选插件，再分别选择“本机设置、界面偏好、保存的密钥”；密钥默认不选。预览只显示键名、项数与阻止原因，不解密或展示值。需要明确确认；清理不可撤销，移除本机 Key 不等于撤销服务商的 Key。

执行前检查实际运行装配而非尚未应用的勾选：本库清理要求该库插件已停用并重载，全局清理要求所有打开的仓库均已停用该插件，或关闭相应仓库；启动／重载期间拒绝执行。先取消勾选但尚未重载仍不可清理。旧服务持有的接口停止后失效，UI 状态访问也要求插件处于当前库运行集合。

本机主进程服务 `PluginLocalMaintenance` 统一提供 `list / preview / clean / retry`；维护 IPC 的 `root` 来自可信窗口，前端不传任意仓库路径。结果逐类别区分已清理、待重试、文件已变化而保留。每个插件和作用域只留最近一笔回执；先持久登记计划再删文件，结果不确定时重试原 token，部分失败可在重开设置后接续。重新核验文件身份和内容，已成功项不会重复删除后来新写的值。预览过期必须重新确认，不自动换成新计划。

沿用本机 `plugin-local/<pluginId>/`：`application.json` 或库路径摘要 `.json` 保存设置，`.secrets.json` 为加密凭据，`.state.json` 为界面偏好；单文件沿用 v1 格式和原子替换。`plugin-local-cleanup/` 存不含配置值的回执；重置界面偏好保留 `imports` 一次性迁移标记，防止旧数据复活。空命名空间、迁移标记和维护回执不是用户业务数据，不承诺连目录也彻底消失。

只覆盖通过公共存储写入的本机数据。MCP 应用授权、宿主布局／预设、保存视图、仓库 `config`、外部账号及插件任意路径不在此入口的范围；当前不做按插件全盘搜索、任意前缀删除或执行卸载钩子。界面接入见[插件本机界面状态](插件本机界面状态.md)。

## 仓库公共服务

类型从 `@resource-manager/plugin-api/core` 导出，调用位于 `host.core`；只供应用／维护界面使用，本批不发布为 MCP 写操作。

| 调用 | 含义 |
| --- | --- |
| `listPluginData()` | 当前仓库的归属、运行状态、持久／派生块数量、旧结构契约和待重试缓存数 |
| `previewPluginDataCleanup({ pluginId, mode })` | 只读计划，返回影响数量、removedKinds 类型名称与数量、保留记录、阻止原因和 token |
| `cleanupPluginData({ pluginId, mode, token })` | 重新核对计划，在同一事务清理数据、索引、历史与契约，提交后处理缓存 |
| `retryPluginDataCleanup({ pluginId })` | 接续上次已提交清理的缓存删除，返回最新结果，不重复清数据 |

`mode: 'derived'` 只处理该插件拥有的派生块、登记的加工状态以及无引用缓存。`mode: 'all'` 再处理可核验的持久数据与结构契约。两者都不是磁盘空间清空或应用级卸载。

```ts
const plan = await host.core.previewPluginDataCleanup({ pluginId, mode: 'all' })
// 展示 plan.blocked、blocks、removedKinds、entities、preservedEntities、historyOperations、
// cacheFiles、retained、retainedEffects；用户明确确认后才执行。
if (plan.blocked.length) return
const result = await host.core.cleanupPluginData({ pluginId, mode: 'all', token: plan.token })
// pendingCaches 非空：数据已提交，缓存部分失败。提供“重试缓存清理”。
```

预览不是锁。后续数据／定义／相关历史或候选文件变化会使 token 失效；收到 `PLUGIN_DATA_CHANGED` 必须重新预览。`PLUGIN_DATA_BLOCKED` 包括尚未停用、必需核心持久数据、收录任务未完成及上一批缓存尚未处理。事务内不能嵌套维护。重复提交最近一次相同 token 返回其回执／接续缓存；不是重新执行删除。每个插件只保留最近一笔维护回执，不新增无限历史。

## 清理边界

1. 普通文件或其他内容仍作为身份主体时，只摘除本插件的属性，原件和其他数据保留。会检查回收站中的块。
2. 仅当声明允许、身份上的块全部归本插件且没有需要保留的引用，才彻底删除独立记录。不会级联销毁其他插件的依附身份。
3. 无法确定删完后仍有内容主体的混合记录保留本插件持久块，避免留下只有笔记／标签的幽灵空壳。保留理由出现在 `retained`。
4. 静态和动态类型都依据归属处理。存在残留块时不重置该插件的结构契约；全部受管块清空后，删除其 `kind_def`、`externalSchema`、`externalDefinitions` 并通知休眠定义刷新。`resetSchema` 只表达这一结果，不表示所有外部影响已消除。
5. 受影响的撤销操作整笔失效，防止部分重放跨插件事务或恢复已清除数据；无关操作仍可撤销。执行本身不可撤销。外部操作的幂等回执继续保留，避免旧 requestId 重试变成一次新写入。
6. 只从派生块 `file: true` 字段收集 `cache/` 文件。当前原始／派生／回收站／未知块和尚存撤销历史中的引用均受保护；不按目录名猜归属，不碰文件空间。无法核验的路径保留。
7. 数据删除与缓存候选一起提交。缓存删除失败可跨重开重试；重试重新检查引用和文件标识，后来被重写或重新引用的文件保留。删除成功与回执更新之间崩溃时，重试可完成，但结果中的实际删除计数可能少记，不承诺跨文件系统与数据库的原子物理删除。

责任声明和最近维护回执留在 `main.config`，用于保留说明与失败接续；这不包含被清理的数据块内容。当前不修改仓库／文件空间格式。

## 设置入口与更新方式

在仓库窗口打开「设置 → 当前仓库 → 数据维护 → 插件数据」，列出曾登记的插件、持久／派生块、结构契约和待重试缓存。纯界面插件可能没有受管数据，不把列表视为安装包清单。

1. 「查看与清理…」选择仅派生数据或插件数据与定义；预览列出将移除的类型与数量、独立记录、保留记录、缓存和整笔失效的撤销操作。
2. 运行中插件先到「功能与插件」停用并应用重载。这里不自动停用、不卸载，也不修改文件空间。
3. 核对不可撤销影响并勾选确认后执行。数据变化要求重新预览；执行期间设置退出守卫阻止关闭／重载。超时保留原 token 重试核对结果。
4. 结果分别说明已处理、因引用／混合记录保留和缓存删除失败。缓存失败不回滚已提交的数据；返回列表或重开设置后仍可看到待重试项，并接续上次任务。

更新常用包后需在仓库选择新版并成功启用一次，宿主才会登记新的责任声明；随后停用、应用重载，再做清理。不要先卸载尚未登记声明的新版。旧包／缺声明仍可预览，不能安全判断的独立记录会保留。

| 插件版本 | 自己负责的数据 | 明确保留的影响 |
| --- | --- | --- |
| tags 2.0.1 | tags 属性、旧 tagGroups 管理记录 | 分组／父子关系、保存视图条件 |
| tag-groups 1.0.2 | tag-groups.groups 管理记录 | 素材标签、层级目录、tags 拥有的旧备份、本机折叠状态 |
| tag-tree 1.0.2 | tag-tree.node 管理记录 | 素材标签、分组、保存条件、本机折叠状态 |
| fields 1.3.1 | template 记录及其 tpl:* 动态字段 | 素材身份、其他块、表格列设置和保存条件 |
| table 1.3.0 | 不定义自己的数据块 | 值由原定义插件负责；显示配置归页面／保存视图，本批不随插件删除 |

标签分组不再自动回退到旧 tagGroups。需要接续旧库时，在分组面板明确点击「导入旧分组」，或调用 `import_legacy_groups`；只在没有独立分组记录时复制，不覆盖现有记录。清理后重新启用不会自动复活旧组。旧备份仍由 tags 拥有，分组插件不能代删。

## 验证与后续边界

`tests/core/plugin-data.test.ts` 覆盖原件保护、混合身份／引用、声明校验、动态定义与结构解锁、旧声明、事务失败、过期预览、共享缓存、跨重开重试与整笔历史失效。已有第一批回执缺少 `removedKinds` 时返回空明细，继续原任务，不再删除数据。

真实 Electron：构建后运行 `node tests/electron/plugin-data-check.mjs`，使用临时仓库和独立 `RM_USER_DATA`。安装测试包、导入新文件并在 utilityProcess 加工，通过实际设置控件验证运行阻止、停用／卸载保留、过期预览、明确确认、真实缓存删除失败、重开设置后重试及结果回执。预览和结果截图保存在输出目录。

可选设置 `RM_LIFECYCLE_PACKAGES_FILE` 指向 JSON 文件，内容为 tags、tag-groups、tag-tree、fields、table 的独立工程产物绝对路径数组。沿同一流程验证真实包清理互不误删、旧分组不复活、动态字段和模板一并处理、原件继续可读。业务源码与产物不复制进宿主。

同一 Electron 流程另验证临时双仓库的本机作用域、真实加密凭据保留与显式清理、跨库运行阻止、旧 UI 写入拒绝、实际文件删除失败及重开设置接续。带常用包时验证折叠状态迁入、写入、重置与旧 localStorage 不回流。本机服务失败回归在 `tests/integration/plugin-local-maintenance.test.ts`。

未验证 Windows 实机或断电恢复；不访问日常仓库。不承诺任意插件都能完全清零：任意外部存储、共享写入归属与运行中派生清理仍待具体案例补充。


## 色板拆包交接（2026-11-15）

`preview` 仅拥有 still/thumb；`palette` 外部包拥有同名派生块和 palette.extract 加工任务。新旧仓库均按需启用色板，附带包默认关闭，已有正式绑定选择保留。停用或卸载仍保留数据。

仓库受控打开时，外部包校验前，palette-handoff 在事务中把旧 preview 的可重建 palette 定义转交给 palette，保留块值、序号和实体；退役 preview.palette 任务签名，并从 preview 清理登记移除该系统，把色板责任登记到 palette。即使未安装包也可在插件数据管理中清理休眠色板。完成后重复打开不再交接，清理后不会恢复旧记录。异常所有权／不可重建定义拒绝自动交接。

启用新包会按现有 thumb 重算；清理 palette 不删除 still/thumb、素材身份或原文件。当前仅平移提色和详情复制，不新增颜色筛选／相似色检索。封面使用中性占位背景，不反向依赖色板。
