# 插件本机界面状态

2026-11-14。用于折叠、展开等小型 UI 偏好，归应用宿主；不用于数据块、正文、编辑草稿、密钥、页面导航或已有工作台布局。纯界面插件不需要为了存状态增加 core / service。

## 声明和使用

`plugin.json` 的 `uiFeatures` 加入 `plugin-local-state-v1`，旧宿主会明确拒绝未知能力。公共导入路径：`@resource-manager/plugin-api/ui/local-state`。

```tsx
import { usePluginState } from '@resource-manager/plugin-api/ui/local-state'

function Tools({ host }) {
  const state = usePluginState<string[]>(host, 'my-plugin', 'collapsed', [], {
    scope: 'library' // 默认；application 为本机跨库共享
  })
  return <>
    {state.error && <p role="alert">{state.error}</p>}
    <button disabled={!state.ready || state.busy}
      onClick={() => void state.set(['section-a']).catch(e => host.notify(String(e)))}>
      折叠
    </button>
  </>
}
```

- `host.localState(pluginId, scope = 'library')` 返回 `get / set / remove / importOnce / onChanged`，前四者异步，订阅返回取消函数。未写入／删除的键返回 `undefined`，hook 使用初始值呈现但不会自动持久化默认值。
- `pluginId` 传自身声明 ID，键只在插件命名空间内。当前插件为可信代码模型，与其他公共插件 ID 接口一样，命名空间和启用检查用于维护归属，不宣称恶意 UI 代码隔离。主进程根据窗口确定当前仓库，不接受路径参数。
- 两个 scope 都仅在本机用户目录；`library` 按仓库路径隔离，搬库后不自动迁移本机偏好，业务关系仍随仓库走。不同安装版本沿相同插件 ID 复用；格式兼容与版本键由插件维护。
- hook 返回 `value / ready / busy / error / set`，提交成功后再呈现，失败保留此前值。初次读取完成前禁用操作，同一个 hook 写入中再次调用 `set` 会拒绝 Promise；这适合低频偏好，不是编辑缓冲队列。
- 同一库中的多个画面／独立内容窗口共用同一来源与变化通知；应用 scope 还通知其他库。多投影整键写入按最后提交生效，没有合并事务／CAS。插件应选小而独立的键，不把整个业务状态塞进一个键。
- 每个作用域状态文件最多 256 KiB、100 个键，JSON 最多 30 层；键最多 80 字符，允许字母数字及 `_.-`，不能是路径或原型保留键。导入标记同样最多 100 个。需要大数据、撤销或共享编辑时使用对应公共能力。
- 插件停用后旧界面不能继续访问；停用和卸载不删除文件。设置中的[本机数据清理](插件数据生命周期.md#本机数据的范围与清理)覆盖这种存储，不依赖插件还能运行。

## 精确迁入旧 localStorage

仅为明确已知的旧键使用 `legacyKey`：

```tsx
const state = usePluginState<string[]>(host, 'my-plugin', 'collapsed', [], {
  legacyKey: `my-plugin:collapsed:${host.root}`
})
```

首次导入使用主进程 `importOnce`：不覆盖已存在的新值，成功后才移除那个精确旧键；若旧键不存在，则登记初始值与迁移标记。记录导入标记，之后即使重置本机界面偏好，也不再把旧值写回来；不会扫描或批量删除任意 localStorage 前缀。读取／解析／保存失败显示错误并保留旧数据。

2026-11-14：`tag-groups` 和 `tag-tree` 1.0.2 分别把折叠状态迁到自己的 `library` 命名空间。分组关系、层级节点仍在各自仓库数据块中，不随界面偏好重置；不要清理仓库业务关系来恢复展开状态。
