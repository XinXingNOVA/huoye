# 受控文件编辑

2026-11-05。以应用发起的编辑、明确交回修改和版本接纳为主。仓库／空间格式保持 v4，已有文件引用和插件的公共保存协议不变。

## 使用

先安装并在当前仓库启用 **文件编辑**（`file-editing`）外部包。基础宿主保留任务服务与应用级编辑器登记；专用管理界面按插件启停。缺少界面时编辑入口提示安装／启用，已有工作副本仍保留。

素材右键 **编辑文件** 会直接创建或复用工作副本，并按本库该格式的编辑偏好打开；未指定时常见格式使用系统默认应用，未知格式或无扩展名文件显示编辑器选择器。文件空间的“修改文件…”也使用同一入口。普通双击阅读仍使用本库已接纳的内容，不被未完成修改替换。

左侧 **编辑中** 是素材的状态视图，展示原素材，复用集合布局、搜索、筛选和排序。双击继续编辑；选中一项后，可在工具条或右侧详情中 **完成编辑**。卡片显示编辑状态，右侧控件归插件提供的可排序／折叠“文件编辑”分区。这个视图按本机登记动态汇集，不接收拖入，不把当前身份集合另存为仓库视图规则。外部插件布局须沿用 LayoutProps.onOpen，才能保持相同双击语义。

1. 在外部程序保存并关闭文件，再 **完成编辑**。宿主检查工作副本、准备稳定快照、发布文件新版本、让本库接纳，最后清理副本和本次预览。无变化时只清理，不发新版本。
2. 独享空间正常完成只需一个按钮。共享文件会先说明发布影响并确认；其他仓库按各自规则接纳。需要检查修改时，打开 **⋯ → 保存方式与修改预览**，文字预览前 4 KB，常见图片并排显示基线与待保存内容。不是通用内容差异比较器。
3. **独立副本**把修改保存到明确选择的独享空间，并切换当前素材引用。素材身份、标签和笔记保留；原文件及其他仓库不变。冲突不会擅自选择这个分支。
4. **放弃修改…**需明确确认，清理本机工作副本及快照，不删除素材或已经发布的版本。已发布但尚未完成接纳的任务不能伪装成“取消发布”，必须先核对原回执。
5. 失败保留副本和处理入口：准备／提交失败重试原请求；“已保存 · 待本库接纳”只续接接纳；“待清理工作副本”只重试清理。保存成功后副本又有修改时继续保留，下一次完成是新的保存意图。

**文件存储… → 选择替换文件…**用于交回已在其他位置修改好的同格式文件。来源保留，复制进入相同流程；已有活动工作副本时拒绝覆盖。未知格式也可明确选择已登记编辑器，或使用替换入口。外部程序另存到其他路径不会自动跟踪。

旧版已结束但保留的副本，以及素材被回收／删除后的副本，在“编辑中”的单独处理区域保留入口。缺失工作文件不会凭空视为完成：可以显示位置、修复后重试或明确放弃。旧文件编辑标签恢复为状态视图，不保留另一套任务页面。

## 选择本机编辑器

在 **设置 → 应用 → 外部编辑器** 添加本机应用，也可在 **文件存储… → 选择编辑器…** 或活动任务 **⋯ → 选择编辑器…** 中选择。macOS 选择 `.app`，Windows 选择 `.exe`；不填写命令行参数。未知格式会直接提示选择编辑器。切换应用只打开同一个工作副本。

选择时可勾选“在当前仓库中，默认用此应用编辑 .扩展名 文件”。依据真实文件格式，不依据显示标题；阅读的默认打开方式单独设置。无扩展名文件只为本次打开选择，不批量记忆。程序不存在或拒绝启动时报告失败并保留副本，不静默改用其他应用。应用设置的“移除”只移除登记及相应偏好，不卸载程序、不删除工作副本。

配置位于应用用户数据目录 `local-editors.json`，包含本机编辑器及按仓库身份／扩展名区分的偏好，不修改仓库数据库。应用列表可跨仓库复用，各库默认选择独立。打开时只交出副本；未知格式不会交给系统默认关联直接执行。

## 身份、冲突与恢复

任务绑定本机仓库身份、素材身份、开始时的文件引用和文件块序号；引用包含空间、文件、版本身份。各仓库任务独立，同一仓库同一素材复用一个活动任务。本机按仓库串行执行任务动作，其他仓库及应用内文字编辑器由版本与仓库基线校验保护。这不是共享空间的全局编辑锁。

- 发布前仍须是原编辑基线，并有空间更新授权、已采用空间当前版本。他人先发布或本库变更文件信息／引用时拒绝覆盖。
- 明确选择独立副本允许把旧基线修改保存为新文件，并切换素材**当前**引用；准备时绑定当前序号，提交期间再变化仍拒绝。
- 笔记等其他块变化不阻止保存；派生内容重新生成，原始数据保留。批注、阅读位置不承诺自动重定位。
- 工作文件检查和复制前后核对状态，支持编辑器原子替换保存；缺失、符号链接、读取期间变化不能作为有效提交。预览后又修改需要重新检查。
- 准备参数、快照和请求身份在调用核心前落盘，确认意图也先落盘。重试已确认保存只续接原快照；副本的后来修改不会被当作已经保存。
- 空间已发布但本库接纳失败保持原请求；接纳跳过或重放回执与本库当前引用不一致时保留副本、提示核对，不覆盖用户的新选择。
- 清理意图在删除前落盘。清理重试再次检查副本；字节或文件状态改变则保留并退出清理态。外部程序生成的未知辅助文件不会递归删除，应先显示工作目录并移走这些内容。

“完成编辑”是用户表示外部保存已结束的明确动作；宿主无法保证任意外部编辑器已退出。清理前核验能拦截已观察到的后续修改，不是对其他程序的写入锁。完成后仍在外部程序中继续保存不属于自动接续范围。没有后台 watcher、任意格式合并、多文件工程编辑或自动回写受管原件。

查看副本与编辑副本不同：[系统查看副本](../plugins/打开方式.md)不回写、不变为受保护草稿。直接伸手修改受管原件仍使用文件空间“磁盘检查”的兜底流程。发布与接纳也不属于普通字符编辑撤销，原件恢复使用已有版本历史。

## 分层与接入

- `src/main/file-editing-tasks.ts` 托管工作副本、准备快照、完成／放弃及恢复，通过核心 `prepareFileEdit / commitFileEdit / discardFileEdit` 调用，不直接写仓库或空间数据库。
- `src/main/local-editors.ts` 保存本机应用与按库格式偏好，系统启动使用固定参数数组、不经过 shell。
- `src/main/file-editing.ts` 限定当前窗口仓库的 IPC、系统启动和预览。主进程完成组合流程，不依赖页面继续挂载。关闭视图不等于放弃；重启不自动发布未确认任务。
- `src/shared/file-editing.ts` 定义本机桥接：`start/open/reveal/list`，可选 `check/commit/discardPrepared`，组合 `finish`，确认后 `discard`。`inspectEnd` 生成放弃确认凭据。`finish` 返回 null 表示完成，返回任务说明仍需处理；异常也保留登记。`lib://<libraryId>/_file-edits/<taskId>/<requestId>` 只读当前准备快照，不交出通用可写 URL。
- 独立 `file-editing` 插件中的 `state.tsx` 每窗口共享一份状态投影；`view.tsx` 用公共集合与动态范围呈现列表；`editing.tsx` 和 `EditorChooser.tsx` 组织完成、放弃和编辑器选择。卡片／详情订阅同一份数据，不逐项发 IPC 或持续散列文件。
- `UiPlugin.fileEditingUis` 对接宿主的 `host.editFile` 通用入口；`host.fileEditing.chooseReplacement` 显示原生选文件框并创建副本，不把任意路径交给插件。所有文件权限、任务落盘和恢复仍由主进程服务负责。


本机登记在应用用户数据目录 `file-editing/<仓库 ID 的 SHA-256>/<任务 UUID>/`。`state.json` 临时写入、同步、原子替换，记录基线和核心请求关联；空间发布回执仍是权威事实。完成后工作文件和快照清理，保留小型完成登记用于响应丢失后的幂等重试，不出现在活动视图。登记不随仓库跨机器迁移，不作为素材导出，也不按查看缓存的有效期删除未完成修改。

UI 插件声明 `uiFeatures: ["file-working-copy-v1"]` 后调用 `host.editFile(itemId)`，宿主路由给已启用的编辑界面，后者使用公共服务创建／复用、启动与反馈。无需依赖标签页 ID 或本机 IPC。插件自身的编辑器继续使用[公共文件编辑协议](../plugins/公共文件编辑.md)，纯数据块编辑继续使用共享草稿；没有扩展通用编辑会话模型。需要自行呈现或管理任务的插件声明 `file-working-copy-service-v1`，使用 `host.fileEditing`，见[公共工作副本服务](../plugins/公共工作副本.md)。文件编辑包完整消费该服务；卸载不会调用放弃或删除工作副本。旧编辑中页在包启用时迁为 `file-editing.page`，保留原页参数与状态；停用后的专用标签按既有插件规则关闭，任务不依赖标签存活。

MCP 继续使用已有准备／提交／接纳工具，不获得启动系统应用或接管本机编辑状态的新权限。大文件仍需要复制和校验的时间、工作副本及暂存版本的磁盘空间；此次不宣称性能提升。

验证入口见[开发与验证](开发与验证.md#受控文件编辑)。
