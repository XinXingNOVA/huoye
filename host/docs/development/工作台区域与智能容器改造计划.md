# 工作台区域、容器与上下文工具改造计划

日期：2026-11-09。状态：**用户确认本轮结构改造收束；区域、普通／智能组、固定绑定、按声明停靠和常用操作栏已实现，API 与接入边界已归档。视觉呈现继续迭代。**

本文归纳本轮讨论的最终方向，并对照当前代码划分实施范围。早先讨论过的通用跟随策略、最近有效目标和无目标时自动开页，不作为首版要求。效果图用于说明区域关系，图中出现的业务工具不等于本轮全部接入。

后续契约整理：用户确认内容与容器通过公共约定解耦，由宿主解析装配，见[容器与内容契约](../architecture/容器与内容契约.md)。本计划保留已完成批次的范围；新文档仅整理语义，不代表外部容器注册、替换设置或统一内容接口已实现。

## 1. 目标与范围

2026-11-09 范围确认：本轮先完成框架交互逻辑，当前容器与内容样式后续仍会变化。实例、位置、绑定、生命周期与操作校验应独立于外观；后续再使用新结构能力开发插件，并在本轮完成后集中梳理 API。现行契约文档随批次更新，不因集中整理在后面而留空。

以“区域 → 布局容器 → 内容视图”组织工作台。左右区域与中央各有自己的顶部，不再由一条独立全局输入栏压在所有区域上方。布局和内容解耦：宿主管空间、实例和生命周期，插件提供具体内容与适配声明。

整体计划分批完成：

1. 分段顶部、普通标签组和左右纵向分区。
2. 将当前“资源”工具拆成导航与集合筛选。
3. 以中央主页面为上下文来源的智能工具容器。
4. 从智能容器拖出独立工具，保留原入口及当时目标。
5. 声明放置能力、实例限制，接续本机布局、预设和现有插件入口。

保持仓库数据库、数据块、文件空间 v4 格式、MCP 和业务操作语义不变。设置继续是独立浮层，使用已有设置服务与退出检查。

## 2. 三层模型

| 层次 | 职责 | 首版形式 |
| --- | --- | --- |
| 区域 | 空间范围、布局方向、可用容器和尺寸约束 | 左、中、右；中央可上下／左右分割，两侧只上下排列 |
| 布局容器 | 安放内容实例、组织切换、提供标签和容器操作 | 普通标签组、智能工具容器 |
| 内容视图 | 展示数据并提供业务交互 | 导航、集合、筛选、详情、阅读器及逐步接入的插件工具 |

标签条是容器的组织形式，标签是内容实例的入口。内置与外部是提供者区别，不作为两种布局内容类型。“图片”“数学逻辑”等导航条目也不分别成为界面类型，它们打开不同参数的集合实例。

内容声明支持的区域、容器形式、默认放置、必要尺寸和实例限制。默认位置仅在首次打开时使用，用户摆放优先。区域与容器共同参与放置判断；同为标签组不代表所有内容都适合窄侧栏。

容器类型可继续发展，但本轮只实现两种宿主内置类型。暂不开放第三方任意注入容器渲染器，不预做一套通用布局脚本系统。

### 首版实现尺度

中央沿用现有分割树；两侧用纵向分组及高度比例表达受限分割。共同使用放置校验、实例身份和布局动作，不为数据结构表面统一重写成熟的中央树。

普通页面与工具视图先通过公共内容描述及有限适配进入容器，保留已有页面和工具的业务契约。新的内容身份、区域归属和绑定关系只在工作区中有一份权威状态，避免维护互相追赶的两套位置记录。

## 3. 顶部与工作入口

- 去掉常驻全局搜索／命令输入框。命令面板主快捷键改为 `Cmd+P / Ctrl+P`，菜单及快捷条保留鼠标入口；统一修改说明与快捷键路由，不新增另一套命令执行机制。
- 左、中、右各自的顶部处于同一水平线，背景与竖向边界延续到窗口顶部。中央各分屏仍有各自标签栏，下方分屏不依赖窗口最顶层标签栏。
- 左右展开时，侧栏开关在各自顶部；收起时，相应展开按钮留在中央顶部对应外缘。多中央分屏时窗口级开关只出现一次。
- macOS 窗口控制安全区、Windows 窗口控件、拖动窗口区域由宿主安排，按钮与标签不落入不可交互的拖动区。
- 最左侧改为常用操作栏，固定全部视图、新建文字、导入文件、命令面板，不用工具所在位置或最上方组决定图标。插件通过窗口 UI 命令明确贡献快捷入口，沿用宿主标准图标；不自动罗列全部工具，不做用户自定义快捷栏编辑器。新建和导入明确面向当前仓库，页面内输入规则另行保持。
- 保留库切换、设置、命令、布局和不可用插件反馈的可发现入口；移除全局顶栏时明确迁移它们，不把原有操作一并丢掉。
- 底部空间本轮继续不启用，不增加常驻播放器条。

## 4. 两种容器

### 4.1 普通标签组

用户决定打开什么、顺序如何、当前显示什么，可以关闭、移动和合并。中央焦点变化不替用户切换组内工具。

“普通”不等于数据冻结：歌词可以继续跟随播放会话，详情可以按自己的明确规则跟随主页面选择。容器不自动更换内容类型。工具的数据来源由它的绑定说明决定。

同一组只显示一个活动内容，两侧可通过多个纵向分组同时展示不同工具。详情内部的文件、标签、笔记等折叠块继续由详情自己组织，不自动升格成工作台分区。

### 4.2 智能工具容器

根据当前中央主页面及它提供的能力，显示适用的插件工具。它可以有标签，但自动装配仅发生在这种容器中。

- 页面类型用于记忆工具组合；能力用于判断工具能否使用。集合提供查询／筛选能力，阅读器按实际接入情况提供阅读导航等能力。
- 用户可按页面类型配置工具的显示、顺序；容器记住该类型上次选中的工具。首先使用已有贡献和轻量菜单，不新增复杂配置页面。
- 插件声明需求和默认建议，宿主统一判定及装配。不能由多个插件各自抢焦点、自动展开或创建布局。
- 未接入、未安装或不满足能力要求的工具不假装可用。没有匹配工具时，容器显示简短占位，仍保留位置和尺寸。
- 切换不反向打开／替换中央页面，也不自动收起整个分区。
- 首版智能容器放在左右侧栏；中央先使用普通标签组。其他组合由后续场景推动。

多个智能容器可以有各自的工具配置。首版默认只放一个，避免重复控制相同内容及无谓的后台开销。

## 5. 上下文、记忆与绑定

### 5.1 上下文来源

以当前激活的中央主页面为准。鼠标经过不算激活；点击侧栏工具、命令面板或设置浮层不会把上下文改成那个控件。中央切换标签或激活另一个分屏，才改变主页面来源；来源内部的查询、选择等状态可以实时更新。

上下文至少区分：来源页面实例 ID、页面类型／显示标题、可用能力、带来源的素材选择。窗口／仓库隔离明确，不使用没有来源信息的全局选择代替绑定关系。

同一个保存视图打开两份时，它们有不同临时筛选，必须按页面实例区分。类型相同不等于绑定目标相同。

### 5.2 首版保留两种直接关系

1. 智能容器中的工具跟随当前主页面。
2. 从智能容器拖出的工具绑定拖出时的目标。

普通入口打开的工具延续已声明的来源，例如导航依赖仓库，详情跟随主页面，歌词依赖播放服务。暂不提供复杂的跟随策略组合、最近有效目标自动回退或自动寻找其他页面。

绑定目标失效时显示“目标已关闭”或“当前页面不适用”。首版允许用户关闭该工具、定位仍有效的目标或重新从智能容器拖出，不要求额外制作目标重绑定编辑器。

### 5.3 三类记忆分开

- 布局：区域、容器类型、比例、普通实例位置与顺序。
- 智能容器偏好：按页面类型保存的工具组合和当前工具。
- 内容局部状态：滚动、展开项及插件报告的恢复状态；编辑草稿仍走原有会话机制。

不把查询对象、函数、DOM 或服务句柄序列化进布局。运行时根据来源页面 ID 解析能力；工作区重开后仅在原目标成功恢复且仍兼容时续接绑定。

切换上下文不能把旧对象草稿写给新对象。带编辑的工具必须按目标隔离草稿，或使用现有离开检查后再换目标；失败保留原目标并明确提示。首批先接入集合筛选等边界清楚的工具，不能仅凭 React 保活就宣称所有编辑插件已支持。

## 6. 拖放、创建与实例

| 来源／落点 | 首版行为 |
| --- | --- |
| 普通内容 → 兼容的普通组接纳区 | 移动原实例或在组内排序 |
| 普通内容 → 可新增的分区边缘／空白 | 分配空间，按内容默认选择创建普通容器实例并移动内容 |
| 智能工具 → 普通组或有效边缘 | 额外打开独立实例，保留拖出时的目标；智能容器不删除工具入口 |
| 内容 → 不支持的区域、尺寸不足或实例超限 | 显示不可放置原因，不留下空组或半次移动 |
| 任意普通内容 → 智能容器主体 | 首版不作为任意接纳区；智能工具组合通过配置修改 |

两侧仅提供上／下分区落点，中央保留四边；标签接纳区表示合并。预览明确区分“移动”“独立打开”和“不可放置”，Escape 可以取消。提供菜单形式的同等操作，拖放不是唯一入口。

“创建容器”是创建已注册容器类型的实例，不是每拖入一个内容就定义新类型。普通内容拖到空白默认创建普通标签组，不推断需要智能容器；智能容器由用户明确添加。

普通移动保留实例 ID 与状态，移空的普通容器回收，中央最后一个组按既有规则保留开始入口。智能容器没有匹配工具时只是空状态，不自动删除。

智能工具拖出属于显式多实例：

- 界面实例独立，业务数据及服务按既有规则共享；不复制素材，不启动第二个播放／流式服务。
- 绑定的是目标页面实例，目标状态继续实时同步。独立筛选改动集合后，其他服务同一集合的筛选也必须更新。
- 插件必须声明并实际支持多实例和绑定快照；旧工具默认不允许复制。不能支持时禁用“独立打开”并说明原因，不暗中搬走智能容器的唯一实例。
- 落点、目标存活、实例数在提交时重新校验；取消／失败不改变原布局。
- 普通点击快捷入口继续优先定位已有实例；只有明确拖出／独立打开才新建。

智能工具的直接绑定目标首版必须是当前中央主页面。固定后的目标仍存活但移到后台，可以继续服务并显示目标名称；目标关闭则失效，不因新页面同类型或同名而重新绑定。跨到侧栏的内容不会自动成为新的智能上下文来源，避免自我跟随与循环依赖。

## 7. 当前“资源”工具的拆分与默认画面

### 导航内容视图

保留预设视图、常用／保存视图、新建保存视图和导航显示设置。它们都是“打开何处”的操作，作为同一个内容视图的内部组织。回收站继续是导航入口。

库切换、设置和布局与工具菜单保留在快捷栏底部；文件空间继续从导航或命令面板进入中央工作台。插件原有导航贡献按其声明接续，不自动变成多个独立标签。

### 集合筛选内容视图

将格式、标签与其他分面独立出来，复用当前 `FacetDef`、范围 facet 和 `TabApi` 能力。默认进入智能容器；只操作其绑定集合。

保留“基础查询＋其他条件，排除自身字段临时条件”的分面口径，保持兄弟标签可见；右侧给素材打标签继续使用全库词汇。标签分组数据和业务查询规则不改。

### 新工作区的首版建议

```text
快捷条 │ 左侧区域                │ 中央区域                  │ 右侧区域
       │ 普通组：导航            │ 普通标签组／分割树        │ 普通组：详情
       │ 智能组：当前页面工具    │ 集合、阅读器等            │ 可自行添加其他组
```

左下在集合上下文首先显示筛选；其他页面只提供已接入工具，否则占位。用户可将智能容器移到右侧，也可拖出筛选固定在左下。聊天、歌词等仅在插件已启用且通过接入验证后出现，不强制随本次更新打开。

旧工作区按迁移结果接续，不强制覆盖为上述新默认。效果图中的右下聊天、目录等展示布局潜力，不承诺本轮重做这些业务界面。

## 8. 公共 API 与实现职责

拟补充的公共语义如下；实际字段和能力标记在实施时按现有契约确定，本文不作为已发布 API。

| 能力 | 声明／调用方 | 宿主职责 |
| --- | --- | --- |
| 放置描述 | 页面与工具声明允许区域、容器、默认值 | 校验落点、尺寸，创建／复用容器 |
| 上下文提供 | 主页面报告类型、能力和带来源的选择 | 维护当前来源，发布有效快照及失效事件 |
| 工具适用性 | 工具声明所需能力及上下文呈现 | 过滤候选，按用户配置装配智能容器 |
| 独立打开 | 支持多实例的工具声明绑定与恢复规则 | 捕获目标、创建实例、遵守数量约束 |
| 显隐与生命周期 | 内容处理可见性、恢复、结束检查 | 区分失焦、隐藏、移动、改绑、关闭和重载 |

继续从现有 `TabType`、`TabApi`、`toolViews` 以及页面来源绑定机制延伸。公共接口放在 `src/plugin-api/ui`，类型说明按工作台领域组织，插件不导入宿主私有组件。

`App.tsx` 只连接窗口服务与区域，不把布局计算、上下文判定和容器装配都塞回 App。预计主要修改范围：

- `src/shared/sidebar-layout.ts`、`workbench-layout.ts`：侧栏分组、容器类型、布局结构与验证。
- `src/renderer/src/workspace.ts`、`app/workspace.ts`：实例／位置权威状态、本机存档和原子布局动作。
- `sidebar-catalog.ts`、`sidebar-layout.ts`、`SidebarWorkspace.tsx`：声明适配及侧栏布局；新增小型上下文协调与智能容器模块。
- `EditorWorkspace.tsx`、`editor-layout.ts`、`RetainedSurface.tsx`：保留已有分割／保活能力，接通公共落点与必要的工具承载。
- `Sidebar.tsx`：按导航与筛选职责拆开，复用已有分面组件。
- `App.tsx`、样式及命令路由：分段顶部、窗口控制安全区、快捷入口和 Cmd/Ctrl+P。
- 工作台预设服务、声明校验和相关文档：同步新布局格式与接入边界。

不为统一名称一次重写全部页面／工具接口；同一运行时在声明边界适配旧入口，新能力通过明确能力标记开放。

## 9. 数据、迁移与插件接续

仅演进本机按仓库保存的工作区布局及相应预设格式。更新读取边界和版本，不将旧布局直接按新形状解释。

- 迁移前保留一份可恢复的旧布局快照。迁移幂等，转换／保存失败不覆盖原值。
- 中央页面、实例 ID、参数、局部存档和共享草稿保持；侧栏尽可能保留原侧、工具顺序、已选择工具、比例与显隐偏好。
- 旧“一个选中容器内纵向排列工具”的结构不能原样等价于新标签组。实施第一批先给出确定映射与旧布局案例：当前同时可见工具优先保持同时可见，其他工具保留入口／存档，不把它们全展开挤满侧栏。已折叠状态按新容器可表达的方式接续，不丢掉对应实例。
- 未启用／未知插件的位置及配置保留，不自动安装、启用或复制业务数据。
- 现行工具使用 `toolViews`＋`tool-placement-v1`。2026-11-10 已移除旧声明适配；存档接续与备份保持，历史阶段描述不代表旧接口仍可使用。
- 旧布局预设同样经过转换。预设只保存排列、容器类型及智能组合偏好，不携带某个窗口的具体绑定对象、正文或草稿；具体绑定只属于工作区存档。应用预设继续保留真实实例，关闭的目标不复活。
- 智能切换不等于业务会话结束。首次需要才挂载，不预先加载所有候选插件；隐藏时停止无必要绘制和重复查询。状态保活与恢复使用现有机制，明确不能自动序列化任意 React 状态。

## 10. 分批实施

每批形成可运行的结果，更新对应规范、精简记忆并单独 Git 提交。具体业务插件按用户启用顺序接入，不要求一次适配全部外部工程。

### 第一批：区域骨架与普通容器（已实现）

- 明确区域、容器、实例的公共描述及旧布局映射。
- 两侧支持纵向普通标签组，中央沿用分割树；稳定快捷入口。
- 分段顶部、侧栏收起后的开关归位、移除全局输入框、Cmd/Ctrl+P。
- 旧工作区及预设接续与本机恢复同步完成，不拖到收尾才处理。

实现：侧栏 v2 普通组、稳定工具快捷条、分段顶部、收起开关归位与 Cmd/Ctrl+P。已有 `toolViews / viewContainers` 适配为普通标签组，暂不新增跨区公共声明或多实例工具协议。旧工作区保留 `sidebarBackup`，旧预设在首次改写前另存备份；详细映射见[工作区布局](../plugins/工作区布局.md)。

验收：原有工具仍能找到，左右可同时放多组；移动不丢状态；重新打开保持布局；设置浮层、命令和原有页面输入正常。实际验证范围见[开发与验证](开发与验证.md#分段顶部与普通侧栏标签组)。

### 第二批：智能容器与“资源”拆分（已实现）

- 上下文提供／消费、智能候选判定、按页面类型记忆工具配置。
- 导航和集合筛选分离，筛选接入智能容器；普通详情保持可用。
- 无适用工具时占位，侧栏／浮层操作不改变中央来源；解决迟到查询和错误目标写入。
- 用宿主现有不同页面上下文与最小公共示例验证工具切换，不为演示假造完整 PDF 目录／字幕业务。

实现：`toolViews.context` 与 `TabApi.context` 接通 `context-tools-v1`；左下默认智能组按能力显示工具、按页面类型保存组合。导航／分面分离，普通详情保持。工具按容器和来源页面隔离，隐藏停止分面查询；旧 v2 本机布局保留备份后拆出筛选位置，预设同步转换。

验收：集合 A/B 的筛选不会串页；切到阅读页时工具按适用性变化，切回来恢复组合；占位不改变分区尺寸。

### 第三批：拖出独立工具与兼容停靠（已实现）

本批实现显式 `detachable`／数量约束、独立实例与来源页绑定、重复固定复用、失效占位、本机恢复及普通侧栏停靠。智能组标题直接起拖，整组落点扩大为目标上／下半区；去掉重复挂载。来源页因固定引用保活，关闭固定实例释放临时状态。预设不携带绑定，切换保留真实实例。后续接通 `tool-docking-v1`：普通／固定工具通过一个实例承载层在左／中／右的普通标签组移动，中央保留位置引用，绑定身份不随位置变化；智能入口仍保留。中央工具获得操作焦点但不成为主页面上下文，也不接收窗口级素材输入。普通组整组和智能组仍限两侧，中央阅读页移入侧栏暂不开放。

- 智能工具拖出，复制界面实例、保留入口，绑定当时页面。
- 普通移动、边缘新组、组内合并、取消、超限／失效／最小尺寸反馈。
- 接通支持新声明的工具在中央普通组和两侧普通组之间移动；旧页面默认不擅自扩大放置范围。
- 关闭、重载及恢复时检查直接绑定；共享数据与局部状态分开。

验收：拖出“筛选：图片”后去读 PDF，独立筛选仍控制图片集合；关闭集合后提示失效，不误控另一份同名页面。拒绝复制时没有空容器和服务重复启动。

### 第四批：整体收口（当前范围已完成）

结构及公共示例的验证范围已记录在[开发与验证](开发与验证.md)，现行接口集中到[工作台 API 索引](../plugins/工作区布局.md#工作台-api-索引)。用户确认后续可以改两侧图标选择器和智能容器外观，保留身份、上下文、位置与生命周期规则；这不要求新增容器类型。以下工作作为每次改外观／接入业务插件时的核对项，未接入的业务插件和 Windows 实机仍不声称已验收：

- 复核布局预设、未知插件、重载、快捷键、焦点及窄窗口行为。
- 清理被替代的顶栏／旧侧栏渲染分支及重复状态；迁移仅保留在读取边界。
- 选用户实际启用的代表插件验证；遇到缺口再修相应适配，未测插件明确列出。
- 完善公共 UI／工作区／生命周期／预设文档及小型接入示例，再交用户体验。

## 11. 验证与完成标准

测试沿已有布局、工作台服务和页面生命周期用例补关键失败回归，不按每个组件重复堆测试。类型检查、构建及受影响集成测试通过后，用临时仓库、独立 `RM_USER_DATA` 做真实 Electron 操作：

1. 左右展开／收起、顶部对齐、控制键／拖动区、窄窗口与多分屏。
2. 普通组移动／合并／独立分区，状态和输入焦点保留。
3. 集合 A、集合 B、阅读器三种来源切换；点击侧栏／设置／命令不丢来源。
4. 智能工具显隐、配置恢复、无匹配占位与不必要请求抑制。
5. 拖出工具后独立绑定；同一目标多个界面实时更新；目标关闭、卸载、失效／超限和拖动取消。
6. 旧工作区／预设转换，新布局重启恢复，未知插件暂缺与重新出现，保存失败不覆盖旧存档。
7. 已有编辑草稿、正常退出检查与命令捕获来源仍成立；代表服务不因布局动作重复启动或停止。

性能关注首次挂载数、重复订阅／分面查询、拖动中的重建与工具切换后的后台工作。用相同页面／插件组合做简短前后对照，不承诺多开实例无额外成本，不为此另起全面性能工程。

Mac 的真实验证与 Windows 的窗口外观验证分开报告。仅布局改动无需为测试数量额外导入新素材；如果实际改动触及加工、导入或原生依赖，再执行相应新文件导入验证。

完成标准：用户能理解每个区域装什么、工具服务谁、拖出后控制谁；宿主公共接口能支持后续插件接入；原有数据、草稿和日常功能可接续；文档明确已实现与未验证范围。

## 12. 本轮暂不实现

- 任意第三方容器渲染器、布局脚本或全面复刻 Obsidian／VS Code。
- 底部面板、浮动窗口、跨窗口拖放、侧栏内左右嵌套分割。
- 自动寻找最近有效页面、无目标自动开集合、多级挂靠和通用上下文表达式语言。
- 强制所有插件支持多实例、适配所有区域或改写全部业务界面。
- 全库标签启动器、完整阅读目录／字幕等新的业务功能；各插件后续按真实需要接入。
- 仓库／文件空间迁移、MCP 扩展或新的通用编辑／数据缓存框架。

本轮不再为未出现的需求继续扩容器体系。后续改外观或接入业务插件时复用已形成接口；遇到需要改变行为边界的具体场景，再说明取舍并增补必要能力。
