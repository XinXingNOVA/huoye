# L0 全权主理实施规划

这份规划保留了 2026-11-17 的阶段设计和分批实施记录。当前各层的完成度、权限、验证证据与候选缺口统一见 [AI 使用模式与验收](AI使用模式与验收.md)。

目标是让外部 Agent 根据用户的资料和整理目标，发现可用能力，装配仓库，建立整理规则，处理素材，最后交付可直接使用的工作现场。用户确定方向与授权范围，范围内的预演和执行由 Agent 连续完成；超出授权、发生冲突或缺少能力时，返回具体原因与可继续的入口。

主线分为三个可独立验收的阶段。1A、1B、1C 已按授权实现，视觉组合的 2A 和 3A 首批按实际问题补齐；其余批次与默认选择仍是实施建议；接口名称在相应批次按现有契约确定，不提前锁定工具数量。每批完成代码、必要文档、针对性回归和真实流程验证后收束，不积攒到最后统一验收。

## 目标场景与阶段交付

贯穿场景：用户提供一个图片与 Markdown 参考资料目录，要求建立毕设素材库，按内容整理分类、填写字段，并安排适合浏览与筛选的工作台。

| 阶段 | 用户能得到什么 | 结束标准 |
| --- | --- | --- |
| 一 自主开工 | AI 选择获准的能力，后台建好仓库，处理安装与启动失败 | 从零仓库出发，经 MCP 建成配置正确的托管仓库，中断后继续同一任务 |
| 二 完成整理 | AI 建结构、读内容、导入分类填值，报告成功与遗漏 | 本批输入都有明确结果，所需派生内容经过核对，重试不重复执行已完成写入 |
| 三 交付工作现场 | 用户打开即见合适的页面、筛选与布局，并能查看本次结果 | 保存视图与工作台实际可用，重启能恢复，交付不覆盖用户后来的工作 |

第三阶段另有插件开发验收批次：外部 Agent 在隔离测试环境中打包、安装、导入、检查与展示一个独立插件。它复用上述能力，可在产品交付批次之后独立完成。

## 最初约定的实现边界

- 首版采用外部 Agent 与现有应用级 MCP。宿主提供可靠能力与结果，不承载模型规划、聊天、定时调度或通用 Agent 工作流引擎。
- 仓库核心继续是唯一数据写入者。UI 与 MCP 复用应用服务和业务命令，字段、标签、文件夹等业务留在各自插件。
- 首批后台运行复用隐藏窗口，保证不抢焦点、可接续、可显式展示。它仍有渲染进程；完全无窗口常驻需要另行解耦会话生命周期。
- 数据库、原件、应用配置、工作台与任务记录继续分别管理。跨这些范围的步骤按实际结果接续，不宣称整批跨层事务回滚。
- 创建位置权限只约束建库。外部 Agent 扫描源目录使用自身已获准的文件访问能力；应用的 MCP 授权不约束 Agent 的终端权限。
- 新库优先使用随库独享文件空间。复用已有空间必须核对已允许的目标身份与成员权限；普通文件夹原地引用不属于现有文件空间能力。
- L1、L2、L3 可复用本轮能力，但细粒度规则内整理、实时焦点选区、视觉差异验收和批次撤回分别推进。

## 第一阶段 自主开工

### 1A 托管授权与能力发现

交付：应用尚未打开仓库时，Agent 能知道允许在哪里建库、哪些能力可用、哪些需要用户处理。

实施内容：

- 为托管创建和本库管理建立明确授权。界面可采用 `admin` 档位，内部按读取、数据整理、结构修改、插件选择与工作台配置检查；安装应用包和空间原件权限独立。
- 新库仅在用户开启托管创建策略后自动取得管理授权；既有仓库显式授权。按现有路径与仓库身份核验，可收回，不通过调用参数自报管理员身份。
- 旧授权与 token 保持可接续，不自动将已有仓库升级为管理权限。实施前的 `organize` 并不等于严格 L1：还包括记录永久清除，插件操作也未声明结构影响。梳理这些入口，给出明确迁移规则；本轮默认托管操作不提供不可恢复清除。
- 建立业务操作影响类别的最小声明与检查入口，支持数据修改和结构修改的区别；第二阶段补业务操作时必须使用。对未分类操作采用明确的不支持或迁移提示，不能靠操作名称猜测，也不能把可信插件声明称为代码沙箱。
- 提供应用能力目录：内置、随附、已安装包、已登记套件和方案，以及版本、依赖、兼容、许可使用和不可运行原因。静态目录不执行插件代码；无运行验证的能力不标成已成功运行。
- 能力目录只披露本次授权可见的信息，不带密钥、任意本机目录或其他未授权仓库的内部内容。来源与包身份由宿主登记核对。

完成标准：零仓库可发现能力；未授权调用被明确拒绝；预授权范围内无需逐步人工确认；旧配置能打开且不提权；撤权后新调用与后续执行阶段重新检查。

1A 已实现并验证（2026-11-17）：

- 本机设置增加 admin，支持明确选择“新仓库由 AI 托管”；保持旧模式、token、原件授权和回执，不自动提权。
- `list_ecosystem_catalog` 提供有快照的分页目录；内置模块、随附／安装包、套件和方案只做静态校验，runtime 明示 not-checked。权限与接口可用性分开；目录不执行插件、不安装、不授信、不访问未授权库。
- `operations.effect` 区分 data/structure，外部包使用 `operation-effects-v1`；调用前按宿主声明检查，并在异步读取后重新检查授权和目标核心。缺省分类明确返回升级提示，内置文字／文件与独立示例已接入；未批量修改其他独立业务插件工程。
- MCP 永久清除入口关闭；trash/restore、入库、原件授权仍复用既有业务。已派发操作不承诺因撤权自动回滚。
- 类型检查、构建、56 项相关回归及 macOS Electron 隔离双库／重启流程通过。当前是真实 SDK stdio 客户端验证，尚未做独立 Agent 自主使用与 Windows 实机验收。命令与范围见[开发与验证](开发与验证.md#l0-1a-托管授权与能力发现2026-11-17)，当前协议见[服务插件 API](../plugins/服务插件%20API.md)。

### 1B 共用建库服务与后台接续

交付：Agent 选择起始方案或明确插件组合，后台建库；中断后能查询并继续。

实施内容：

- 从启动页建库编排中提取 UI 与 MCP 共用的调用入口，复用目录认领、预分配仓库身份、首次配置事务与布局接续。
- 支持预演、创建、读取状态、继续和取消接续。预演固定方案、包选择与修订；提交复核，旧预演失效则重新规划。
- 保留 MCP 的 `requestId` 幂等语义，将其与实际创建任务关联。任务完成后的回执仍可查询，不能因撤下临时任务而再次建库；同请求参数变化拒绝。
- 已确认任务始终使用原包摘要和配置，不因套件更新改变恢复目标。取消只停止后续步骤，保留已产生的仓库与数据，并报告实际完成到哪里。
- 后台选项覆盖首次创建、再次打开、重试与插件重载，避免现有打开路径主动聚焦窗口。增加显式显示入口；运行、装配和工作台就绪状态分别表达。
- 应用仍需运行。正常退出协调保存与关闭；进程中断后通过任务状态接续，不把隐藏窗口称为独立守护服务。

完成标准：Agent 不点击启动页即可建成库；选定插件参与首次装配；屏幕不被抢焦点；同请求重试只有一个库；在目录认领、初始化、插件启动和响应丢失处中断后均可核对或接续；原启动页流程保持。

1B 已实现并验证（2026-11-17）：

- `preview_library_creation` 与增强的 `create_library` 共用启动页预演、认领、首次事务初始化、核心装配和工作台接续；支持方案或明确插件列表，预演修订与创建授权绑定。非默认选择需要 admin 创建策略；本批仅使用随附确切摘要或目标位置已获准的本地包。
- `get_library_creation`、`resume_library_creation`、`cancel_library_creation` 持久保存原身份、选择与终态；重试不换用更新后的方案、不覆盖用户后来的配置、不恢复撤回的授权。取消只截断后续阶段，已有数据保留；旧失败回执没有可恢复计划，仍需在应用检查原目录。
- 默认隐藏创建／打开，覆盖附属画面与重载；`show_library` 显式显示。正常退出保存前后台意图，重开保持。创建阶段、当前核心运行、工作台加载／布局回执分别报告；completed 不替代 workbench=ready，更不代表素材加工完成。
- 类型、构建、41 项针对性回归和三个 macOS Electron 专项通过：MCP 后台建库／强制中断／正常退出重开、原应用 MCP 双库、原启动页创建。真实 utilityProcess 新文本加工通过；没有独立 Agent 自主使用或 Windows 实机验收。后台仍使用隐藏窗口，应用须运行；陌生包授信、已有库插件调整和通用工作台编排留待后续。

### 1C 获准包安装与本库能力调整

交付：缺少本地可用插件时，Agent 能在许可范围内补齐；建库之后也能调整本库插件组合。

实施内容：

- 复用现有本地 `.rmplugin` / `.rmsuite` 安装预览与逐项结果。预览确认绑定具体内容，安装与本库启用分开；依赖同样检查许可。
- 使用应用随附的确切包与用户事先允许的包策略。仅“曾经安装”不自动等同于允许 AI 在所有仓库使用；版本变化按照明确策略重新核对。
- 新代码超出许可时返回待授权状态，并由应用提供用户入口。获准后从原任务继续；Agent 不能替用户确认自己的提权请求。
- 本库插件变更复用组合预演、保存、生命周期检查与重载。显式报告配置已保存、运行失败和布局待接续，数据随停用保留。
- 新库默认空间自动完成；已有空间只从用户允许关联的目标中选择。关联不自动升为共享、不修改其他成员权限、不把关联等同于收录。
- 应用级卸载、跨库替换更新和联网插件市场不进入此批次。

完成标准：用一套含缺包的本地方案走通安装、启用和后台建库；缺许可、坏包、依赖不兼容与启动失败有准确结果；重试不重装成功项；其他仓库配置保持。

1C 已实现（2026-11-17）：固定本地归档快照、人工确切版本许可、逐项安装及回执；本库组合预演／提交／状态／取消复用原页面保存与重载；获准空间按身份关联。停用和取消保留数据，终态回执不阻止包更新。未开放网络市场、跨库自动更新、应用卸载或任意工作台编排。接口见[服务插件 API](../plugins/服务插件%20API.md)，实际验证范围见[开发与验证](开发与验证.md#l0-1c-获准包安装与本库能力调整2026-11-17)。

第一阶段结束时，已有一个配置正确、可以显示和恢复的仓库。此时不宣称已经理解或整理用户素材。

## 第二阶段 完成整理

### 2A 结构规划与业务操作接入

交付：Agent 能建立这个场景所需的模板、字段、分类与查询规则，再为素材填写数据。

实施内容：

- 先核对第一套使用组合的实际包版本与运行能力，按需要接入自定义字段、标签及分组、文件夹、评分、笔记、来源和保存视图；不要求所有实验插件一起迁移。
- 各插件通过已有 operations / queries 发布结构和数据操作。宿主只增加公共影响分类、授权与预演支撑，不写各插件的 MCP 特例。
- 建模板与填字段分开；改字段类型、删除选项、删除模板等需要受影响范围与版本基线，执行时拒绝旧预演覆盖新编辑。第一条完整场景优先用新增结构，已有结构破坏性迁移不顺带扩大。
- 使用返回的稳定身份继续后续动作，不通过名称或列表顺序猜测模板、字段、文件夹和视图。重复创建沿用请求回执。
- 定义、命令、索引与视图校验共用现有业务路径；未知或未启用能力提供阻塞原因。

完成标准：Agent 建立一套包含文本、单选等必要字段的模板与分类，批量填值并读回；结构操作在普通整理授权下被拒绝；同一业务由 UI 和 MCP 执行结果一致；并发修改和失败不留下半份结构。

### 2B 内容读取与本批加工就绪

交付：Agent 能实际读取正文和图片，知道本批需要的派生结果是否已准备好。

实施内容：

- 复用现有正文分页读取，增加按已授权素材身份取得有界图片预览的入口，并在实际外部客户端验证模型能读取图像，而非只拿到文件名或路径。
- 图片大小、内容版本、无可用预览、原件离线和不支持格式均显式处理。素材正文及插件说明作为数据，不提升为用户命令或授权来源。
- 加工查询按本批素材及所需产出判断，返回等待、可用、失败、缺少处理能力或已过期等结果。不等待无关仓库任务，也不以整个队列空闲表示所有产出成功。
- 读取期间版本变化需要重新核对；等待有界，超时返回当前进度和可续查信息。按需加工按已有调度契约触发，不静默跳过所需产出。
- 先覆盖图片与 Markdown。PDF 优先沿用已有提取正文，扫描件 OCR、音视频理解和 EPUB 等再按实际场景接入。

完成标准：真实 Electron 导入全新图片与文本后，外部 Agent 能读取并利用内容；缺处理器、单项加工失败和超时不会阻塞全部结果或误报成功；读取的是本库认可的版本。

### 2C 批量整理与进度恢复

交付：一批素材经过导入、加工检查、分类和填值，全部输入都有去向，失败项可继续处理。

实施内容：

- 外部 Agent 根据已授权目录生成输入清单，按现有单次上限分批导入；保留输入与返回素材身份的对应，以及新建、复用、恢复和失败差异。
- 建立最小整理批次记录，关联输入、请求 ID、受影响素材、步骤结果与未完成原因。复用已有导入和操作回执，不另造业务写入队列。
- 批次记录持久化且有界、可分页；只记录恢复与交付所需事实，不保存模型思考或无关秘密。明确完成后的保留与用户清理方式。
- Agent 负责规划与续跑；宿主负责权威执行结果。连接中断后先核对回执和当前数据，再继续，不能把旧回执当作当前状态。
- 对已经被人修改的字段使用现有基线检查或增量命令，冲突单列，避免重跑覆盖。无法可靠分类的内容进入待整理结果，并说明原因。
- 分类质量使用人工标注的小样本检查，再做数百项批量流程验证；模型判断与程序数据正确性分别验收。

完成标准：混合资料目录可完整整理；输入总数与各类结果对得上；中途退出后能够接续已完成进度；无重复副作用、无静默覆盖；待处理项明确且可再次执行。

第二阶段结束时，库中的资料已能通过实际内容、字段和查询使用。批次记录不是永久审计或整批撤销栈。

## 第三阶段 交付工作现场

### 3A 保存视图与本库工作台编排

交付：首次展示时已有适合任务的筛选视图、页面与侧栏安排。

实施内容：

- 使用业务操作创建保存视图，再通过本库内容定位契约打开这些实体对应的页面；显示布局与查询规则分别设置。
- 扩展现有工作台编排的可验证入口，处理页面类型、实例规则、缺少插件、区域容量与呈现选项。由宿主解析与保存，Agent 不直接改工作区 JSON 文件。
- 区分本库初始工作现场与可跨库分享的预设。前者可以绑定本库实际身份；后者继续遵守可迁移规则，不把本库 viewId 塞进共享模板。
- 首版布局以已有单区或双区、普通工具及侧栏能力组合；具体素材阅读页、跨库实体映射和任意外部容器按后续需求推进。
- 默认只布置新任务库或明确允许调整的工作现场。提交前检查布局修订与用户变化，冲突时保留现状；不得丢草稿或通过重建实例强制覆盖。
- 应用结果与工作台存档一同持久化，沿用完成回执，恢复时不重复覆盖用户后来的布局。

完成标准：真实界面中看到正确的视图、表格或瀑布流、侧栏与选中页；重开保持；已编辑的页面和草稿不丢；预设缺项与过期布局修改明确拒绝。

### 3B 结果交付与显式展示

交付：用户收到一个可直接使用的库，以及本次做了什么、剩下什么的简明说明。

实施内容：

- 基于第二阶段的批次事实提供结果摘要：素材范围、使用的结构与插件、成功数量、失败和待整理项，以及可直接打开的结果集合。
- 完成条件核对数据结果、必要加工、插件实际运行和工作台应用回执。允许明确标记部分完成，不将“窗口已经出现”视为全成功。
- 显示与聚焦由独立动作触发；任务结束也可保持后台。重复展示复用同一仓库，不新建多份现场。
- 首版结果页是查看已生效结果。用户可用已有编辑与线性撤销处理问题；不提供暗示任意批次可逆的“整批撤回”。
- 字段差异、逐项接受、写入前草案与冲突感知的批次撤回留给 L2 专题设计，不改变本轮完成标准。

完成标准：用户只看交付入口即可找到本批素材、主要视图与异常项；真实就绪后才标完成；正常重启仍能查看结果；展示不会抢走另一仓库的编辑状态。

### 3C 反哺独立插件开发

交付：开发 Agent 能用公共能力完成一个独立插件的构建与集成验收。

实施内容：

- 复用现有独立工程工具链和测试脚本，由 Agent 执行检查、打包，再用本轮公共接口装配临时仓库、导入样本、读回数据和加工结果。
- 使用独立 `RM_USER_DATA`、临时仓库与临时文件空间，开发包的使用许可限定到明确的开发环境，不能带入日常应用授权。
- 通过测试用例验证新增、升级、停用保留与重装接续中与该插件有关的行为；界面插件继续用真实鼠标键盘、画面或既有 capture 流程验证。
- 产出源码提交、包版本与摘要、测试步骤及结果。模型对结果的自评不能替代确定性断言和实际界面检查。
- 临时库只隔离业务数据，不是任意 Node 代码的安全沙箱；需要执行隔离时使用单独的受限环境。本轮不提供生产环境自动发布或未知代码自动信任。

完成标准：一个使用公开 API 的独立插件，从构建到真实 Electron 新文件加工、业务结果与必要界面检查走通；过程可以按记录复现，无宿主私有导入或日常数据依赖。

## 实现归属与入口

### 验收驱动的设计记录（2026-11-17）

用户认可通过维护者在正常应用中的实际开发／验收流程发现能力缺口。现有建库、插件配置、业务读写与工作台编排优先复用；后续先补运行状态、本批加工等待与诊断，再补预览和会话感知，最后贯通开发加载及生命周期。以下为纳入本轮讨论后的实施建议，不表示新增接口已经开放。

首批已实现：`get_library_status` 按 sections 汇总现有核心、装配／服务、工作台就绪及队列，`get_processing_status` 按指定素材与产出查询／等待，核对输入新鲜度、上游依赖、失败、只读授权及会话变化。视觉素材库原生验收已改用公开 MCP 等待新图的缩略图、画幅和色板。工具列表由 48 增至 50；本批没有加入开发专用工具。详细语义见[服务插件 API](../plugins/服务插件%20API.md#仓库运行状态与本批加工2026-11-17)。第二批已实现 read_preview 单图／最多 12 项编号拼版，以原生 MCP 图像返回；导入快等在持久回执之外返回 processingObservation。沿用只读授权、已接纳版本和有界加工服务，工具总数为 51。接口见[服务插件 API](../plugins/服务插件%20API.md#素材预览与导入快等2026-11-17)。后续会话感知、开发验收和视觉批次验收的实测范围见 [AI 使用模式与验收](AI使用模式与验收.md)。

- **控制工具与 Schema 规模**：讨论时静态 MCP 列表为 48 项，首批后为 50 项，第二批后为 51 项。按业务语义合并状态读取，优先聚合核心在线、实际插件摘要、工作台就绪和有界诊断，按需返回；本批加工状态与有界等待可共用读取入口，重试保留明确写入边界。不为压缩工具数量建立任意动作路由。连接配置可选择日常、管理、开发等工具集合；切换后明确刷新或重连，每次调用仍由宿主核对当前权限，不能仅靠隐藏工具授信或拒绝。具体分组与数量在实现时决定，以实际序列化体积与客户端使用效果验证。
- **开发许可独立**：开发目录的构建／应用先限定到用户预先许可的目录、插件与验收仓库，复用现有开发加载服务。首批整窗截图也只面向明确的验收许可与目标窗口。独立配置目录隔离数据和授权，不等于隔离插件代码执行。普通关库可沿用正常生命周期权限和保存保护；强制终止进程与故障注入由外部验收器管理其自行启动的隔离实例。开发开关不自动扩大普通库的 admin 权限。
- **素材预览与软件截图分开**：素材预览是日常只读能力，读取本库认可版本的受控预览，以 MCP 图像内容返回。支持单图与有界拼版（建议首批最多 12 项），保持比例，附稳定编号到素材 ID、内容版本的映射；失败项保留编号并报告原因。拼版用于初筛，细节可再取单图；视觉成本与可辨识度实测，不承诺固定节省比例。软件窗口截图归窗口会话许可，不由素材读取权限推导。
- **导入快等复用同一加工查询**：可在导入工具提供有上限的可选 waitMs（建议初始上限 2 秒，默认不等），只观察本次返回素材及所需产出；collect=false 明确无收录加工可等。先取得持久导入回执，再做有界观察；等待预算不进入写入签名，当前加工快照不写成永久导入结果。超时或单项加工失败仍保留成功导入结果并给出待办；重试沿原回执继续观察，不再次导入。独立的批量状态／等待能力继续支持大批量任务。
- **会话感知按日常 L2 能力设计**：读当前窗口／页面、有效查询、selectedIds 和实际呈现版本，显式区分焦点／选择变化与查询结果更新。推送视图或素材定位绑定目标窗口／页面及会话修订，用户中途切换时报告冲突；结果高亮与用户框选分别管理。初次就以正式会话服务提供，复用于验收；保存视图规则仍属于仓库，窗口状态仍属于本机工作台。展示结果不产生新的撤销语义，现有线性撤销不冒充任意 AI 批次回滚。
- **验收脚本保持外部**：样本生成、预期值、确定性断言、报告、应用进程重启和临时目录回收归工程的验收器；功能场景通过公开服务，按钮／快捷键／拖拽通过真实界面操作。正常应用提供稳定可访问名称与必要会话状态。单元测试及进程崩溃、损坏文件等隔离故障测试保留各自形式。

## 验证与推进方式

- 1A 至 1C 顺序推进，随后 2A 至 2C，再完成 3A、3B。3C 独立收尾。批次内按接口、实现、必要迁移和验收完成闭环；不因文件拆分或测试数量增加延长任务。
- 授权、建库和 MCP 优先扩展既有 `application-access`、`library-creation`、`plugin-presets` 等回归与 `application-mcp-check.mjs`，包安装复用现有实际流程；新增应用级工具后更新旧测试中“所有其他工具都要求 libraryId”的假设。
- 导入、加工与新媒体读取必须在运行中的 Electron 导入新文件，使用独立配置、临时库和临时空间。预制素材不能代替新文件加工。
- 工作台使用真实页面、插件和输入操作检查，验证焦点、隐藏窗口、草稿保护与重启恢复；不能只检查 JSON 或发送内部动作。
- 每阶段至少一次真实外部 Agent 接入。脚本 MCP 客户端证明协议与数据行为，实际 Agent 证明发现、图片消费与错误解释可用，分别报告。
- 阶段验收先选少量可人工核对的样本，再做数百项规模验证；性能结论需要同口径测量，不由通过功能测试推定。
- 当前以 macOS 验证推进；Windows、长期常驻、跨客户端表现按实际覆盖列明，不将已有历史记录当成本版验收。
