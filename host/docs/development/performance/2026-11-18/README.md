# 2026-11-18 发布前性能基线

两套基准依次运行在同一台 Apple M5（10 核、16 GiB）上。系统为 macOS 26.4（25E246）arm64，Node 为 26.7.0，Electron 为 44.7.0，Chromium 为 152.0.7977.130。

五万、十万真实文件的后续测试包含后台收录和全空间刷新期间的搜索、滚动与点开详情。[大库日用实测](大库日用.md) · [空间刷新优化前后对照](空间刷新优化.md) · [自动收录与版本核对复测](增量收录与版本核对.md)

十万项库清空搜索后，查询、进程排队和可见缩略图的重复测量见[清空搜索回到网格](../2026-11-19/清空搜索.md)。

## 优先排查

1. **先拆解空间刷新。** 万项单空间刷新中位数 1,856 ms，同库的无变化扫描仅 62 ms。把同样多的素材分到三个空间后，刷新其中约三分之一的引用降至 649 ms。单空间刷新期间，核心空请求最长等了 2,401 ms，渲染计时器最大延迟仅 1.2 ms。下一步可分别计时引用查找、逐项原件可读性检查、重新调度与通知，并在有明确文件变更时验证缩小刷新范围的收益。[刷新入口](../../../../src/core/host.ts) · [引用查找](../../../../src/core/file-spaces.ts) · [逐项检查](../../../../src/core/space-refresh.ts)
2. **用同一批十项拆解组合删除。** 万项库里，仅回收仓库记录约 1.1 ms，连同原件一起处置并通知窗口要 2,245–3,729 ms。三空间组连预览也达到 403 ms。执行会复核引用、调用系统废纸篓、等待受影响空间刷新。下一步分别记录各阶段和调用次数，再判断第一项优化能覆盖多少耗时，同时保留处置前的一致性复核。[组合删除执行](../../../../src/application/item-disposal.ts) · [空间通知](../../../../src/main/space-notifications.ts)
3. **复测刷新后的查询等待和内存回落。** 万项单空间笔记查询第一轮 5.5 ms，此后四轮 180–193 ms。现有基准每轮末尾会刷新空间，单凭这组数据无法把额外等待归因于全文索引。可将连续查询、刷新后查询分开重跑，记录核心空请求和内存随时间的变化。该进程的工作集从首屏 216.5 MiB 升到读后 578.1 MiB、写后 730.1 MiB。现有快照只到写入结束，是否持续增长需用重复操作及空闲回落实测。

## 测量条件

- **核心**使用干净提交 `9c0e5e7`。现有基准用测试插件定义创建 10 万个身份，每项写文件、图片和标签块，每十项另写一条笔记。生成时暂停加工调度，各操作各计时一次。[全部 19 项耗时](core.tsv)
- **Electron** 使用干净提交 `98aec88`，相对上一个提交只修正了测试程序定位工作台搜索框的方式。第一次用默认构建准备夹具时缺少标签块，在计时前退出。正式测量从当前插件源码重新打包，经 `RM_PLUGIN_BUNDLE` 随构建载入 12 个外部包，加上 8 个内置插件，四组启用清单一致。[版本、逐次耗时、响应性和内存](electron.json)
- 真实 Electron 窗口使用隔离用户目录和临时 v4 文件空间。1,000 与 10,000 项分别测试单空间和三空间。三空间组把一个随库空间和两个共享空间绑定到同一测试仓库，均匀分配素材。刷新测第一空间，组合删除的十项则跨越三个空间。
- 每组用三个新进程测启动，再开一个进程测操作。首屏要求数量正确、可见缩略图加载成功且经过两帧。缩略图已生成，系统文件缓存保留。表中 Electron 耗时取中位数，读操作五次，界面搜索、导入和删除各三次。样本较少，保留原值便于复核。
- 导入每次使用十个不同的 1600 × 1000 纯色 PNG。“缩略图就绪”计到收录的素材都有缩略图，且检查时没有加工错误。大照片、视频、PDF、后台积压时的滚动和长时间空闲回落需另测。

## 复测

在宿主根目录用相同插件版本、本机磁盘和相同规模依次运行。插件源码位置由 `RM_PLUGIN_SOURCES` 或本机的 `.plugin-sources.local.json` 指定。

```sh
npm run bench
npm run plugins:pack
RM_PLUGIN_BUNDLE=artifacts/plugins/catalog.json npm run bench:app
```

Electron 会打印结果目录；其中的 `summary.json` 在全部场景完成后带有 `complete: true`。将下面第二个文件参数换成该目录的实际路径，即可与本次归档逐项比较。

```sh
node scripts/performance/compare.mjs docs/development/performance/2026-11-18/electron.json artifacts/performance/本次运行目录/summary.json
```
