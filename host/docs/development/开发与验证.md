# 开发与验证

## 环境与独立构建

Node.js 24+、npm、Git。Electron 及 SQLite／图像处理包含原生依赖，必须在目标系统安装；预编译包不可用时需要该平台编译工具。依赖版本以锁文件为准。

```sh
npm ci
npm run typecheck
npm test
npm run build
npm start
```

开发使用 `npm run dev`；开发和预览默认使用独立 `.local/user-data`，可用 `RM_USER_DATA` 指定其他隔离目录。宿主普通构建不需要外部插件源码，会读取已提交的发行套件并附带对应插件包。`out/` 是可重建编译产物，`artifacts/` 放插件包、发行及验证结果，`examples/` 是 API 示例。

源码输出不强制镜像，也不复制开发机 npm 配置。需要镜像时由使用者自行设置 npm/Electron 下载环境；不要在源码锁中提交凭据。锁文件将已知公共镜像的 resolved URL 规范到 npm 官方域名，版本与 integrity 保持。

Electron 运行程序可能在首次启动时才下载；如果停在 `Downloading Electron binary...`，先检查网络。需要可选镜像时，可在当前终端设置 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`，再运行 `node node_modules/electron/install.js`。PowerShell 使用 `$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'`。不要关闭包内 checksum 校验或把某台开发机的 Electron 目录写入配置。npm 的离线缓存安装成功不代表 Electron 的下载已完成。

## 独立插件与附带组合

源码工作区顶层先执行：

```sh
node host/scripts/release/configure-source.mjs
```

该命令从示例生成 host 的 `.plugin-sources.local.json` 和各插件的 `.rm-dev.json`，使用相对路径；不会覆盖不同的已有配置，也不会启用应用开发目录。有 `package-lock.json` 的插件先在自身目录运行 `npm ci`。当前 `file-editing` 没有独立运行依赖和锁文件，直接使用已安装的宿主工具链，跳过这一步。随后在插件目录运行：

```sh
npm run configure
npm run check
npm run pack
```

包输出到插件自身 `artifacts/<id>.hyplugin`，在应用中安装并按仓库启用。开发目录则由仓库设置添加源码工程，源码变化后统一应用与重载。

普通构建直接读取 `packaging/starters/catalog.json` 所列的发行套件，首次启动即可按方案建库。安装包为每个共享插件保留一份经过摘要校验的内容。

需要测试自定义发行组合时，可用 `npm run plugins:pack -- artifacts/bundled` 从配置的独立源码构建附带包，再指定 `RM_PLUGIN_BUNDLE=artifacts/bundled/catalog.json` 构建宿主。此时只登记所需插件摘要全部匹配的发行套件。

## 验证范围

默认 `npm test` 跑宿主测试；选择与改动相关的文件即可。`npm run test:source-release` 检查源码提取的固定提交、清理、失败保护与可重复输出，无需安装 npm 依赖。

`npm run test:plugins` / `npm run typecheck:plugins` 是需要显式外部源码的可选集成，通过 `RM_PLUGIN_SOURCES` 或本机来源配置读取。插件纯业务测试在各自工程运行，不复制到宿主。

涉及导入、加工或原生环境，构建后还需真实 Electron 验收。例如：

```sh
node tests/electron/application-mcp-check.mjs
```

此流程创建临时仓库、文件空间和独立应用配置，覆盖应用 MCP、写入／导入与重启接续。其他 `tests/electron/*-check.mjs` 按场景选择；capture flow 由测试入口设置 `CAPTURE_FLOW`、`CAPTURE_DIR`，不要对日常仓库运行。仅浏览旧素材或 Node 测试不能代替新文件导入。

## 平台打包与源码提取

Windows x64 使用 `npm run trial:windows` 或 `scripts/release/windows-build.ps1`，脚本自动安装宿主与插件依赖、打包本版可选插件、核对随附目录、校验媒体程序、构建与打包冒烟；不需要手工准备 catalog。失败停止在对应阶段，结果和日志写入本次独立的 `artifacts/trials/` 目录。详见[AI 构建指南](Windows-AI构建指南.md)。`npm run trial:prepare` 可在其他系统验证公共阶段，结果不会标记为 Windows 已验收。跨平台复制 node_modules 不受支持。说明见[Windows 试用说明](../user/Windows试用说明.md)。

macOS 的 `npm run dist:mac` 生成 Apple Silicon DMG 与 ZIP，`npm run pack:mac:test` 仅生成目录测试产物；两者都会准备第三方许可材料。当前使用 ad-hoc 签名，未做 Developer ID 公证。用 `npm run smoke:packaged -- <应用路径>` 在独立用户目录运行安装包冒烟。Windows 本批暂缓。

固定提交与公开文档导出见[源码提取](源码提取.md)。源码、插件包与应用安装包是不同产物，分别记录来源和实际验证范围。
