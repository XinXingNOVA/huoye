# 文件空间工作台：前后端接入约定

2026-10-31。只扩展查询和本机设置入口，仓库与文件空间持久格式不变。空间管理原件，仓库管理收录、回收状态和接纳引用；界面可在一个任务流程中组合它们。

## 列表、搜索与计数

```ts
const spaces = await host.core.listFileSpaces({ includeCounts: true })
const page = await host.core.listSpaceFiles({
  spaceId, scope: 'active', search: '旅行', collectFilter: 'uncollected',
  includeCounts: true, limit: 50
})
// 翻页保留搜索、scope、recordScope 与 collectFilter，传回原 snapshot。
const next = await host.core.listSpaceFiles({
  spaceId, scope: 'active', search: '旅行', collectFilter: 'uncollected',
  offset: page.nextOffset, limit: 50, snapshot: page.snapshot
})
```

只有存在 nextOffset 才翻页。search 最长 256 字符，按显示文件名子串匹配，使用 Unicode 小写转换；不匹配目录，`%`、`_` 是普通字符，不去除输入空格。先筛选再分页，沿用按文件 ID 的稳定排序。

collectFilter 只在带仓库上下文且 scope=active 时可用：

| 值 | 口径 |
| --- | --- |
| all / 省略 | 全部 active 文件 |
| uncollected | 没有对应的现存本库素材；彻底删除后的旧映射不算已收录 |
| collected | 对应素材存在、文件引用匹配且不在仓库回收站 |
| trashed | 对应素材在仓库回收站；再次收录会恢复原身份 |
| outdated | collected 中，空间当前版本与本库接纳版本不同的文件 |

这些状态与文件是否可读正交。缺失文件也保留在列表和计数中供诊断；收录或预览前检查 state。outdated 是 collected 的子集，不能把全部徽章相加。SpaceCandidate 新增 collectionState、hasUpdate，原 collected（素材 ID）、trashed、adoptedVersion、updateError 保留。

独立空间入口 `window.bridge.spaces.files(root, input)` 支持文件名搜索及空间汇总，但不理解仓库关系，传入非 all 的 collectFilter 会报 LIBRARY_CONTEXT_REQUIRED。仓库入口在 recycled/records 使用关系筛选会报 INVALID_INPUT；不会悄悄忽略参数。

includeCounts 默认不启用：

- SpacePage.total：**当前搜索与筛选后的总数**。
- SpacePage.counts / SpaceBindingInfo.counts：**整个空间的汇总**，不受搜索和当前筛选影响。
- active、recycled：对应文件列表与空间回收站，均排除归档记录。
- records：记录管理的 current 分区；archived：记录管理的 archived 分区。
- 仓库额外返回 uncollected、collected、trashed、outdated，均在 active 范围内。
- 离线或解除关联的空间不提供伪造的零计数，保留 error；undefined 表示未知／未请求。

`getImportSettings().bindings[].uncollected` 已复用新口径。原 pending 继续表示自动收录待处理队列，**不表示待接纳版本**；徽章请用 counts.outdated。

snapshot 是不透明的查询快照，不持久保存。空间变化、查询条件变化、仓库写入或核心重载后可能失效；收到 SPACE_CHANGED 清空旧页和批量选择，从首页刷新。仓库写入采用与通用查询相近的保守失效策略，后台派生写入也可能要求重读。旧 version 参数继续兼容，但它只检查空间版本，不能代替 snapshot。

普通无筛选翻页只补查当前页的收录关系；筛选与汇总按需读取元数据，不扫描原件内容或生成缩略图。子串搜索及关系汇总仍有随数据量增长的查询成本，不应每帧或每个详情组件各自拉全空间统计。

## 未收录预览

可读取的 SpaceCandidate 返回 `reference`，绑定当前具体内容版本：

```tsx
<img src={host.url(file.reference!)} loading="lazy" alt={file.name} />
```

仅对受支持的图片格式和可见项目渲染；state 不可用或 reference 缺失时显示错误／占位。加载失败应刷新状态。reference 是不透明引用，不解析拼接，不替换为系统路径；读取仍检查关联、成员身份、原件生命周期和文件变化。

未收录预览不会创建仓库素材。发布新版本后，旧引用仍指向原版本；解除关联或回收后不保证继续可读。host.url 需要有效关联仓库的路由，不能借此预览未关联的任意空间。这是原文件预览，尚非压缩缩略图缓存。

## 检查器与单素材存储面板

`fileStorageInfo(id)` 新增：

- hasUpdate：已知空间当前版本与素材引用版本不同。
- canRevise / canRecycle：空间对当前仓库的授权，与 listFileSpaces 同源；不包含 MCP 授权，不代表此文件所有操作当前都可执行。不可确认关系时可为 undefined。

有新版时调用 previewFileUpdate(id)，展示 previous/current 的固定版本引用和摘要。确认后用预演返回的 expectedPath、revision、current.id 调用 acceptFileUpdate，并传新 requestId；重试复用 requestId。状态已变化则重新预演。

**接纳只改变本库引用，不要求 canRevise。** 发布原件修改才要求空间更新授权。不可用、回收或其他业务条件仍由预演／提交接口最终判断。历史、替换发布和独立副本继续使用现有公共文件编辑协议，不增加绕过预演的写入方法。

## MCP 设置内的空间授权快捷入口

模块 UI 通过已有 ApplicationUiHost.service 调用，不能直接访问 window.bridge：

```ts
const permission = await host.service('mcp', 'setSpacePermission', {
  key: library.key,         // MCP 设置中已登记的仓库 key，不是任意路径
  spaceId: space.id,
  permission: 'revise',     // 或 recycle
  enabled: true,
  revision: space.revision // 刚读取的空间版本
})
// 返回 { revision, members: [{ id, name, revise, recycle }] }
```

仅允许目标仓库已打开、关联有效且空间身份匹配；空间变更时返回 SPACE_CHANGED，需要重新展示并确认。调用只改空间对该仓库的授权，不改 MCP 的 mode 或 fileSpaces 配置。即使 AI 未授权，也允许用户在本机界面配置空间规则。

界面可以一次明确确认后，先调用这个入口，再用现有 settings / change 保存 AI 授权；分别刷新两层状态。第二步失败时说明“空间授权已完成，AI 授权未完成”，不要声称整体原子成功，也不要擅自回滚用户可能正在其他窗口修改的授权。撤销 AI 授权不应顺带撤销仓库的空间授权。将 read 提升到 organize 也需明确说明，不能藏在快捷按钮中。

此方法仅注册在本机应用服务 invoke，不在 MCP 工具清单或 ExternalApi 白名单；外部 AI 不能调用它给自己提权。

## MCP 与验证

应用级 MCP 的 list_file_spaces 支持 includeCounts；list_space_files 使用相同查询契约。前端和 MCP 不复制筛选算法。

相关验证包含：搜索字面量与大小写、分页与快照失效、回收／恢复、版本接纳、计数口径、未收录引用及解除后的拒绝、缺失原件、空间权限与 AI 权限隔离。真实 Electron 流程使用临时仓库验证图片协议预览、MCP 查询、收录后加工以及本机授权；不改日常仓库。不涵盖前端 AI 新布局的最终交互验收，也未进行大库专项性能基准。

## 当前界面接入

文件空间工作台集中了关联入口、本库收录策略、状态筛选、文件名搜索和单文件版本面板。勾选用于批量操作，行末“版本”用于单文件操作；两者独立。设置页保留快捷配置。外观主题是本机偏好，不写入仓库业务数据。

关联被空间明确拒绝（例如独享空间已有其他仓库）时，回退本次仓库登记；不留下新 pending 条目。若空间已确认登记而仓库侧后续完成失败，仍保留 pending 和凭据供重试。旧版本已留下的条目不做猜测性自动清理，仍可按原入口解除、移除。

发布结果需区分空间发布与本库接纳。界面仅在 library.state 为 accepted 时提示接纳完成，其余状态显示具体结果。预览图片解码失败只隐藏该预览，不触发全空间扫描。

空间授权现统一调用 bridge.spaces.setVersionPermission(root, spaceId, libraryId, permission, enabled, revision)，permission 为 revise 或 recycle；原 setVersionRevise 已删除。本机 MCP 设置的 setSpacePermission 仍保留应用级作用域检查，内部使用相同授权实现。旧文件替换 RPC 已退出，UI／插件继续使用当前 file-edit 协议，详见架构文档的恢复边界。

## 磁盘检查（2026-11-05）

工作台「磁盘检查」使用应用级 `window.bridge.spaces.disk`，业务由 `storage/space-disk.ts` 实现，契约见 `shared/space-disk.ts`。此处操作空间登记，不直接改某仓库数据块。当前是本机显式管理入口，尚未暴露新的 MCP 工具，也不是插件可直接调用的 `window.bridge` 能力。

```ts
const requestId = crypto.randomUUID()
const off = window.bridge.spaces.disk.onProgress(p => {
  if (p.requestId === requestId) showProgress(p.checked, p.total)
})
try {
  await window.bridge.spaces.disk.check(root, { spaceId, requestId, deep: false })
} finally { off() }
const page = await window.bridge.spaces.disk.page(root, { spaceId, limit: 50 })
// 输入 source 代表明确选择文件进行重新定位；不填则核对该版本现存位置。
const input = { spaceId, versionId, source: selectedPath }
const preview = await window.bridge.spaces.disk.preview(root, input)
// 显示 action、blocked、来源、影响范围后，才由用户确认。
const apply = { ...input, token: preview.token, requestId: crypto.randomUUID() }
await window.bridge.spaces.disk.apply(root, apply)
```

- `page.items` 按版本呈现，含状态、当前／历史版、位置、检查时间。`replacement` 表示已登记后续有效内容，不代表旧版恢复；失配历史继续可见。
- `page.pending` 是未完成的明确确认任务。`resume(root, spaceId, requestId)` 校验并继续；`abandon(...)` 只可放弃未登记任务。失败后刷新清单，重试复用请求 ID；不同输入不得复用同一个 ID。
- `cancel(requestId)` 停止本窗口的在途检查／处理；已经提交的登记不会被撤回。预览操作的取消键使用 `versionId`。停止、窗口关闭均不会自动发布待完成任务。
- `check` 的 `deep` 默认 false；首次没有可信 stat 的文件仍需读全内容，完整检查耗时与登记字节量有关。只遍历登记版本，未知文件、数据库、缓存、未发布草稿不扫描。
- 根目录离线与文件缺失分开；不凭缺失进行回收或清理。文件回收状态不因重新定位被自动恢复。
- `preview.action=repair` 必须内容哈希一致；选择不匹配来源会返回 `blocked`。`accept` 只处理当前未回收版，保存新的有效内容，仓库接纳仍按原策略。
- 发布或核对后通知已打开的相关仓库；通知失败不回滚空间事实。重开／主动刷新会核对当前引用。
- `FileUpdatePreview.previous.unavailable` 允许展示旧版损坏信息，不能尝试将该旧引用画成正常预览；current 仍须有效。检查器、存储弹窗及工作台已接通。

空间格式仍为 v4，在集中打开阶段补已知表。不可直接修改历史 hash、关闭版本读取校验或让前端自行改 JSON 路径来“修复”。
