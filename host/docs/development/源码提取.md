# 源码提取

这是源码交付流程：固定提交 → 提取与公开改写 → 校验 → 在独立目录安装和构建。本工具只按已提交发行策略提取，不打安装包或上传；Windows 组装交给提取后的 build-trial 入口。项目及自有插件采用 Apache-2.0；第三方材料保留原许可。

## 配置和导出

Node 24+ 与 Git 即可运行提取器，无需 npm 依赖。每个工程必须已有独立 Git；收到源码 ZIP 后只做构建无需初始化 Git，继续开发并提取新版本时再各自建库和提交。

1. 复制宿主根目录 `.release-sources.example.json` 为忽略的 `.release-sources.local.json`，按实际位置填写宿主与插件 `path`、`ref`。相对路径以配置文件所在目录为基准。首版清单包含 12 个随附插件和 7 个可选插件。
2. 完成本版改动并提交；使用 HEAD 锁定时有未提交修改会拒绝。也可填写明确的历史提交，提取始终不读取未提交文件。
3. 在宿主运行：

```sh
npm run release:source -- lock .release-sources.local.json .local/source-lock.json
npm run release:source -- export .local/source-lock.json artifacts/releases/source-draft.1
```

每版使用新的锁文件和输出目录，不覆盖旧产物。锁文件包含本机工程路径，只留本机；其中提交号、版本、提取器与规则摘要会成为对外来源记录。

```text
source-draft.1/
  source/                  # 可读源码快照
  source.zip               # 同一快照，解压后顶层 huoye/
  source-manifest.json     # 来源与逐文件 SHA-256，无本机路径
  SHA256SUMS.txt            # ZIP 和来源清单摘要
```

源码根目录另有自动生成的 `插件功能清单.md` 和 `plugins.json`，来自本版各插件 manifest 与宿主发行策略；Windows AI 指南随宿主文档交付。

清单的 files 不含自身，避免循环摘要；外层 SHA256SUMS 校验清单本身。ZIP 采用固定来源时间、固定作者和排序快照；同一来源与工具的重复导出应得到相同摘要。只承诺源码快照可复现，未承诺不同平台编译产物字节相同。

## 提取规则与维护

- `packaging/source-profile.json` 锁定插件 ID 和明确排除的内部文档；公开模板位于 `packaging/source-public/`，路径映射到源码工作区根目录。规则、模板和执行工具都取自锁定宿主提交，不能用修改中的模板偷偷重写旧发行包。
- 保留源码、配置、锁文件、必要测试、夹具和 SDK 示例。排除 Git、个人记忆、迁移记录、产物、缓存、本机配置与实际 `.npmrc`；插件 README 去掉工程搬迁段落和历史验收结论，当前业务与兼容规则保留。
- 公共 npm 镜像 URL 规范到官方 registry，保留版本与 integrity；陌生依赖来源拒绝自动导出，需人工审查并明确调整规则。
- 自动检查文件名、大小写冲突、符号链接／子模块、可疑凭据与个人绝对路径、文档文件链接。检查失败不留下半个交付目录。此检查不能代替人工审阅，也不扫描外部网页或校验 Markdown 标题锚点。
- `.plugin-sources.example.json` 与各插件 `.rm-dev.example.json` 按本版来源生成；`configure-source.mjs` 只创建相对目录配置，保留已有不同配置，不自动安装依赖或启用插件。

修改公开说明时改模板；修改当前技术规范时改实际文档。不要只手工清理某个 ZIP。新增源码位置、依赖下载方式或需保留的二进制夹具，应先明确规则和隐私边界，不能一律放行敏感扩展名。

## 独立验收与交付记录

先解压 ZIP 到新的临时目录，不复用开发 node_modules、`.local`、插件输出或机器配置。按输出包的“开发与验证”执行宿主 npm ci、类型检查和构建，按本版范围安装、检查、打包插件。有锁文件的插件使用 npm ci；无独立运行依赖和锁文件的 file-editing 直接使用宿主工具链打包。涉及环境仍须真实 Electron 新文件导入，使用临时仓库和独立 RM_USER_DATA。

验收结果写在外层交付记录，标明系统／架构、命令、实际操作、未覆盖项和源码 ZIP 摘要；不要把运行后的依赖和用户配置重新压回源码包。安装包、正式插件组合、许可证和第三方材料另行完成后才能形成完整试用交付。

提取器回归：`npm run test:source-release`。保留固定提交、可重复 ZIP、隐私拒绝、链接与失败保护等独立风险，不把每条排除规则各写一套重复测试。
