# 前端界面约定

当前按“区域职责与总流程 → 区域内部交互 → 信息层次 → 控件与视觉细节”的顺序逐步优化。宿主视觉组件位于 `src/renderer/src/components`，公共插件 API 继续以 `src/plugin-api/ui` 为边界；不要让外部插件导入宿主私有组件。

## 设计与协作顺序

1. 从实际使用任务梳理信息和功能，划分可能的工作区，明确每个区域负责什么、相互如何协同。先定职责，再决定侧栏、中央页面或浮层的位置；可停靠布局不改变职责。
2. 研究区域内部的操作：入口、作用对象、前置条件、状态变化和结果反馈。区分当前页面、选中素材和正在查看的内容，避免动作作用于用户看不到的对象。
3. 安排信息层次：默认需要看什么、选择后出现什么、什么按需展开；高频动作和管理动作分别放在哪里。跨区域入口可以有多个，业务规则与权威状态仍有明确归属。
4. AI 负责控件选择、间距对齐、按钮细节、焦点与响应式布局等具体实现，沿用已有原语。影响操作含义、保存或删除范围的变化须按上层逻辑推演，不能作为视觉调整顺手改变。

用户主要确认结构、逻辑与实际体验。每批沿一条完整使用流程检验，只推进相关区域；已有壳层和组件继续复用，必要时回到上层修正，不要求先穷举所有界面或一次重做全部页面。

## 工作台区域外壳

2026-11-09 本轮结构已收束，保留区域、容器、内容、上下文和实例规则；容器呈现继续按使用反馈调整。完整边界见[结构基线与 API 索引](../plugins/工作区布局.md)。现有分段顶部与侧栏普通工具组：左、中、右的上边界对齐，窗口控制安全区和窗口拖动区由宿主管理。中央各组保留自己的标签栏；两侧工具按纵向组组织，同组切换不改变其他组。窗口级侧栏开关只出现一次，收起时归到中央顶部外缘；操作它们不能激活别的中央分屏。

参考 [Obsidian 的侧栏分组](https://obsidian.md/help/sidebar)，拖动根据当前组的上／中／下区域显示独立放置或合并预览，不用隐藏的像素细线充当主要入口。命中层只在宿主布局拖动期间出现，拦截工具内容的输入／业务拖放；普通文件拖入继续原流程。预览不提前改存档，提交时重新判断空间和来源。原生拖动启动完成后才显示命中覆盖层，避免在 `dragstart` 内盖住起点而被 Chromium 取消；结束、取消和卸载都要清理待执行任务。

窗口原生拖动按 [Electron 的 app-region 规则](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)安排：只让实际按钮、标签等控件使用 `no-drag`，不要把 flex 填充的整条标签栏一并排除。上缘和留白保留窗口拖动，内部布局拖动时临时让出事件；检查样式覆盖和实际鼠标行为，两者不能互相替代。

最左快捷栏执行全部视图、新建文字、导入和命令面板等常用动作，插件仅显式贡献窗口命令；组内选择器负责切换内容，组菜单负责布局。选择器可由文字标签换成图标，但保留可访问名称、键盘路径、稳定实例 ID 和可用拖动区域。关闭工具与移动工具都不表示结束业务服务；第一次显示才挂载，之后保留实例，隐藏由 `active` 告知插件。布局存档只保存结构，不替插件保存任意局部状态。智能工具组独立承担主页面上下文切换；普通组不加入隐式自动切换。智能组无匹配时保持位置和尺寸，不自动打开别的页面。工具来源按页面实例 ID 区分，切换标题相同的集合也不能共享临时条件；局部状态按容器与来源隔离，运行时能力不进入布局存档。

2026-11-10 侧栏容器统一为紧凑头部：当前工具以 26px 高的圆角矩形展开名称，其余仅图标并在悬停时显示同类圆角底色；普通、智能、固定工具共用同一选择器，不复制文档标签外形。普通容器头部只放工具选择器与公共布局控件，不随某个工具追加来源按钮，以免切换时挤动其他入口；固定来源放在工具完整提示和右键／组菜单的定位动作中。只有智能容器保留跟随指示，区分其自动跟随行为。正文不补一条来源栏，工具内部必要的业务控件仍由工具负责。窄栏收进溢出菜单，完整名称、键盘选择及原生拖动都须可用；整组抓手与单项图标的拖动含义分开。首组保留 44px 与窗口顶部对齐，其他组头部 36px，不挤占窗口控制安全区。无适用工具仍显示组名与空状态，不折叠布局；中央页面继续保留文档标签形态。

改外观继续调用工作区既有动作，不新增第二份布局状态；智能组改标题／来源提示不改候选和固定绑定。若改成同组多个内容同时呈现，需明确新的可见性、生命周期和存档规则，不能当成单纯样式修改。工具内部业务结构由插件决定，宿主只约束承载边界。标签分组等业务样式归对应插件，不以 `.sidebar` 等宿主祖先选择器给插件补皮肤，避免跨容器后失效。

2026-11-10 中央容器头部以内容切换为主，移除独立分屏图标和 Alt 切换方向；保留常见、低强调的 `···` 管理按钮。精确放置通过拖动完成，菜单只保留向右／向下分屏及当前布局需要的整理动作；多目标选择放到下一步。标签高 32px，头部图标统一 16px，操作按钮点击范围 28px；按钮与标签内容共用视觉中心，不按整个 44px 顶栏各自居中。保持键盘焦点可见及顶部拖窗留白，不按单项／多项切换容器样式。

2026-11-11 侧栏 `···` 菜单按“工具操作 → 容器位置 → 关闭操作”分段，段间使用原生菜单分隔线，不额外添加标题行。当前工具操作、智能候选配置和添加工具放在首段；整组跨侧移动与上下排序放在中段；关闭当前工具和关闭整组放在末段。普通组与智能组保持同一顺序，按上下文省略不适用项；分组只调整菜单呈现，不改变原有执行与状态保留规则。

## 容器与控件

2026-11-10：形状按用途统一。操作按钮、输入框和容器 Tab 使用圆角矩形，沿用控件圆角 `--radius`；数据标签块与状态角标使用胶囊／椭圆，悬浮球使用圆形。可点击的数据标签仍表达一个标签值，不因使用 `button` 就改成操作按钮外观；容器工具切换项也不因名称简称为“标签”而使用数据胶囊形状。后续界面按此约定逐步收敛，不以全局元素选择器强制覆盖插件的业务样式。

`ui-primitives.tsx` 提供四个内部组件：

| 组件 | 用途 | 主要参数 |
| --- | --- | --- |
| SectionHeader | 模块标题与动作 | title、subtitle、badge、actions |
| SettingGroup | 配置分组 | title、description、action、children |
| SettingRow | 左标题／说明，右控件 | title、description、vertical、children |
| StatBar | 紧凑摘要与操作 | label、meta、actions |

优先复用组件。必须用 `label`、`li` 等语义元素时，可以复用 `.ui-setting-row`，其子节点统一使用 `.ui-setting-info`、`.ui-setting-title`、`.ui-setting-desc`、`.ui-setting-control`，不另外发明近似类名。标签必须与控件关联，多控件行分别提供可访问名称。窄窗口自动改为纵向排列，文字区不能保留横排时的固定高度。

色彩使用已有主题变量；保留键盘可见焦点。折叠内容必须真正隐藏，不能仅透明或用固定最大高度裁切，避免 Tab 进入看不见的控件或长列表被截断。

## 样式归属

`src/renderer/src/styles.css` 只按顺序导入以下样式，不在入口末尾追加覆盖补丁：

| 文件 | 职责 |
| --- | --- |
| `styles/base.css` | 主题默认变量、全局复位和根页面；用户主题仍由主题服务应用 |
| `styles/controls.css` | 共享按钮、输入、字段控件、界面原语和通用遮罩 |
| `styles/workbench.css` | 区域、容器头部、标签组、快捷栏、拖放、保活插槽与命令浮层 |
| `styles/settings.css` | 设置窗口正文、导航与设置内容、插件管理 |
| `styles/content.css` | 集合、检查器、阅读器、启动页及业务浮层；暂不继续逐组件拆文件 |

新增规则放到对应职责附近。相同选择器的基础声明尽量合并；响应式、密度、悬停和选中态仍是各自的条件规则。不能只按类名机械移动：同等优先级下，后出现的规则胜出，通用遮罩必须早于设置／命令专用遮罩，卡片选中边框仍要优先于悬停边框。局部按钮样式中原本被主按钮覆盖的属性，用 `:not(:where(.primary))` 明确让出，不增加选择器优先级，也不影响该行其他布局属性。跨文件不要靠末尾追加重复规则修补。

宿主控件和外壳样式不构成公共插件 API。插件业务样式继续随插件维护，不依赖某个宿主祖先布局选择器；本轮未改插件样式加载方式，也未引入 CSS Modules 或新的主题框架。

## 设置与命令外壳

设置左栏过滤目录，右栏只显示当前分类。分类切换隐藏并保留表单；关闭、原生关闭菜单、正常退出与重载统一经过 `SettingsService`。表单有手动草稿时自行注册 guard；已保留状态才能允许 navigate，保存中不能卸载。插件启停仍须明确统一应用，安装仍不自动启用。

浮层用 `modal-focus.ts` 管理打开时聚焦、Tab 循环及关闭后恢复焦点。嵌套确认框优先处理自己的输入，Esc 不同时关闭父设置。原生菜单的文本编辑继续可用，素材回收／撤销等不能落到被模态窗口遮住的工作台。

命令面板在转移焦点前取得会话。分组后的显示列表、高亮索引、箭头移动与回车执行使用同一序列；禁用项不执行。刷新与搜索的迟到返回不覆盖新输入；执行完成再释放会话。快捷条入口同时支持鼠标和键盘按钮激活，Cmd/Ctrl+P 与原生菜单复用同一命令面板。

公共接入见[设置与命令](../plugins/设置与命令接入.md)。

## 精简文案的边界

普通说明保留必要的一句，技术细节移入文档。不可逆处置、共享影响和恢复步骤要在确认时直接可见，不能只放 title：

- 仓库回收、空间回收、系统废纸篓分别影响什么；撤销素材不等于恢复原件。
- 影响所有引用仓库；只核对本库时须说明其他引用未知。
- 原件含历史版本、清理恢复清单后的限制，以及外部覆盖不能凭空恢复旧字节。
- 部分失败、未完成任务与重试入口继续保留。

## 验证

类型检查和构建之外，运行 `tests/electron/workbench-services-check.mjs` 与 `tests/electron/package-install-check.mjs`。它们使用临时仓库和独立用户目录，覆盖真实命令键盘、设置草稿与模态嵌套，不操作日常数据。跨平台外观和完整业务插件组合仍须单独验收。

## 主界面信息与操作密度

侧栏普通组与智能组保持一致的工具切换项样式，单项容器也不改成另一种标题外观；数量变化不影响拖动、菜单与焦点语义。

详情顶部只放一个主操作、少量图标快捷入口和更多菜单。危险操作保留名称、分组与原确认流程；分区专用操作归分区，取回完整数据归素材。摘要与分区通过已呈现字段去重，不依赖 DOM 或删数据。打开状态与原件编辑分开，已打开时定位到实际页面。

筛选胶囊采用简短字段名和值，保留“或”、范围、未填写及定义不可用等实际语义；完整说明可悬停或打开条件编辑。追加条件不显示“临时”标签，仍与保存视图规则分开，重置和另存行为保持。标签分组是轻量目录标题，只显示数量；已选数量在标题提示中，键盘焦点保留细线。

上下文绑定显示页面友好名称。阅读页通过既有 `expose({ context: { title } })` 报告动态名称；缺少名称时显示“当前页面”，不把类型 ID 当作用户文案。无适用工具保持原容器和空状态，不自动收起或切换到其他页面。

PDF 阅读角标由 PDF 插件投影已有 `pdfreading` 记录：未保存阅读记录及单页文档不显示；阅读中简写为页码／总页数（包含第一页）；上次保存位置在末页时显示与页码同样风格的“已读”文字角标，悬停提示“上次读到末页”。它不代表逐页读完或独立完成标记，回翻并保存后回到阅读中。详情统一显示“阅读进度”：未查看、页码／总页数或已到末页，悬停说明为上次保存位置；标签列不拆行。摘要已显示页数时分区按 `summarizedFields` 省略重复，未提供摘要信息时仍保留页数。阅读动作统一使用顶部打开／定位入口，分区不重复提供按钮，不额外引入完成百分比或重置动作。阅读进度仍在原有页面生命周期中保存。

## 设置窗口的外壳与正文（2026-11-14）

设置已独立为原生非模态窗口。后续样式改动集中于 `SettingsContent.tsx` 和 `styles/settings.css`；不在正文恢复全屏遮罩、父窗口固定宽高或创建第二份设置服务。`SettingsWindow` 管理本窗口弹窗和通知，`AuxiliarySurface` 同步样式、主题及显示文档。主窗口继续可操作；退出保护、配置归属不由外壳样式决定。公共浮层和焦点管理使用实际显示文档，插件自己操作 DOM 时遵守 `ownerDocument/defaultView`。
