# 层级标签 1.0.2

独立业务插件，依赖 `tags` 2.0.0；宿主需 `query-subtree-v1` 和 `facet-identity-v1`。与分组插件共享素材打标值，父子关系完全独立。公开协作规则见 [共享契约](contracts/tags-v1.md)。

- 筛选时点击标签查自身和全部后代；⌘/Ctrl 叠加，Alt 点击仅此标签。保存视图保持动态关系，不是后代列表的快照。
- 母标签计数是当前视图范围内的素材并集，不把多标签素材重复相加。已选零结果标签仍能取消，祖先也保留。
- “整理”切到全库目录，包括空节点。＋创建根／子标签，拖到另一个标签上成为其子标签，拖到底部成为根标签；点击标签提供菜单替代拖动。禁止自身／后代循环。
- 移除层级节点不删素材标签，直接子节点提升一级。父级关系和展开状态分开保存；第一版层级目录最多 500 节点，不自动显示拖动浮现槽。
- 文字标签键沿用旧格式，大小写敏感、全局唯一，不支持跨父级同名身份及全局改名。空节点归本插件，不自动成为分组插件的空目录；给素材打标时可输入这个标签。
- 拖入分支视图只添加根标签，不把所有后代写上。导入预检对层级关系保守提示待确认，实际收录仍按当前关系复核。
- 停用本插件后，已有精确标签筛选继续可用；层级查询明确报关系不可用。重新启用恢复关系。关系调整可撤销。

MCP：`tag_tree_set_parent`、`tag_tree_remove`；只读 `tag-tree.list_nodes`、`tag-tree.branch`。分支查询接受 scope，返回 Query 和 count，可接通用 search_items；list_nodes 的返回游标放到 args.cursor（非外层 cursor）。

安装基础与此包，在仓库勾选后统一应用。`npm ci` 后配置 `.rm-dev.json`，运行 `npm run check` / `npm run pack`，输出 `artifacts/tag-tree.rmplugin`。

## 数据清理（1.0.1）

需要宿主 `data-lifecycle-v1`。启用新版登记声明，停用并重载后，可在设置的数据维护中清理自己拥有的层级节点。素材标签、分组目录、保存的查询和本机折叠状态保留。关系清空后重新启用，旧分支条件不再包含原后代；停用时仍明确提示关系不可用。存在保留引用或混合数据的节点由宿主报告并保留。停用／卸载默认不清理数据。

## 本机界面偏好（1.0.2）

需要宿主 `plugin-local-state-v1`。折叠状态通过 `host.localState` / `usePluginState` 存于本机、按本库隔离；精确迁入旧 localStorage 键，成功后移除旧键。多处画面订阅同一份偏好。需要重置时，先停用并重载，到「当前仓库 → 数据维护 → 插件的本库本机数据」，只选界面偏好即可；不会删除标签或组织关系。重置后不从旧存储复活，普通停用／卸载仍保留。

## AI 操作权限

本版声明 `operation-effects-v1`，需要支持该特性的宿主。建立与调整标签层级属于 `structure`，需要 `admin`。安装后还须在目标仓库启用新版本；旧包不会因宿主升级自动获得声明。
