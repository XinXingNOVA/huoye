# 表格插件

当前版本：`1.3.0`。需要支持 `browsing-layout-v1`、`ui-extension-points-v1` 的宿主。“显示”面板隐藏无效的卡片大小滑块；按素材行锚点恢复纵向位置，并保存横向位置。 更新包后沿用原插件 ID、仓库视图与配置。

随应用附带的纯界面包，保留布局 ID `table`。自身不定义数据块；读取公共定义、查询和素材订阅，以宿主字段组件编辑值，声明 `table.tools` v1，通过 `host.extensions` 获取其他插件提供的表头和结构操作。协作类型由本工程的 `contract/` 公开，不能导入字段插件实现。

在本插件目录执行 `npm run pack`；也可复制本目录到项目外后打包。表格布局和单元格样式随包，共用字段控件和弹层样式仍由公共 UI 提供。

新库按需启用，旧库保留原选择。停用后集合暂用基础布局，原表格配置继续保存；字段检查器独立可用。表格启用但字段停用时，旧模板值按保存定义只读显示。未配置选列时保留原默认列；自定义列可跨数据块、跨模板组合。使用和回归见[本地插件指南](../../host/docs/README.md)。

支持功能分类、关键词与使用入口；只调整目录信息和说明，持久定义不变。已绑定旧版的仓库不自动切换版本；新元信息需要更新后的宿主。

## 独立开发

运行 `npm ci` 安装本工程依赖；设置 `RM_PLUGIN_TOOLCHAIN` 为宿主工程，或在未提交的 `.rm-dev.json` 中指定 `toolchain`。`npm run configure` 生成本机编辑器 SDK 路径；`npm run check` 检查公共 API 边界和类型（也会刷新 SDK 路径），`npm run pack` 输出 `artifacts/table.rmplugin`，`npm run dev` 监听源码。应用按仓库选择本目录，勾选后应用并重载。插件 ID／数据不因目录位置改变。

宿主集成验证由宿主可选测试套件负责；本工程不复制宿主私有测试框架。

## 扩展表格

`table.tools` v1 的载荷是 `contract/index.d.ts` 中的 `TableTools`，包括纯函数 `match(kind)`，可选的 `columnMenu`、`header` 和 `addOption`。这些是同一组工具，按外层贡献的 `order` 从小到大，首个匹配胜出；同序按贡献 ID。休眠数据定义不提供编辑工具。

第三方插件在 `plugin.json` 声明 `optional: ["table"]` 和 `uiFeatures: ["ui-extension-points-v1"]`，依赖公开的 `@resource-manager/table-contract` 类型包，向 `UiPlugin.extensions` 添加：

```ts
{ id: 'my-plugin.tools', point: 'table.tools', version: 1, order: 20, value: myTableTools }
```

原有字段菜单、表头增列和新增选项只是 `fields` 提供的一个实现。新贡献不需要修改宿主或表格代码。`match/title` 应同步、纯且轻量；匹配出错时记录来源并继续查找，标题错误回退到数据块名称。附加组件分别包裹渲染边界，`addOption` 经 `extensions.invoke` 调用；组件内部事件仍由贡献方处理自己的异步失败和业务撤销。

公开类型包源码在 `contract/`；可用 `npm pack ./contract --pack-destination <目标目录>` 生成归档。贡献工程可随源码携带归档作为 `file:vendor/*.tgz` 开发依赖，这样复制到任意位置后仍能 `npm ci`，不需要表格源码在旁边。类型包没有运行代码，实际插件包不捆入表格实现。契约语义变化需明确升级点版本；不要覆盖已经分享的同版本类型归档。

宿主已移除旧表格专用接口，table／fields 至少使用 1.2.0，当前建议配合 1.3.0。已有新版包无需重复安装；仍用旧 1.1.x 包时应先升级插件再升级宿主。模板与仓库格式不变。

运行 `npm test` 验证契约校验、匹配故障、标题回退和休眠定义。真实编辑、撤销、独立模板编辑、选列保存、停用及重开由宿主 `node tests/electron/sidebar-layout-check.mjs --table-tools` 覆盖。

## 选择和排列列（1.3.0）

在集合页切换到表格后，打开“显示 → 显示字段”：

- **默认列**：普通视图使用常用列，模板视图使用查询要求的第一个模板的全部字段；新增模板字段会跟随显示。
- **自定义列**：首次从常用列起步，按数据块／模板搜索并勾选字段；在“已选列”拖动把手或使用上下移按钮调整顺序，× 只隐藏这一列。“素材”固定为首列。
- 候选来自仓库公开定义，不随当前结果数量变化；暂不提供内部 JSON 和文件定位字段。最多选择 200 列，休眠字段可读。

配置属于本页，切换布局与重启会接续；通过“视图”菜单保存后，列及顺序成为保存视图的一部分。不同视图可有不同列。选择、隐藏、排序不改查询成员、不删除字段或值。自定义列不会自动加入新字段；可以手动勾选，或恢复默认列。

配置保存 `{ columnMode: 'custom', columns: [{ kind, field }] }`，使用稳定 ID，不存可变标题。改名后显示新名称；字段缺失时保留原列位并显示“暂不可用”，定义恢复后接续。模板列对应素材未附加该模板时显示“添加模板”，明确点击后才添加，已有块不被清空。休眠／只读定义不能通过此入口编辑。

本版保留 `table.tools` v1 契约，无宿主运行接口变化。两项列配置回归与原两项契约测试通过；真实 Electron 跨插件验证覆盖混合选列、按钮与拖动排序、隐藏不删值、显式添加模板、改名接续、保存视图、插件启停和进程重启。拖动使用 DOM 事件验证，物理鼠标手感和 Windows 实机未验收。

## 数据责任与清理

表格是纯界面插件，没有自己的持久数据块，也不新增空的 CorePlugin 来登记删除权限。单元格写入属于对应字段定义插件（如 tags、fields），停用或卸载表格不能代删这些值。

列选择、顺序等显示配置保存在页面状态或用户保存视图；布局切换和停用继续保留，可在“显示字段”恢复默认列。当前仓库插件数据维护不删除这些共享配置，清理 fields 后缺失列仍按“暂不可用”显示；用户自行移除列或调整保存视图。本次仅明确责任，表格包维持 1.3.0。
