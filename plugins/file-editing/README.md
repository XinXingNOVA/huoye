# 文件编辑

外部 UI 插件，ID `file-editing`，首版 `1.0.0`。管理宿主提供的本机工作副本，没有自己的数据块、数据库或 MCP 接口。

## 安装与使用

在设置的应用级插件管理中安装 `artifacts/file-editing.rmplugin`，再到当前仓库勾选“文件编辑”，统一应用并重载。它也可由应用选择随包交付；在已有仓库中仍需明确启用。宿主必须支持清单中的 `file-working-copy-ui-v1` 等能力。

右键 **编辑文件** 创建或复用工作副本；在外部应用保存并关闭后，回到左栏 **编辑中**，选中素材并 **完成编辑**。可在“⋯”中预览、选择编辑器、改存为独立副本或明确放弃。右侧“文件编辑”分区显示活动任务，可排序、折叠；卡片角标展示同一份任务状态。

宿主的“文件存储…”继续提供编辑、选择编辑器和选择替换文件入口。共享空间发布会要求确认影响；冲突、接纳失败、清理失败保留副本和恢复入口。未知格式由用户明确选择本机编辑器，无扩展名不设批量默认。普通双击阅读仍使用仓库已接纳版本。

停用／卸载只撤下这些界面和订阅，不自动保存、发布、放弃或删除任务。重新启用或重装兼容版本后继续处理原工作副本。请保留宿主的本机用户数据目录：任务和编辑器偏好都由宿主保存，并不随插件包传给另一台电脑。宿主没有编辑界面贡献时，编辑入口会说明原因，不暗中创建新副本。

旧“编辑中”标签在插件已启用时自动接续为 `file-editing.page`，保留筛选与布局状态。停用后专用标签按宿主规则关闭；重新启用可从导航再打开，任务不受影响。

## 独立开发

工程位置任意。设置 `RM_PLUGIN_TOOLCHAIN` 为已安装依赖的宿主目录，或写本机 `.rm-dev.json`：

```json
{ "toolchain": "../../host" }
```

执行 `npm run configure` 生成编辑器路径映射，`npm run check` 校验公共边界并打包，`npm run pack` 生成 `artifacts/file-editing.rmplugin`。本工程仅用宿主注入的 React，没有额外运行依赖；不把宿主整棵依赖拷过来。当前仓库的“插件开发”可直接添加本目录，勾选后构建、应用。发布新内容须提升 `plugin.json` 与 `package.json` 版本。

## 结构与协作

- `ui.tsx`：界面处理器、窗口 Provider、导航、标签页、详情分区和角标声明。
- `state.tsx`：每窗口一次任务订阅，读取失败保留最近状态，卸载释放订阅。
- `view.tsx`：公共 `ResourceCollection` 加动态 ID 范围，禁止拖入和新建。
- `editing.tsx`：继续、预览、完成、冲突选择和带确认 token 的放弃。
- `EditorChooser.tsx`：登记与选择编辑器，不取得可写路径或任意命令。

宿主通过 `fileEditingUis` 将 `host.editFile` 请求交给此插件；插件不得再调用 `host.editFile` 来实现处理器，否则会递归。实际编辑调用 `host.fileEditing`。替换文件使用 `chooseReplacement(id)`，原生选择和路径校验留在主进程。

跨边界回归在宿主执行：配置 `.plugin-sources.local.json` 或 `RM_PLUGIN_SOURCES` 的 `file-editing` 来源后，构建宿主，再运行 `node tests/electron/file-editing-check.mjs`。它安装真实包并依次验证运行、停用、卸载、重装与重启，使用临时仓库与独立用户目录；系统编辑器启动由测试替身代办。
