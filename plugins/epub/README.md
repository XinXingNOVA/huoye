# EPUB 阅读器

活页的可选阅读器，依赖文件与预览功能。1.2.0 支持工作台工具停靠：书籍目录默认在左侧，也可以放到中央或右侧。阅读器的「目录」按钮会打开它当前所在的位置。

## 使用

1. 在“设置 → 套件与插件包”添加 `artifacts/epub.rmplugin`。
2. 在当前仓库的「功能与方案」勾选“EPUB 阅读器”，统一应用并重新加载。
3. 拖入 `.epub`。首次收录会在后台提取书籍信息、封面、目录与正文；已入库的 EPUB 启用插件后也会加工。
4. 双击书籍卡片进入阅读器。工具栏“目录”打开书籍目录；右侧详情沿用已有笔记、标签等插件。
5. 用目录、上一章／下一章或左右方向键切换章节；“排版”调整字号、行距、暖纸色背景；“搜索”或 ⌘/Ctrl+F 搜书内正文。
6. 滚动后自动保存阅读位置。“书签＋”保存当前位置，目录工具的“书签”中跳回或删除；书签增删支持现有撤销。
7. 正文可用鼠标拖选文字，通过统一菜单复制。启用摘录批注 后还可「标记摘录」或「添加批注」，支持 #标签；点击标记或摘录卡片可查看批注、回到原文。

升级时在「套件与插件包」更新 EPUB 包，按提示重载仓库即可接着读。已有书籍、阅读位置和书签继续沿用。

侧栏选择仍按宿主现有规则保存，插件不会强制切换它。切换标签、关闭阅读标签和重启应用后可以续读。原文件变化后不会将旧位置套到新书，旧书签保留并标明失配。

## 首版范围

支持普通、无 DRM、流式排版的 EPUB 2/3。包括 OPF 元信息、spine 阅读顺序、EPUB 3 导航与 EPUB 2 NCX、章节内和跨章锚点、常见位图插图、基本段落／列表／表格／强调／ruby。

采用统一阅读排版，不执行书中脚本，不加载外部资源，不应用原书 CSS、嵌入字体、交互内容、音视频或复杂 SVG 图形。外部网页链接只有用户点击后才交给系统浏览器。书内图片需要 JPEG、PNG、GIF、WebP 或 AVIF；不支持的资源显示阅读提示。固定版式、加密正文及损坏书籍给出错误，原文件继续作为普通素材保留。

本版支持章节内的文字摘录与批注，暂不支持跨章节一次拖选或 EPUB CFI 互通。续读和书签保存“原文件指纹 + 章节 href + 规范化正文 UTF-16 偏移”，字号、行距、窗口变化不会依赖旧页码；当前位置按可见文字片段定位。阅读字体及主题属于本机标签页，阅读进度和书签属于仓库。

正文搜索及 AI 读取最多索引前三百万 UTF-16 单位，超出时明确提示；阅读器仍支持上限内全书内容。首版处理上限：压缩文件 128 MiB、解压总量 200 MiB、单资源 16 MiB、5000 个包条目、1500 个章节、正文一千万 UTF-16 单位。异常结构和越界路径拒绝加工，不静默丢章。

## 数据与协作

| 数据块 | 作用 | 生命周期 |
| --- | --- | --- |
| `file` | 原 EPUB 文件和稳定素材身份 | 核心托管 |
| `epub` | 书籍信息、章节、目录、图片与章节缓存文件路径 | 可重建 |
| `epubtext` | 搜索与通用读取的纯文本、截断标记 | 可重建 |
| `still` → `thumb` / `palette` | EPUB 提供代表图，preview 继续生成缩略图与色板 | 可重建 |
| `epubreading` | 指纹、章节、文字位置、全书进度、最后阅读时间 | 持久记录，不占用撤销历史 |
| `epubbookmarks` | 书签及对应原书位置 | 持久记录，可撤销 |

缓存文件以内容摘要命名，声明为 `file` 字段供宿主取回／清理；图片和章节缓存按素材隔离，不共享会被另一素材删除的文件。原 EPUB 字节不改写。停用或卸载后，已有原文件、进度、书签和正文保留；专用阅读和业务查询撤下，通用读取仍可用；已保存摘录和批注也继续保留。

`lib/` 只负责后端解析。书籍 HTML 经白名单变成自有阅读树，UI 使用 React 节点呈现，不注入原始 HTML、不要求放宽宿主 CSP、不开 iframe 或新协议。全部生产代码只导入插件自身、纯 JavaScript 依赖与公共 `@resource-manager/plugin-api/...`。

## 公共选区与摘录

`selection.tsx` 将正文阅读树的文字位置转换为 `epub.quote@1`（指纹、章节 href、偏移、前后文），负责定位、坐标与回跳；摘录批注保存通用 anchor，不读取 EPUB 私有 DOM。`epub.anchor` 按相同规则产生可重建的失配判断。字号和窗口变化重新计算标记位置，来源变化保留摘录原文。详细接入见[公共选区通道](../../host/docs/README.md)。

## MCP 与业务查询

启用后，既有 `describe_library` 自动发布下列查询，经固定 `execute_query` 调用；没有 MCP 专用分支，也不要求为插件配置另一条连接。

- `epub.chapters`：`args: { id }`，支持宿主 `limit / cursor` 分页。返回章节编号（从 1 起）、标题、稳定 href、全文长度、可读的索引长度。
- `epub.read_chapter`：`args: { id, chapter, offset?: 0, limit?: 4000 }`。最多读取 8000 字符，`nextOffset` 提供本章续读位置，`truncated` 表示本章未完整进入索引。查询不改变用户阅读进度。
- 通用 `search_items`：按 `epub` 的书名／作者／出版社、`epubtext.content` 搜索；`read_content` 可继续分段读正文。标签和笔记写入仍由相应插件提供操作。

`savePosition / addBookmark / removeBookmark` 是插件自有 UI 命令，本版没有额外对外写操作。

## 独立开发

运行 `npm ci` 安装本工程依赖；设置 `RM_PLUGIN_TOOLCHAIN` 为宿主工程，或在未提交的 `.rm-dev.json` 中指定 `toolchain`。`npm run configure` 生成本机编辑器 SDK 路径；`npm run check` 检查公共 API 边界和类型（也会刷新 SDK 路径），`npm run pack` 输出 `artifacts/epub.rmplugin`，`npm run dev` 监听源码。应用按仓库选择本目录，勾选后应用并重载。插件 ID／数据不因目录位置改变。

宿主集成验证由宿主可选测试套件负责；本工程不复制宿主私有测试框架。

1.3.0 起，正文和工具栏图标会随活页主题及所属小窗更新。「排版」里的手动字号、行距和暖纸优先，点击「恢复主题排版」可让字号与行距重新跟随主题。
