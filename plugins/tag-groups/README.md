# 标签分组 1.0.2

独立业务插件，依赖标签基础 `tags` 2.0.0；宿主需 `facet-identity-v1`。与层级插件可同时启用，组织关系互不影响。

筛选工具中的“标签分组”：散标签直接流式胶囊，不再显示“未分组”标题。点“整理”原地显示全库标签与空分组，可新建、改名、删除组；标签拖到组里或根区域调整归属，点击标签也可用菜单完成相同操作。普通浏览不允许拖动整理。计数沿用当前视图范围，打标仍由基础插件提供。

旧分组需点击“导入旧分组”接续到 `tag-groups.groups`，保持组 ID 和素材标签；已有独立记录不会覆盖。旧记录保留为备份，不再自动回退，清理后也不会自动复活。详情见[共享契约](contracts/tags-v1.md)。MCP 查询归属为 `tag-groups.list_groups/list_tags`；新增 `import_legacy_groups`，原分组写操作名称保持。

与基础包一起安装并统一应用；可单独关闭或卸载本插件，数据保留。`npm ci` 后配置 `.rm-dev.json`，`npm run check`、`npm run pack`，产物为 `artifacts/tag-groups.rmplugin`。

## 数据清理（1.0.1）

需要宿主 `data-lifecycle-v1`。启用新版登记声明后，可停用并重载，在设置的数据维护中预览清理自己的分组管理记录。基础标签、父子关系及 tags 拥有的旧备份、本机折叠状态保留。混合其他数据或被引用的记录由宿主保守保留；普通停用／卸载不会清理。

## 本机界面偏好（1.0.2）

需要宿主 `plugin-local-state-v1`。折叠状态通过 `host.localState` / `usePluginState` 存于本机、按本库隔离；精确迁入旧 localStorage 键，成功后移除旧键。多处画面订阅同一份偏好。需要重置时，先停用并重载，到「当前仓库 → 数据维护 → 插件的本库本机数据」，只选界面偏好即可；不会删除标签或组织关系。重置后不从旧存储复活，普通停用／卸载仍保留。

## AI 操作权限

本版声明 `operation-effects-v1`，需要支持该特性的宿主。分组目录与标签归组属于 `structure`，需要 `admin`。素材打标继续由 tags 插件提供。安装后还须在目标仓库启用新版本；旧包不会因宿主升级自动获得声明。
