# 音乐播放器外部插件

依赖宿主的音频与播放进度能力，复用仓库中的音频身份，提供歌曲列表、歌单、播放队列和右栏滚动歌词。播放控制位于歌词面板底部，窗口底部不占位。源码与样式均在此目录；不静态加入宿主，不自动安装到日常仓库。

## 打包与使用

```sh
npm run pack
# artifacts/music.rmplugin

# 也可把本目录复制到任意位置，再使用项目的公共打包工具：
npm run pack
```

先重新构建并重启宿主，在“设置 → 应用 → 插件包 → 添加插件…”选择产物并安装，再到“当前仓库”勾选音乐播放器，统一“应用并重新加载”。需要音频和播放进度插件启用，音频解析／转换需要 ffmpeg。左侧资源导航出现“音乐”；现有音频素材也能右击“在音乐播放器中播放”。此包声明 `uiFeatures: ["window-surfaces-v1"]`，旧宿主需升级后才能安装。

当前版本 **1.3.3**。1.3.1 补充“应用与场景”目录、关键词和使用入口；需要新版宿主读取这些元信息。已安装 1.0.0 / 1.1.0 / 1.2.x 的仓库同样添加新版包，勾选 1.3.2 并统一应用。1.3.0 的歌曲列表和页面头图通过公共 `ResourceCover` 显示歌曲内嵌封面；头图取当前列表第一首可用歌曲，无图继续用原占位。需同时更新宿主以启用内嵌封面加工，音乐包不自行解析媒体。持久定义与 ID 不变，歌单、歌词、修正信息、队列和播放进度继续使用。1.2.1 改善跨平台快捷键提示，1.2.0 增加库内歌词匹配。左侧“音乐”打开歌单导航；点击“全部歌曲”或歌单进入中央页面。右侧直接点“歌词”，或从音乐页点“歌词与播放控制”。

- 音乐页双击歌曲或点击序号播放；顶部“播放全部”。搜索覆盖仓库可搜索字段，包括曲名、艺术家、专辑、修正信息、标签和歌词。
- 勾选多首后加入歌单或队列。左栏 ＋ 新建歌单；进入歌单可改名、删除，拖动行调整顺序，右侧“···”也可上移／下移、移除歌曲。删除歌单保留歌曲、原文件和歌词，可用宿主撤销。
- “···”支持下一首播放、修正信息、编辑歌词和通用详情。修正留空时沿用音频解析信息，不改原文件。
- 歌词面板底部控制上一首／下一首、进度、音量和顺序／随机／单曲循环；顺序播放到队尾停止。控制区与歌词滚动分开，无歌词时仍可控制播放。队列面板可以跳到某首或移除项目，独立于歌单。无法读取或被删除的歌曲保留引用并提示，可手动切到下一首。
- 右栏“添加歌词”可导入 LRC / TXT 或粘贴文本。支持 UTF-8 和 GB18030、多个时间戳、毫秒、LRC offset、额外正负秒偏移；无时间戳时展示普通歌词。正偏移表示歌词延后。保留原始文本及导入文件名，解析行只在内存生成。
- 歌词跟随实际播放时间高亮、平滑滚动，点击某句跳转。手动滚动时暂停跟随，点击“回到当前歌词”恢复；尊重系统减少动态效果设置。
- 通过工具选择入口打开音乐导航、歌词或队列，可放在左右栏或中央。中央标签切换不会改变侧栏选择。切走歌词时控制区一起隐藏；收起侧栏或关闭音乐标签不会停止声音。
- 拖动侧栏与中央之间的分隔线调整宽度；双击恢复默认，也可聚焦分隔线后用方向键调整。宽度按仓库在本机保存，窗口缩窄时给中央保留空间。
- 同一仓库窗口里，音乐与现有音频／视频试听互斥，后开始的播放暂停前一个。退出窗口、重载或停用插件停止播放；重新打开恢复队列、音量、模式和位置，保持暂停。

## 仓库内歌词匹配（1.2.0）

把 `.lrc` 文件像普通素材一样收进仓库，然后播放歌曲。播放器自动查找当前库中的歌词；侧栏隐藏或中央标签切走也可完成匹配。播放后新收录的歌词会在索引完成后重新检查。不会联网搜索或上传歌曲。

- **来源**：LRC 文件；含时间戳或 `[ti:曲名]` 标记的 TXT；其他未回收音频已有的非空歌词。普通日记 TXT 不会只因文件名相同就当作歌词。文件读取上限 1 MB，支持 UTF-8 / GB18030；已有文件启用插件后也会加工。
- **匹配依据**：优先使用歌曲的手动修正，再用音频元信息；读取 LRC 的 `[ti:]`、`[ar:]`、`[al:]`、`[length:]`。统一大小写、全半角、空白和标点，但保留 Live、伴奏、Remix 等版本文字。曲名必须一致；双方歌手不同则排除，专辑不同或已知时长相差超过 2 秒时要求手选。
- **自动采用**：歌曲尚无歌词块，只有一份候选，双方有明确曲名和相同歌手，且没有版本冲突。库内待处理的歌词文件索引完成后才判断唯一性。歌曲恢复为暂停状态时只查找，开始播放后才自动采用。
- **候选选择**：多份候选、缺歌手或仅文件名匹配时，在右栏展示来源、匹配依据、同步／普通类型和内容预览；点击“采用这份歌词”。文件名还支持“歌手 - 曲名”，但这种信息不足以自动采用。没有候选时可“重新匹配”或继续手动“添加歌词”。
- **保存与保护**：采用原始文本和额外时间偏移，写入歌曲原有的 `musicLyrics`，来源字段保存文件名或来源歌曲说明。保存时重查目标、候选和唯一性；候选改动／回收、歌曲改信息或新增手动歌词会拒绝过期结果。已有歌词块（包括主动保存为空）不自动覆盖。采用可撤销；本次窗口会话中撤销／移除后不会立刻重新自动填入，仍可手动选择；该抑制状态不跨重启保存。

采用的是**文本快照**。原 LRC 仍是独立仓库文件，不改音频；之后编辑、回收源歌词都不会改动已经采用的文本。首版没有歌词记录共享引用、来源追踪关系或多版本切换，也不自动替换已有歌词。要重新采用另一份，需要先明确移除现有歌词块。

## 数据与边界

| 数据 | 归属 |
| --- | --- |
| 音频原文件、`audio`、`audioProxy`、`audioPlayback` | 复用文件与音频；播放记录调用音频 recordPlayback 命令 |
| `musicPlaylist` | 仓库中的独立管理记录；名称＋有序歌曲关联引用，单个歌单同一歌曲不重复，最多 10000 首 |
| `musicLyrics` | 挂在歌曲上的不可重建数据：原始文本、时间偏移、来源说明；手动编辑或库内采用的快照，可搜索 |
| `musicLyricSource` | 歌词文件上的可重建索引：元信息、原文、文件指纹和读取问题；停用不影响原文件 |
| `musicTrack` | 挂在歌曲上的手动曲名、艺术家、专辑修正，不被音频重新解析覆盖 |
| 播放队列／音量／模式／位置快照 | 按仓库路径保存在本机 localStorage，暂停、切歌与播放中定时保存；不随仓库复制到另一台机器 |
| 两栏显隐与面板选择 | 宿主工作区，本机每库保存；停用插件回退显示，保留原选择 |
| 当前歌词行、手动滚动状态 | 界面内存 |

核心命令：`createPlaylist / renamePlaylist / deletePlaylist / addTracks / removeTracks / moveTrack / saveLyrics / editTrack / findLyrics / applyMatchedLyrics`。`findLyrics` 只查询，不留下撤销记录；`applyMatchedLyrics` 复查后写入。所有业务写入经过核心事务、通知与撤销；核心按定义提供字段搜索和读取，MCP 可按现有通用工具发现／检索／读歌词。首版未单独开放歌单编辑操作给 MCP，也没有把 UI 播放指令加入核心命令。

停用／卸载仅撤下能力，仓库数据与本地会话保留；定义快照支持只读访问，重新安装启用后可接续。空歌单有独立意义，不自动清理。歌曲进回收站或文件丢失不悄悄从歌单删掉；此时可以从歌单移除引用，原文件仍按宿主管理。

当前是可信本地包：无在线曲库／在线歌词匹配、逐字卡拉 OK、系统媒体键或跨窗口播放互斥；不存在退出应用后继续播放的后台进程。使用 Electron 可解码文件或现有音频转换副本，界面本身不增加媒体解析依赖。未来改变持久块结构仍受首版外部包的结构冻结限制，不能直接改定义升级已用仓库。


## 独立开发

运行 `npm ci` 安装本工程依赖；设置 `RM_PLUGIN_TOOLCHAIN` 为宿主工程，或在未提交的 `.rm-dev.json` 中指定 `toolchain`。`npm run configure` 生成本机编辑器 SDK 路径；`npm run check` 检查公共 API 边界和类型（也会刷新 SDK 路径），`npm run pack` 输出 `artifacts/music.rmplugin`，`npm run dev` 监听源码。应用按仓库选择本目录，勾选后应用并重载。插件 ID／数据不因目录位置改变。

宿主集成验证由宿主可选测试套件负责；本工程不复制宿主私有测试框架。

## 1.4.0：接续媒体记录与当前工作台

需要提供 `media-recording-v1` 的宿主。安装新包并统一应用；旧独立 playback 不再需要。音频试听与音乐共享音频拥有的 `audioPlayback`，视频记录独立；原播放记录由宿主开库交接。音乐的歌曲修正、歌单、歌词定义未改，本机队列继续保留原 localStorage 格式。侧栏接口改为 toolViews / showView，导航、歌词和队列可放到当前工作台容器。

新增清理声明：显式清除音乐数据可删除歌单记录并剥离歌词／修正等块；素材和音频记录保留。本机队列本批未迁移公共状态存储，清理仓库数据不宣称清除本机队列。停用／卸载默认保留。

开发检查：`RM_PLUGIN_TOOLCHAIN=/path/to/host npm run check`、`npm run pack`；真实媒体协作由宿主隔离集成流程 `node tests/electron/sidebar-layout-check.mjs --playback` 验证。
